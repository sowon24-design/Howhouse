### 효과가 있었던 프롬프트
- 디자인 컨셉에 맞춰 3D 오브젝트의 질감을 구체화하기: 처음에는 털 질감의 소라게 오브젝트를 제작했지만, 글래스모피즘 기반 UI와 시각적으로 어울리지 않는 문제가 있었음. 이후 화면의 디자인 컨셉에 맞춰 투명하고 매끄러운 유리 질감을 중심으로 이미지를 수정해 UI와의 일관성을 높였음.

- 원하는 이미지를 한 번에 완성하기보다 반복적인 수정 과정이 필요했음. 생성된 이미지가 디자인 방향과 맞지 않을 때마다 질감과 시각적 표현을 조정했고, 최종적으로 UI에 적합한 3D 오브젝트를 제작할 수 있었음. 생성형 AI를 활용할 때도 결과물을 그대로 사용하는 것이 아니라 디자인 의도에 맞게 검토하고 수정하는 과정이 중요했음.
- 디자인 컨셉은 개별 화면뿐 아니라 서비스 전체의 경험과 연결되어야 했음. 초기 스케치 단계에서 3D 오브젝트를 활용한 컨셉과 깔끔한 UI 중심 컨셉을 각각 제안하고 비교함. 이후 브랜드의 개성과 시각적 차별성을 강화할 수 있는 방향을 중심으로 디자인을 구체화함.

## 8주차 활동 정리

### 사용한 도구

- Figma: 페이지별 와이어프레임 및 디자인 제작, 온보딩·로그인·회원가입 화면 구성, 신고 바텀시트와 설정 관련 페이지 디자인
- Codex: 해결방법 페이지의 기본 디자인을 바탕으로 지정된 콘텐츠에 따라 화면을 변경하는 과정 시도
- ChatGPT: 소라게 일러스트 제작 및 페이지별 기본 일러스트 생성
- Google Sheets: 약 58개 생활 문제의 사례, 예상 소요 시간, 배상 책임 주체, 준비물, 단계별 해결 방법 등 콘텐츠 데이터 정리
- **수업 피드백 및 조별 회의:** 동기들의 피드백을 취합·선별하고, 우선순위가 높은 개선 사항을 선정하여 디자인에 반영

### 효과가 있었던 프롬프트 및 작업 방식

- **기본 해결방법 페이지를 기준으로 화면 확장 시도:** 기존 해결방법 페이지의 디자인을 기준으로 삼고, 지정된 내용에 따라 화면을 변경하는 방식으로 여러 생활 문제에 대응할 수 있는 페이지 제작을 시도함. 개별 페이지를 처음부터 만드는 대신 공통 구조를 활용하여 반복 작업을 줄이는 방향을 탐색함.
- **생활 문제 데이터를 구조화한 뒤 디자인에 활용:** 약 58개의 생활 문제를 Google Sheets에 정리하고, 사례별로 예상 소요 시간·배상 책임 주체·필요 준비물·스스로 해결할 수 있는 4단계 과정을 구분함. 콘텐츠를 일정한 형식으로 정리하여 이후 해결방법 페이지에 적용할 수 있는 기반을 마련함.
- **실제 피드백을 바탕으로 디자인 수정:** 수업 중 동기들에게 받은 피드백을 취합한 뒤 조별 회의에서 개선 항목을 선별함. 이 중 3개 항목을 선정하여 실제 디자인에 반영하고, 배상 책임 주체를 명확하게 안내하는 영역과 해결방법별 YouTube 링크를 연결하는 영역을 중심으로 페이지 구성을 수정함.

### 실패한 시도와 배운 점

- **AI를 활용한 반복 페이지 제작의 한계:** 기본 페이지를 기준으로 지정된 콘텐츠만 변경하는 방식을 시도했지만, 여러 페이지의 디자인과 콘텐츠를 일관되게 유지하려면 기본 구조와 변경 범위를 명확하게 정의해야 함을 확인함. 반복 생성에만 의존하기보다 공통 컴포넌트와 콘텐츠 데이터의 구조를 먼저 정리하는 과정이 중요했음.
- **콘텐츠의 양보다 정보 구조가 중요함:** 생활 문제 약 57개의 해결 정보를 수집하는 과정에서 사례별로 필요한 정보가 일정한 형식으로 정리되어야 실제 화면에서 활용하기 쉽다는 점을 확인함. 특히 배상 책임 주체와 해결 절차는 사용자가 문제를 해결하는 데 직접적으로 도움이 되는 정보이므로 명확한 위계로 전달할 필요가 있었음.

### 효과가 있었던 프롬프트 및 작업 방식

- **데이터 보존 조건을 먼저 전달:** 제목과 준비물을 수정하되 CSV의 행·열 위치와 사례 ID를 바꾸지 않도록 지정함. 기존 화면 연결을 유지하면서 내용을 정리하는 데 도움이 됨.
- **실제 메시지를 기준으로 문구 검토:** 집주인에게 보낸 실제 메시지의 말투를 참고하고, 문제 설명·현재 상태·요청 사항이 자연스럽게 이어지도록 사례별로 검토함. 전체 사례를 같은 문장으로 처리하는 방식보다 적합했음.
- **해결 여부와 문의 대상을 분리:** 해결된 집주인 문의와 미해결 문의를 따로 구성하고, 전문 업체에는 해결된 집주인용 추가 문장을 적용하지 않도록 범위를 지정함.
- **억지스러운 블록은 삭제:** 모든 사례에 같은 수의 문장을 채우도록 하기보다, 추가 확인 이유가 자연스럽지 않은 사례는 중간 블록을 빼고 짧게 구성하도록 요청함.
- **현재 구현을 확인한 뒤 방향 변경:** 해외 AI 생성만 끄는 것이 아니라 기존 사례 매칭도 어떤 서비스를 사용하는지 코드와 문서로 확인함. 이후 로그인·Supabase·해외 AI 없이 기기 안에서 글로 사례를 찾는 방식으로 범위를 정함.
- **성공과 실패 경로를 함께 검증:** 검색 성공뿐 아니라 등록되지 않은 문제, 다른 물건의 사례가 잘못 나오는 경우, 질문 수정 시 입력 유지 등을 함께 확인하도록 요청함.

### 실패한 시도와 배운 점

- **공통 문의 문구의 부자연스러움:** 해결·미해결에 비슷한 문장을 붙이니 상황 설명과 요청이 맞지 않거나, 해결되지 않았는데 손봐 두었다고 말하는 문제가 생김. 사용자 상태와 수신자에 맞춰 문장 전체를 나눠 구성해야 함을 배움.

- 기존 사례에 없는 문제는 해결 방법을 새로 생성하지 않으므로 결과가 없을 수 있음.
- 글 검색 전환 코드는 로컬에서 타입 검사·빌드와 관련 검사 21개 및 브라우저 동작 확인을 마쳤지만, GitHub 코드 반영·Android 재설치·실기기 검증은 남아 있음.
- 사진을 기기 안에서 분석하는 기능은 준비 사항을 문서화한 단계이며 모델 개발과 정확도·외부 전송 검증을 완료한 것은 아님.
- 기기 내 검색과 별개로 사용자가 선택하는 쿠팡·유튜브 외부 링크에는 인터넷이 필요하며 외부 서비스의 정책이 적용됨.


## 11주차

### 사용한 도구

- Codex·Figma: 사용성 개선 내용 정리, 발표자료 구성·편집과 디자인 일관성 점검에 활용
- Behance·기존 중간 발표자료: 시각적 참고 자료와 사용성 테스트 개선 근거로 활용

### 효과가 있었던 프롬프트 및 작업 방식

- 문제와 개선을 연결: 용어 이해·단계별 클릭·준비물 파악·글 안내의 어려움을 실제 개선 기능과 대응시켜 설명하도록 요청함.
- 변경 범위를 구체화: 새 시안을 옆에 만들거나 기존 레이아웃에서 문구만 수정하도록 지정해 비교와 반복 검토에 활용함.
- 전체 기준을 명시: 제목 위치·크기·자간·행간과 공통 그리드를 지정하고 페이지별 결과를 확인함.

### 실패한 시도와 배운 점

- 제작 단계나 개선점을 같은 크기의 칸으로 나누니 자료가 부족하거나 이미지 수가 많아졌음. 산출물 나열보다 핵심 변화와 정보량에 맞는 구성이 중요했음.
- 색상 통일 과정에서 그라데이션까지 변해 복원함. 정리할 단색과 유지할 디자인 요소를 구분해 전달해야 함을 배움.
- 개별 페이지 수정만으로는 전체 일관성을 확보하기 어려워 공통 그리드와 실제 좌표를 함께 검토함.

### 다음에 개선할 점

- 표지·마지막 페이지 목업을 추가하고 내보낸 자료의 줄바꿈·이미지 해상도·발표 화면 가독성을 확인한다.
- 발표 대본의 기능과 테스트·출시 현황을 최신 구현 상태와 대조한다.

### 남은 한계

- 이번 작업은 기존 개선 사항의 정리와 발표자료 제작이며, 앱 기능 신규 구현이나 추가 사용성 테스트를 수행한 것은 아님.
- 표지·마지막 페이지 목업 삽입과 최종 서비스 범위 대조가 남아 있음. 특히 기존 10주차의 기기 내 글 검색 전환 기록과 발표 대본의 AI 기능 설명을 확인해야 함.

## 12주차

### 사용한 도구

- Figma: 기존 일러스트 모션 확인, 적용 영역·동작 정의표·분석·수정 과정을 담은 개인 과제 프레임 편집
- Codex·Figma 연결 도구: 원본 화면과 모션값 분석, React·CSS 구현, 브랜치·커밋·PR 관리와 검증에 활용
- 브라우저·영상 변환 도구: 실제 사용 흐름 확인, 시연 녹화와 60fps MP4 제작, 원본 화면과 영상의 색상 비교
- GitHub: 과제 실습 브랜치와 최종 적용 브랜치를 구분하고 최신 main의 팀원 작업을 함께 확인

### 효과가 있었던 프롬프트 및 작업 방식

- **적용할 영역과 순서를 먼저 지정:** 홈에서 카테고리로 넘어갈 때의 끊김과 완료 시트의 등장 방식을 먼저 살펴보고, 버튼 반응·화면 전환·목록 등장·완료 안내의 순서를 정해 요청함. 효과 선정까지 AI에게 맡기기보다 내가 필요한 반응을 먼저 설명함.
- **원본 모션을 기준으로 재현 요청:** 피그마에 이미 넣어둔 일러스트 모션을 기준으로 레이어와 움직임을 나누어 확인하고, 실제 앱에서도 같은 동작이 나오는지 비교함.
- **시연에서 보인 문제를 그대로 전달:** “화장실 애니메이션이 안 나온다”, “시트 밑에 빈틈이 보여 퉁 튀는 것 같다”, “마지막 홈 버튼이 끊긴다”처럼 어느 구간이 어색한지 구체적으로 짚어 다시 수정하도록 요청함.
- **과제 실습과 최종 적용을 구분:** 처음 실습한 효과를 모두 메인에 넣지 않고 B01 목록 등장과 완료 시트·소라게 모션만 최종 선정함. 최신 메인을 다시 받아 필요한 변경만 옮기도록 요청해 팀원 작업을 보존함.
- **보고서에도 판단 과정을 남기기:** 기능 설명만 적기보다 왜 해당 영역을 골랐는지, 왜 그 순서로 움직이게 했는지, 실제로 보고 무엇을 바꿨는지를 내 말투로 보완함. 화면 이미지와 수정 전후 자료도 함께 배치함.

### 실패한 시도와 배운 점

- 피그마의 애니메이션 값이 코드에 있어도 실제로 재생되지 않는 문제가 있었음. 구현됐다는 설명만 보고 끝내지 않고 앱에서 반복이 시작되는지 확인해야 했음.
- 처음에는 시트가 살짝 튀면 괜찮을 것 같았지만 실제 화면에서는 하단 빈틈이 드러나 부자연스러웠음. 텐션감 자체보다 이 화면에서 자연스럽게 보이는지를 보고 반동을 제거함.
- 정적인 캡처로는 시트와 마지막 버튼의 끊김을 알기 어려웠음. 전체 사용 흐름을 영상으로 확인하면서 프레임 수, 이미지 로딩, 시트가 닫히기 전 화면이 바뀌는 부분을 다시 점검함.
- 60fps로 다시 만든 영상은 색상 범위 설정 때문에 색이 밝게 뜨는 문제가 생겼음. 움직임뿐 아니라 최종 내보낸 파일의 색도 원본 화면과 비교해야 했음.
- 제출 자료를 A4에 맞춰 칸으로 나누니 내용과 이미지가 답답하게 들어갔음. 실제 작업을 설명하는 제목과 화면 자료 중심의 구성으로 바꾸고, 선정 이유와 수정 판단을 더 자세히 쓰도록 요청함.
- 작업 중에도 main에 다른 팀원의 변경이 추가됐음. 처음 받은 코드가 계속 최신일 것이라고 생각하지 않고 다시 fetch한 뒤 통합·검증하는 과정이 필요했음.

### 다음에 개선할 점

- 실물 Android 기기에서 목록 등장과 완료 시트·소라게 모션의 속도와 프레임 저하 여부를 확인한다.
- 동작 줄이기 설정과 시트 재열기·닫기에서도 화면과 버튼을 불편 없이 이용할 수 있는지 추가 확인한다.
- 최종 선택 효과와 과제에서만 실습한 효과를 구분해 설명하고, 최종 제출 문서와 실제 main의 구현 범위를 다시 대조한다.

### 남은 한계

- 브라우저의 412px 일반 모션·360px 동작 줄이기, 타입 검사·빌드는 확인했지만 실물 Android 성능과 새로운 사용자 대상 사용성 테스트까지 확인한 것은 아님.
- 현재 main에는 의견 버튼 진입 경로가 없어 B02-3 모션은 완료 컴포넌트를 별도로 띄워 검증함. 의견 기능 자체를 복구한 작업과는 구분함.
- 시연을 위해 과제 브랜치에서 보완한 버튼·이동 효과와 최종 PR #74의 반영 범위는 다름. 최종 서비스 선택은 B01 정적 일러스트·목록 등장, B02 완료 시트·소라게 모션임.
