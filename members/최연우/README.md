### 효과가 있었던 프롬프트
- 디자인 컨셉에 맞춰 3D 오브젝트의 질감을 구체화하기: 처음에는 털 질감의 소라게 오브젝트를 제작했지만, 글래스모피즘 기반 UI와 시각적으로 어울리지 않는 문제가 있었음. 이후 화면의 디자인 컨셉에 맞춰 투명하고 매끄러운 유리 질감을 중심으로 이미지를 수정해 UI와의 일관성을 높였음.

- 원하는 이미지를 한 번에 완성하기보다 반복적인 수정 과정이 필요했음. 생성된 이미지가 디자인 방향과 맞지 않을 때마다 질감과 시각적 표현을 조정했고, 최종적으로 UI에 적합한 3D 오브젝트를 제작할 수 있었음. 생성형 AI를 활용할 때도 결과물을 그대로 사용하는 것이 아니라 디자인 의도에 맞게 검토하고 수정하는 과정이 중요했음.
- 디자인 컨셉은 개별 화면뿐 아니라 서비스 전체의 경험과 연결되어야 했음. 초기 스케치 단계에서 3D 오브젝트를 활용한 컨셉과 깔끔한 UI 중심 컨셉을 각각 제안하고 비교함. 이후 브랜드의 개성과 시각적 차별성을 강화할 수 있는 방향을 중심으로 디자인을 구체화함.

## 8주차 활동 정리

### 사용한 도구

- Figma: 페이지별 와이어프레임 및 디자인 제작, 온보딩·로그인·회원가입 화면 구성, 신고 바텀시트와 설정 관련 페이지 디자인
- Codex: 해결방법 페이지의 기본 디자인을 바탕으로 지정된 콘텐츠에 따라 화면을 변경하는 과정 시도
- ChatGPT: 소라게 일러스트 제작 및 페이지별 기본 일러스트 생성
- Google Sheets: 약 58개 생활 문제의 사례, 예상 소요 시간, 배상 책임 주체, 준비물, 단계별 해결 방법 등 콘텐츠 데이터 정리
- **수업 피드백 및 조별 회의:** 동기들의 피드백을 취합·선별하고, 우선순위가 높은 개선 사항을 선정하여 디자인에 반영

### 효과가 있었던 프롬프트 및 작업 방식

- **기본 해결방법 페이지를 기준으로 화면 확장 시도:** 기존 해결방법 페이지의 디자인을 기준으로 삼고, 지정된 내용에 따라 화면을 변경하는 방식으로 여러 생활 문제에 대응할 수 있는 페이지 제작을 시도함. 개별 페이지를 처음부터 만드는 대신 공통 구조를 활용하여 반복 작업을 줄이는 방향을 탐색함.
- **생활 문제 데이터를 구조화한 뒤 디자인에 활용:** 약 58개의 생활 문제를 Google Sheets에 정리하고, 사례별로 예상 소요 시간·배상 책임 주체·필요 준비물·스스로 해결할 수 있는 4단계 과정을 구분함. 콘텐츠를 일정한 형식으로 정리하여 이후 해결방법 페이지에 적용할 수 있는 기반을 마련함.
- **실제 피드백을 바탕으로 디자인 수정:** 수업 중 동기들에게 받은 피드백을 취합한 뒤 조별 회의에서 개선 항목을 선별함. 이 중 3개 항목을 선정하여 실제 디자인에 반영하고, 배상 책임 주체를 명확하게 안내하는 영역과 해결방법별 YouTube 링크를 연결하는 영역을 중심으로 페이지 구성을 수정함.

### 실패한 시도와 배운 점

- **AI를 활용한 반복 페이지 제작의 한계:** 기본 페이지를 기준으로 지정된 콘텐츠만 변경하는 방식을 시도했지만, 여러 페이지의 디자인과 콘텐츠를 일관되게 유지하려면 기본 구조와 변경 범위를 명확하게 정의해야 함을 확인함. 반복 생성에만 의존하기보다 공통 컴포넌트와 콘텐츠 데이터의 구조를 먼저 정리하는 과정이 중요했음.
- **콘텐츠의 양보다 정보 구조가 중요함:** 생활 문제 약 57개의 해결 정보를 수집하는 과정에서 사례별로 필요한 정보가 일정한 형식으로 정리되어야 실제 화면에서 활용하기 쉽다는 점을 확인함. 특히 배상 책임 주체와 해결 절차는 사용자가 문제를 해결하는 데 직접적으로 도움이 되는 정보이므로 명확한 위계로 전달할 필요가 있었음.
- **피드백을 실제 개선으로 연결하는 과정의 중요성:** 모든 피드백을 한 번에 반영하기보다 조별 회의를 통해 우선순위를 정하고, 선정한 3개 항목을 실제 디자인에 적용함. 피드백을 수집하는 것에서 끝내지 않고 서비스의 사용성과 정보 전달을 개선하는 방향으로 연결함.

### 다음에 개선할 점

- 해결방법 페이지의 공통 레이아웃과 콘텐츠 입력 규칙을 확정한 뒤, 구조화된 데이터를 활용하여 여러 페이지에 일관되게 적용한다.
- 생활 문제별 콘텐츠의 정확성과 배상 책임 안내의 신뢰성을 검토하고, 각 해결방법에 연결되는 외부 영상 자료를 확인한다.
- YouTube 링크 연결이 실제로 작동하는지 확인하고, 영상이 없거나 연결에 실패했을 때의 대체 안내를 마련한다.
- 바텀시트와 개인정보·계정 관련 페이지의 실제 이동 흐름 및 인터랙션을 점검한다.
- 디자인 시안 제작에 그치지 않고, 확정된 페이지 구조와 기능을 개발 단계에서 활용할 수 있도록 화면별 요구사항을 구체화한다.

### 남은 한계

- 약 57개의 생활 문제에 대한 콘텐츠를 정리했지만, 모든 사례가 실제 서비스 화면에 적용되고 검수된 상태는 아님.
- Codex를 이용한 반복 페이지 제작은 시도 단계로, 콘텐츠 변경 시 레이아웃과 스타일이 일관되게 유지되는지 추가 확인이 필요함.
- YouTube 링크 연결을 고려한 디자인을 반영했으나, 실제 API 연동 및 동작 여부는 별도의 구현·검증이 필요함.
- 개인정보 및 데이터 관리, 이용약관, 개인정보 처리방침 등의 페이지를 제작했으나, 실제 서비스의 데이터 수집·처리 방식과 문서 내용이 일치하는지 출시 전 검토가 필요함.
- 페이지별 디자인 작업을 진행했으나, 실제 화면 전환과 예외 상황을 포함한 전체 사용자 흐름은 추가 검증이 필요함.
