### 효과가 있었던 프롬프트(거의 대화형)
- 처음부터 모든 화면과 기능을 한 번에 요청하기보다, 메인 프로토타입 시안을 기준으로 화면을 제작한 뒤 결과를 확인하며 세부 UI와 기능을 단계적으로 수정함.
- 기존 화면의 구조를 유지하면서 변경할 요소를 구체적으로 지정하고, 수정 결과를 확인한 뒤 추가 요청을 이어가는 방식이 효과적이었음.
- 페이지별 화면뿐 아니라 페이지 간 이동과 연결까지 함께 구현하도록 요청하여 전체적인 사용자 흐름을 구성함.

### 실패한 시도와 배운 점
- 기능을 계속 추가하면서 화면 구성과 사용자 흐름이 복잡해지는 문제가 발생함.
- 개별 기능이 정상적으로 구현되더라도 기능이 많아지면 전체적인 사용성이 떨어질 수 있음을 경험함.
- 기능을 추가할 때는 해당 기능의 필요성뿐 아니라 기존 화면과의 관계, 사용자가 기능을 찾고 이용하는 과정까지 함께 고려해야 함을 배움.

### 남은 한계
- AI가 예상보다 높은 수준의 디자인과 페이지 연결을 구현했지만, 기능이 많아질수록 전체적인 구조와 일관성을 관리하기 어려웠음.
- 화면 구현 결과가 자연스러워 보이더라도 실제 사용자가 직관적으로 이해하고 이용할 수 있는지는 별도의 사용자 테스트를 통해 확인할 필요가 있었음.
- AI가 구현한 결과를 그대로 받아들이기보다 서비스의 핵심 목적에 맞는지 검토하고 불필요한 기능을 조정하는 과정이 필요했음.

## 6주차
### 사용한 AI 도구
- ChatGPT: 사용자 테스트 분석 질문 구성 및 개선 방향 구상 보조
- Claude Sonnet 5.5: 사용자 테스트 녹화 영상 분석 및 사용자 행동 검토

Figma Make: 프로토타입 UI 및 기능 개선
### 효과가 있었던 프롬프트(거의 대화형)
- 사용자 테스트 영상 분석 시 단순히 전체적인 인상을 요약하도록 하기보다, 초 단위로 사용자의 행동과 화면 체류 시간, 기능을 찾는 과정, 어려움을 겪은 지점 등을 구체적으로 분석하도록 요청함.
- 분석 결과에서 발견한 문제점을 팀원들과 검토하고, 이를 바탕으로 프로토타입의 UI와 기능을 하나씩 수정함.
- Figma Make에서는 기존 프로토타입을 기준으로 변경할 화면과 기능을 구체적으로 지정하고, 수정 결과를 확인하며 후속 요청을 이어가는 방식으로 작업함.
- 카카오맵 API 등 외부 기능을 적용할 때는 사용자가 원하는 기능을 먼저 검토한 뒤, 실제 API의 지원 범위와 구현 가능성을 확인하며 대안을 탐색함.

### 실패한 시도와 배운 점
- 팀원들과 반복적으로 프로토타입을 사용해 보고 Google Forms 설문까지 진행했지만, 실제 사용자 테스트에서는 예상과 다른 행동이 나타남.
- 초기 테스트에서 제시한 상황이 적절하지 않아 사용자가 예상한 흐름대로 움직이지 않았고, 기존 가설을 폐기한 뒤 테스트 상황과 방향을 수정하게 됨.
- 설문에서 필요하다는 응답이 높았던 기능도 실제 사용 과정에서는 사용자가 필요성을 느끼지 못하거나 활용하지 않는 경우가 있었음.
- 이를 통해 설문 응답만으로 사용자의 실제 요구를 확정하기 어렵고, 실제 행동을 관찰하며 가설을 검증하는 과정이 중요하다는 점을 배움.
- 사용자 요구를 반영하는 과정에서도 카카오맵 API의 기능 범위와 구현 가능성을 고려해야 했음. 이상적으로 생각한 기능을 모두 구현할 수는 없었으며, 제약 안에서 대안을 찾아야 한다는 점이 아쉬웠음.

### 남은 한계
- 참여자 3명의 테스트 결과만으로 다양한 사용자의 행동과 요구를 충분히 파악하기에는 한계가 있었음.
- AI 영상 분석은 사용자의 행동을 검토하는 데 도움이 되었지만, 분석 결과를 실제 영상과 대조하고 맥락을 확인하는 과정이 필요했음.
- 설문에서 드러난 요구와 실제 사용 행동 사이의 차이를 확인했지만, 어떤 기능을 최종적으로 유지하거나 제거할지 판단하려면 추가적인 검증이 필요함.
- 사용자 요구와 기술적 구현 가능성 사이에서 타협점을 찾아야 했으며, API의 제약에 따라 UI와 사용 흐름을 수정해야 하는 한계가 있었음.
- 기능을 많이 추가하는 것보다 핵심 기능을 선별하고 사용자가 실제로 활용할 수 있도록 단순하고 명확한 흐름을 설계하는 것이 중요하다고 판단함.

## 7주차
### 사용한 AI 도구
- Figma: 메인 홈, 해결 방법 제시 페이지, 커뮤니티 페이지의 UI 디자인 구현 및 디자인 시안 구성/중간고사 발표 PPT 제작. AS-IS·TO-BE, 페르소나 및 시나리오, 앱 플로우차트, 디자인 시안 비교, 개발 계획 및 일정 페이지 구성
- ChatGPT: 앱 화면에 사용할 3D 오브젝트 생성 및 수정. 초기 털 질감의 소라게부터 글래스모피즘 UI에 어울리는 유리 질감의 오브젝트까지 반복적으로 제작
- Claude AI: iOS 앱 출시를 위한 단계별 체크리스트 사이트 제작 및 팀원 공유


디자인 레퍼런스 자료: 3D 컨셉의 홈 화면을 중심으로 시각적 참고 자료를 수집하고 디자인 방향 구체화
### 효과가 있었던 프롬프트
- 디자인 컨셉에 맞춰 3D 오브젝트의 질감을 구체화하기: 처음에는 털 질감의 소라게 오브젝트를 제작했지만, 글래스모피즘 기반 UI와 시각적으로 어울리지 않는 문제가 있었음. 이후 화면의 디자인 컨셉에 맞춰 투명하고 매끄러운 유리 질감을 중심으로 이미지를 수정해 UI와의 일관성을 높였음.
- 생성한 이미지를 실제 UI에 적용하는 것을 고려하기: 단순히 개별 이미지의 완성도만 높이는 것이 아니라, 앱 화면에 배치했을 때 주변 UI와 조화를 이루는지를 기준으로 생성 결과를 검토하고 수정함. 최종적으로 3D 오브젝트를 직접 제작해 화면에 적용함으로써 컨셉에 맞는 시각적 경험을 구성할 수 있었음.

### 실패한 시도와 배운 점
- 오브젝트 자체의 완성도와 UI 전체의 완성도는 다를 수 있었음. 초기 털 질감의 소라게는 개별 이미지로는 표현이 가능했지만, 글래스모피즘을 중심으로 구성한 화면과는 질감과 분위기가 달랐음. 이미지 자체의 완성도뿐 아니라 화면 전체의 디자인 언어와 어울리는지도 함께 고려해야 한다는 점을 배움.
- 원하는 이미지를 한 번에 완성하기보다 반복적인 수정 과정이 필요했음. 생성된 이미지가 디자인 방향과 맞지 않을 때마다 질감과 시각적 표현을 조정했고, 최종적으로 UI에 적합한 3D 오브젝트를 제작할 수 있었음. 생성형 AI를 활용할 때도 결과물을 그대로 사용하는 것이 아니라 디자인 의도에 맞게 검토하고 수정하는 과정이 중요했음.
- 디자인 컨셉은 개별 화면뿐 아니라 서비스 전체의 경험과 연결되어야 했음. 초기 스케치 단계에서 3D 오브젝트를 활용한 컨셉과 깔끔한 UI 중심 컨셉을 각각 제안하고 비교함. 이후 브랜드의 개성과 시각적 차별성을 강화할 수 있는 방향을 중심으로 디자인을 구체화함.

### 다음에 개선할 점
- 3D 오브젝트를 제작하기 전에 화면별 역할과 오브젝트의 형태·질감·색상 기준을 정리해 반복적인 이미지 수정을 줄인다.
- 개별 화면의 완성도뿐 아니라 앱 전체의 컬러, 타이포그래피, 오브젝트 스타일이 일관되게 유지되는지 함께 검토한다.
- 디자인 시안 비교 단계에서 시각적 매력뿐 아니라 정보 전달력, 가독성, 사용성을 함께 평가해 최종 방향을 구체화한다.
- 피그마의 주요 화면과 컴포넌트를 정리하고, 실제 앱 개발 단계에서 구현할 수 있도록 화면별 디자인 기준을 명확히 문서화한다.
- iOS 출시 체크리스트를 실제 개발 진행 상황에 맞춰 갱신하고, 팀원들이 각 단계의 진행 여부를 확인할 수 있도록 관리한다.

### 남은 한계
- 초기에는 메인 홈, 해결 방법 제시 페이지, 커뮤니티 페이지를 중심으로 디자인을 진행해 앱의 모든 화면과 예외 상황에 대한 디자인 검토가 충분하지 않을 수 있음.
- 3D 오브젝트의 시각적 완성도와 화면 내 조화에 집중했으며, 실제 기기에서의 성능과 로딩 속도 등 구현 단계에서 확인해야 할 사항이 남아 있음.
- 정적인 디자인 시안만으로는 실제 화면 전환과 인터랙션의 사용성을 충분히 판단하기 어려워, 프로토타입 및 실제 앱 구현 단계에서 추가 검증이 필요함.
- iOS 출시 체크리스트 사이트를 제작해 공유했으나, 실제 앱의 개발·빌드·배포 과정에서 각 항목의 적용 여부를 지속적으로 확인해야 함.
- 디자인과 발표 자료 제작을 진행했지만, 실제 개발 결과물과 디자인이 일치하는지는 향후 구현 과정에서 확인해야 함.
