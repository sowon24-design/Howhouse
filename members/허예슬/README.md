- **수치를 명확하게 제시한 프롬프트:** 수치는 4배수를 기본으로 하되 필요한 경우 2배수를 허용하고, 카드 배경은 특정 Figma 프레임을 기준으로 맞추도록 지정함. 직접 수정한 디자인을 최대한 유지하면서 반복적인 수치·스타일 정리를 맡기는 데 효과가 있었음.

### 실패한 시도와 배운 점

- **스케치의 의도가 그대로 전달되지는 않았음.** 홈의 3D 집은 자취 초보자의 레벨을 표현하는 원룸이었지만, 처음에는 잘 꾸며진 집으로 생성되었음. 헤더와 집을 배경 위에 배치하려던 의도도 이미지 카드 형태로 해석되었음. ‘Lv.1’, 거미줄·먼지, 투명 배경, 카드가 시작되는 위치처럼 의미와 배치 조건을 구체적으로 설명해야 한다는 걸 배움.
- **같은 효과를 적용해도 시각적으로 동일하지 않을 수 있었음.** 흰색 카드에 같은 글라스 효과가 들어가 있었지만, 채우기 불투명도가 72%, 96%, 100%로 달라 보이는 차이가 생겼음. 효과 이름만 통일하는 것이 아니라 채우기·불투명도·테두리·그림자와 인스턴스의 개별 설정까지 확인해야 했음.
- **AI가 작업하는 환경과 실제 Figma 환경에 차이가 있었음.** 요청한 Pretendard를 Codex 연결 환경에서 불러오지 못해 초기 시안에 대체 폰트가 사용되었음. 생성 결과가 요청한 폰트·스타일과 일치하는지 직접 확인하는 과정이 필요했음. 결국 이를 한 번에 수정하기 위해 Type style을 만들 것을 명령한 후 스타일에서 일관적으로 변경하는 과정을 거침.

- **기존 디자인을 기준으로 일관성을 요청한 프롬프트:** 참고할 디자인 시안과 적용할 섹션을 지정하고, 기존 컴포넌트 및 디자인 시스템에 맞춰 화면을 생성하도록 요청함. 하단 CTA 버튼, 내비게이션 바, 상단 헤더 등 공통 영역의 배치와 간격을 맞추는 데 도움이 되었음.

### 실패한 시도와 배운 점
- **여러 화면을 한 번에 요청하니 완성도가 낮아짐.** 기존 시안을 바탕으로 여러 화면의 수정과 초안 생성을 한 번에 요청했지만, 결과물을 그대로 활용하기 어려웠음. 결국 기존 화면을 참고해 Figma에서 직접 다시 구성하는 방식으로 대부분의 화면 제작이 진행됨. 화면 수를 늘리기보다 한 화면씩 제작하고 검토하는 방식이 더 적합하다고 느낌.
- **수정 방향만 설명하는 것으로는 의도가 충분히 전달되지 않음.** 화면마다 개선 방향을 제시했지만, 구체적인 구성과 배치는 기대와 다르게 표현되었음. 휠 피커처럼 원하는 UI의 형태, 포함할 요소, 배치 방식을 명확히 설명했을 때 결과가 더 좋았음. AI에 요청하기 전, 최종 화면의 구조를 먼저 구체화할 필요가 있음을 배움.
- **디자인 시스템을 따르라는 요청만으로 모든 요소가 통일되지는 않음.** 기존 디자인을 참조하도록 해도 세부 요소는 직접 확인하고 조정해야 했음. 일관된 결과를 얻으려면 기준이 되는 스타일과 컴포넌트부터 정리되어 있어야 한다는 점을 확인함.

### 다음에 개선할 점
- 컬러, 타이포그래피, 간격 등 디자인 시스템의 기준을 체계적으로 정리한다.
- 아이콘의 크기와 선 두께, 형태를 통일하고, 반복되는 UI 요소를 컴포넌트로 정리한다.
- AI에는 화면별로 필요한 요소와 배치를 구체적으로 전달하고, 한 화면씩 검토한 뒤 다음 화면으로 확장한다.
- 개발에 필요한 핵심 화면과 상태를 우선 점검하고, 구현을 시작할 수 있도록 디자인 작업의 우선순위를 정한다.

### 남은 한계
- 일부 반복 UI는 컴포넌트화했지만, 디자인 시스템과 컴포넌트 정리가 전체 화면에 일관되게 적용된 상태는 아님.

- 아직 개발을 시작하지 못해, 실제 구현 과정에서 필요한 조정 사항은 확인하지 못함.
