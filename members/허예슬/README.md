### 사용한 도구
- Claude: 기술 타당성 검토, PRD 프롬프트 작성, 폴더 구조·README 문서 정리
- Manyfast: PRD 생성
- Figma / Figma Make: 와이어프레임, 프로토타입
- Codex: 저장소 폴더 구조 생성 및 커밋·push
- GitHub: 저장소 협업, PR 흐름

### 효과가 있었던 프롬프트
- (직접 옮겨 적기) PRD 프롬프트: 교수님이 말한 순서(리서치→문제→아이디어→퍼소나→시나리오→로파이)를 그대로 목차로 줌. 화면은 사진 대신 말로 설명함.
- (직접 옮겨 적기) Codex 폴더 구조 프롬프트: 교수님 가이드의 폴더 구조와 팀원 이름(유소원, 최연우, 허예슬)을 넣어 한 번에 생성하게 함.

### 실패한 시도와 배운 점
- **아이디어를 기술적으로 검증하니 기능이 바뀜.** 수리기사 일정 조율은 네이버/카카오 API가 영업시간·예약 현황을 주지 않아 구현이 어려워서 이번 범위에서 뺌. 좋은 아이디어도 데이터 소스가 없으면 못 만든다는 걸 배움.
- **GitHub 보호 규칙의 영향.** 본인 PR을 본인이 승인할 수 없어서 폴더 구조 PR(#1)이 바로 병합되지 않았고, 팀원 승인을 받은 뒤에 병합됨.
- **커밋이 Contributors에 안 보임.** 기여자 표시는 main에 들어간 커밋만 집계돼서, PR이 병합되기 전에는 내 계정이 보이지 않았음.
