### 실패한 시도와 배운 점
- **스크립트만으로는 분석이 안 됨.** 처음에 음성 스크립트만으로 템플릿을 채웠더니, 참여자가 어느 화면에서 무엇을 눌렀는지와 결과 칸을 채울 수 없었음. "여기랑 이거"처럼 화면을 가리키는 말도 무엇을 뜻하는지 알 수 없었음. 발언만으로는 행동을 알 수 없다는 걸 배움.
- **자료를 겹칠수록 결론이 정확해짐.** 손 촬영 영상만 봤을 때와 화면 녹화를 더했을 때 문제 정의가 바뀐 경우가 있었음. P02의 커뮤니티 문제는 '목록이 걸러지지 않는다'에서 '하단 탭으로 들어갈 때만 필터가 풀린다'로 바뀌었음. P03이 업체를 찾아 헤맨 원인도 '진입점이 안 보임'에서 '메시지를 보낸 뒤 홈으로 이동해서'로 바뀌었음. 관찰 자료는 화면 녹화를 기본으로, 여러 종류를 함께 남겨야 한다는 걸 배움.
- **리서치에서 고른 기능이 실제로는 쓰이지 않음.** 사용자 투표와 로파이 롤플레잉을 거쳐 핵심 기능으로 정한 SOS 모드를 UT에서는 과업 해결에 쓴 참여자가 없었음. 둘러본 참여자도 "굳이 두 개를 할 필요"가 있냐며 홈 입력과의 차이를 이해하지 못했음. 5주차에는 기술 검증으로 기능이 바뀌었다면, 이번에는 사용 검증으로 기능이 바뀜.
- **프로토타입의 예시 데이터도 api에 의거해서 구현 가능한 범위만 넣어야 한다.** 업체 카드에 평점·리뷰 수·후기 태그를 예시로 넣었더니, 테스터가 리뷰 내용과 가격까지 기대했음. 그런데 카카오맵 API는 이 정보를 주지 않고, 리뷰를 수집해 보여주면 저작권 문제가 생김. 프로토타입도 실제로 가져올 수 있는 데이터 범위 안에서 만들어야 테스트 결과를 그대로 쓸 수 있다는 걸 배움.
- **테스트 환경을 통제하지 못함.** P02의 시작 화면 '최근 확인한 문제'에 과업과 같은 문제가 미리 있어서 입력 단계를 건너뛰었고, 이전 세션의 기록도 쌓여 있었음. 촬영용 휴대폰에 카카오톡·인스타그램 알림이 계속 떠서 분석할 때 따로 걸러내야 했음.

### 다음에 개선할 점

<details><summary><h2>7주차</h2></summary>

### 사용한 도구
- Codex: 스케치와 레퍼런스를 바탕으로 Figma 디자인 초안 생성, 공통 스타일·오토레이아웃 적용, 디자인 시안별 수정
- Figma: AI가 생성한 초안의 레이아웃·타이포그래피·컴포넌트를 직접 수정하고 디자인 고도화
- Claude, ChatGPT, Codex: 플로우 차트·유저 저니맵 정리, 중간 발표 PPT에 수록할 1–7주차 활동 일부 요약
- ChatGPT: 앱에 사용할 3D 이미지 생성 및 배경 투명화

### 효과가 있었던 프롬프트
- **구체적인 프롬프트:** 직접 그린 스케치를 기본 구조로 제시하고, 기존 바이브코딩 디자인은 컬러 참고용이라고 설명함. 또한 네비게이션 등 글라스 효과나 인터렉션이 들어가는 디자인에 대해서 자세히 알아들을 수 있도록 구체적으로 프롬프트 작성. 예시: 본문 16pt·헤더 20pt, 오토레이아웃 적극 사용, 공통 카드 디자인(padding 16px)처럼 구체적인 조건도 함께 전달해 초안을 만드는 기준을 잡을 수 있었음.
- **수치를 명확하게 제시한 프롬프트:** 수치는 4배수를 기본으로 하되 필요한 경우 2배수를 허용하고, 카드 배경은 특정 Figma 프레임을 기준으로 맞추도록 지정함. 직접 수정한 디자인을 최대한 유지하면서 반복적인 수치·스타일 정리를 맡기는 데 효과가 있었음.
- **추상적인 분위기를 구체적인 규칙으로 바꾼 프롬프트:** 두 번째 시안은 ‘깔끔하고 솔리드한 느낌’이라는 방향과 함께 흰 배경 유지, 포인트 컬러 `#CEFF53` 추가, 3D 제외, 커뮤니티 제목 1줄·본문 2줄 이후 말줄임, 강제 줄바꿈 금지를 명시함. 분위기만 설명하는 것보다 실제 화면에 적용할 조건을 전달하는 것이 수정 방향을 분명하게 했음.

### 실패한 시도와 배운 점
- **디자인 고도화를 AI만으로 완성하기는 어려웠음.** 초안은 빠르게 만들 수 있었지만, 레이아웃이 전형적이고 세부적인 간격·위계·시각적 완성도는 직접 조정하는 것이 훨씬 빨랐음. Codex로 편집 가능한 초안을 만든 뒤 Figma에서 고도화하고, 반복적인 정리는 다시 AI에 맡기는 방식이 더 효율적이었음.
- **스케치의 의도가 그대로 전달되지는 않았음.** 홈의 3D 집은 자취 초보자의 레벨을 표현하는 원룸이었지만, 처음에는 잘 꾸며진 집으로 생성되었음. 헤더와 집을 배경 위에 배치하려던 의도도 이미지 카드 형태로 해석되었음. ‘Lv.1’, 거미줄·먼지, 투명 배경, 카드가 시작되는 위치처럼 의미와 배치 조건을 구체적으로 설명해야 한다는 걸 배움.
- **같은 효과를 적용해도 시각적으로 동일하지 않을 수 있었음.** 흰색 카드에 같은 글라스 효과가 들어가 있었지만, 채우기 불투명도가 72%, 96%, 100%로 달라 보이는 차이가 생겼음. 효과 이름만 통일하는 것이 아니라 채우기·불투명도·테두리·그림자와 인스턴스의 개별 설정까지 확인해야 했음.
- **AI가 작업하는 환경과 실제 Figma 환경에 차이가 있었음.** 요청한 Pretendard를 Codex 연결 환경에서 불러오지 못해 초기 시안에 대체 폰트가 사용되었음. 생성 결과가 요청한 폰트·스타일과 일치하는지 직접 확인하는 과정이 필요했음. 결국 이를 한 번에 수정하기 위해 Type style을 만들 것을 명령한 후 스타일에서 일관적으로 변경하는 과정을 거침.
- **사용량을 고려한 작업 범위 관리가 부족했음.** Figma 구조 확인, 화면 생성, 반복 수정과 검수 과정에서 Codex 사용량이 예상보다 많이 소모되었음. 한 번에 모든 화면을 완성하려 하기보다 화면별 작업 범위를 정하고, 수정 요청을 모아 전달하며 여러 날에 나누어 진행할 필요가 있었음.

### 다음에 개선할 점
- 공통 색상·타이포·간격·카드 규칙을 먼저 정리한 뒤 화면을 확장한다. 카드 한 개를 먼저 검수하고 여러 화면에 적용해 반복 수정을 줄인다.
- 직접 수정한 뒤에는 최신 Figma 프레임을 기준으로 작업하도록 지정하고, 변경 범위를 좁혀 전달한다.
