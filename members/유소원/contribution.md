## 9주차
### 맡은 역할 :
- 어쩌집의 LLM 문제 분석 기능 및 실제 API 연결 구현
- 분석 서버·저장 환경 구성, 비용 절감 및 오류 진단
- 팀원 화면과 분석 모듈의 연결 기준 정리 및 Android 실기기 검증 참여
### 한 일 :
- 개발 환경 및 협업 기준 정리: 기존 공통 설정을 유지하고, 최신 main을 담당 브랜치에 반영하면서 기존 작업을 보존. 분석 담당 코드를 `src/analysis/`와 서버 영역으로 구분하고, 화면 이동을 담당하는 팀원들에게 함수·상태·취소·결과 전달 방법을 문서로 제공
- AI 제공업체 비교 및 API 준비: OpenAI GPT, Google Gemini, Anthropic Claude에 같은 질문과 사진을 사용하여 답변의 질을 확인하는 비교 테스트를 진행하고 OpenAI API를 채택. 학생 프로젝트의 비용을 고려하여 결제·키 발급·서버 보관 방식과 실제 호출 전 확인 절차를 정리
- 글·사진 분석 흐름 구현: 사용자 글과 사진으로 주거 문제를 파악하고, 기존 사례의 증상·조건·조치가 적합하면 사례 ID로 원본 데이터를 조회하도록 구성. 기존 사례가 없더라도 정보가 충분하면 새 해결책을 생성하고, 정보 부족·서비스 범위 밖·안전한 안내 불가 등의 실패를 구분
- 해결 결과와 문의 문장 연결: 기존 사례 결과와 생성 결과의 전달 형식을 구분하고, 생성 결과에는 준비물·단계별 조치와 문의가 필요한 대상별 문장을 작성하도록 구현. 전문가 문의가 필요한 상황의 안전한 안내, 예상 시간과 책임 관련 정보, 수정 가능한 문의 문장 전달 방식을 보완
- 분석 상태 및 예외 처리: 분석 시작·성공·실패·중단을 화면 담당자가 연결할 수 있도록 분리하고, 90초 대기 제한과 취소된 요청의 늦은 응답 무시를 적용. 실패·재입력·연결 복구 시 글과 사진을 보존하고 사용자가 다시 분석을 선택하는 흐름을 검증
- 비용 절감 및 키 보호: 동일 사용자의 동일 입력에 대한 유효한 분석 답변을 암호화하여 재사용하고, 진행 중인 중복 요청을 합쳐 불필요한 API 호출을 줄임. OpenAI 키와 Supabase secret 키는 프런트엔드가 아닌 서버 환경변수에서 관리하고, 공개 연결 설정과 비밀 키를 구분
- 시험 서버 배포 및 운영 오류 대응: Render 분석 서버와 Supabase의 임시 사용자 인증·암호화 결과 저장 환경을 연결. PR 반영 후 지정 커밋을 수동 배포하고 Live 상태를 확인. 실패 응답을 구분하는 진단을 추가하고, `provider-http-401` 발생 시 OpenAI 키 만료를 확인하여 키 교체와 재배포를 진행
- Android 실기기 검증: 갤럭시 퀀텀 4를 USB 디버깅으로 연결해 사진 첨부와 개수 표시, 분석 결과 확인, 재입력 시 사진 보존, 문의 문장 수정·복사 및 화면 복귀 후 내용 유지 등을 단계적으로 확인
- 평가·의견 저장 서버 준비: 좋아요·싫어요의 선택·해제·전환과 별도 의견 제출을 처리하는 API·Supabase SQL을 작성. 임시 사용자와 실제 결과 식별값을 연결하고, 중복 요청·선택 순서 역전·저장 실패·사용자 간 접근을 검증. 평가·의견 및 관련 식별 기록의 보관 기간은 1년(365일)로 정리하고, 실제 DB 적용·삭제 작업·B 화면 연결 절차를 문서화
- 검증 및 개인정보 검토: 최신 main과 병합한 코드에서 자동 검사 122개, 빌드와 공통 설정 검사를 통과하고 365일 조건의 SQL 검사 11개를 추가 확인. OpenAI·Supabase와 실제 중계 서버인 Render의 공식 정책을 확인해 국외 처리 고지·동의에 필요한 항목과 추가 확인 사항을 정리
### 결과 (커밋/PR/이슈 링크로 근거 남기기):
분석 모듈·서버·연결 계약과 검증을 담당하여 분석 샘플 연결부터 글·사진을 사용하는 실제 API 분석, 시험 서버 배포와 Android 실기기 검증까지 진행했다. 평가·의견 저장 코드는 main에 병합했으며, 실제 Supabase 적용·주기 삭제 작업·서버 활성화·B 화면 연결은 코드 준비와 구분하여 후속 검증 대상으로 남겼다. 키 교체 후 서버 정상 기동을 확인했으며, 결로 분석 오류의 최종 해소 여부는 실제 재분석 결과로 별도 확인하도록 정리했다.

## 10주차
### 맡은 역할 :
- 최신 출시 화면에 맞춰 LLM 분석 결과와 문의 초안, 준비물 전달 방식을 보완했다.
- 분석 서버의 비용 보호, 평가·의견 저장, 동의·신고·삭제·운영자 검토 기능과 실서버 검증을 담당했다.
- Android 실기기 확인에 참여하고, 출시를 위한 업체별 개인정보 처리 조건과 남은 연결 항목을 정리했다.
### 한 일 :
- 출시 화면과 분석 결과 보완: A06 문제 확인 흐름과 최신 화면 요구에 맞춰 분석 결과의 전달 기준을 보완했다. 생성 문제 제목은 가급적 짧은 명사로 작성하고, 문의 초안은 최대 4문장으로 맞췄다. 준비물은 0단계로 구분하여 총 해결 단계 수에서 제외하고, 각 준비물을 누르면 해당 제품의 쿠팡 검색 결과로 이동하도록 보완했다. 문제 상황을 자세히 적도록 돕는 추가 안내는 요청에 따라 보류하고 다른 변경과 구분했다.
- 평가·의견 저장 적용과 검증: 9주차에 준비했던 저장 구조를 이어서 Supabase와 서버에 적용하고, 기존 사례 ID와 생성 결과 식별값을 구분해 평가·의견이 올바른 해결 결과에 연결되는지 확인했다. 평가 선택과 의견 제출, 공백 거절, 중복 요청, 이전 선택의 늦은 도착, 사용자 간 접근 차단을 검증했다. 보관 기간은 최대 365일로 유지하고, 사용자 삭제가 먼저 이루어지면 관련 기록도 정리하도록 준비했다.
- 공개 출시 비용 보호: OpenAI 월 예산을 10달러, 사용자별 신규 유료 분석을 한국 시간 기준 하루 5회로 정하고, 전체 동시 예약 3개와 신규 분석 중단 장치를 준비·적용했다. 기존 답변 재사용과 신규 호출을 구분했으며, 자동 유료 재시도 없이 예산과 사용량을 관리하도록 구성했다. 월 예산은 운영 목표와 서버 보호 설정으로 관리하며 모든 외부 청구가 정확히 그 금액에서 끝난다고 단정하지 않았다.
- Android 실기기 확인: Android Studio와 USB 디버깅으로 별도 테스트 앱을 설치해 첫 화면, 분석 결과, 4문장 이내 문의 초안, 복사와 수정 내용 보존을 직접 확인했다. 오프라인 복구 후 자동 분석이 시작되지 않는지, 분석 중 뒤로가기 후 늦은 응답이 반영되지 않는지, 글과 사진이 유지되는지도 확인했다. 출시용 서명 키를 생성했으며 키와 비밀번호는 저장소에 포함하지 않았다.
- 출시 모드와 개인정보 기능 준비: 출시 모드에서 개발용 안내·테스트 도구를 숨기고, 만 14세 이상 확인과 분석·국외 이전 동의 흐름을 준비했다. 동의 철회, 본인 데이터 삭제와 외부 삭제 요청, AI 결과 신고 및 운영자 검토 기능을 추가했다. 동의·삭제·신고 검토용 테이블과 서버 전용 권한을 적용하고, 승인된 운영자 계정 한 개만 검토 기능을 사용할 수 있도록 설정했다.
- 보관 정책과 안전한 빌드 조건 정리: 답변 캐시 7일, 호출 기록 30일, 미사용 임시 계정 90일, 평가·의견 최대 365일의 정리 기준을 준비했다. 최종 개인정보 문서가 미확정이거나 개발용 자산이 남아 있으면 출시 빌드를 통과시키지 않도록 검사 조건을 추가했다. 정책 준비와 실제 운영 기능의 정식 활성화는 구분해서 관리했다.
- 미국 지정 분석과 실서버 검증: Render 시험 서버에 출시 대응 코드를 배포하고, 미국 지정 OpenAI 요청이 지원되는지 고정 문장으로 한 번 확인했다. 이후 실제 개인정보·저장 기능 검사에서는 유료 AI 호출 없이 54개 항목을 검증했다. 운영자 화면에서 테스트 신고의 검토 상태를 저장하고 다시 조회했으며, 검증 중 만든 임시 계정 4개와 관련 테스트 기록의 정리를 확인했다. 검증 후에는 기존 시험 앱과의 호환성을 위해 개인정보 기능 활성화 설정을 원복하고 남은 정식 적용 절차를 기록했다.
- 개인정보 고지 근거 조사: Render의 싱가포르 서버, Supabase의 서울 DB·Auth, OpenAI의 미국 지정 분석 요청과 데이터 공유 비활성화 상태를 구분해 확인했다. 공식 정책의 내용과 실제 계정에서 확인한 사실을 나누고, 팀원이 개인정보 문서를 작성할 수 있도록 업체별 처리 국가·보관·지원 접근의 확인 범위를 정리했다. Supabase에 문의 메일을 발송해 DPA의 약관 자동 적용을 확인했지만, EU 로그 국가와 내부 기록 보관기간은 답변이 남은 항목으로 유지했다.
- 대체 서비스 및 출시 조건 비교: AWS·네이버클라우드·NHN Cloud의 공식 자료를 찾아 저장 지역, 로그·백업, 지원 접근과 요금을 비교했다. 특정 업체 사용 가능 여부와 우리 앱의 개인정보·보안·신고 의무 충족 여부를 구분했으며, 서비스 이전이나 유료 가입을 임의로 진행하지 않았다.
### 결과 (커밋/PR/이슈 링크로 근거 남기기):
9주차에 구현한 실제 분석 기능을 출시 화면과 공개 운영 조건에 맞게 보완했다. 출시 대응 변경에서 자동 검사 197개와 타입 검사·미리보기 빌드·출시 차단 검사를 확인했고, 실서버에서는 유료 분석 없이 54개 항목을 검증했다. Android 테스트 앱에서도 분석·문의·오프라인 복구·취소와 입력 보존을 확인했다. 검증 결과와 적용 범위는 문서 PR로 공유했다.

다만 최종 출시 앱과 개인정보 문서가 모두 적용되어 Google Play 공개 출시까지 완료되지는 못했다. 최종 동의 기록 연결, 정책 URL과 서버 기능의 정식 활성화, 최종 서명 AAB 검증과 Play 심사 제출은 후속 확인 대상으로 남겼다. Supabase의 구체적인 운영 로그 국가·별도 내부 기록 보관기간과 팀원 수동 백업 여부도 미확정 사항으로 정리했다.
