## 3. 분석 프롬프트

### 3.1 설계 과정

1. **스크립트만으로 시작:** 처음에는 스크립트만 주고 템플릿 07~10의 빈칸을 채우게 했다. 발언은 잘 정리됐지만 '어느 화면에서 무엇을 눌렀는지'와 '결과' 칸은 채울 수 없었다.
2. **예시 문체 맞추기:** 예시 작성문을 주고 같은 형식으로 다시 쓰게 했다. 여기서 '화면·행동은 "~함." 형태', '발언은 핵심 구절만' 같은 규칙이 정해졌다.
3. **영상 분석용 프롬프트 작성:** 영상을 함께 분석하기 위해, 반드시 지킬 규칙과 출력 형식을 정한 프롬프트를 만들었다(3.2절). 이후 세 참여자 모두 이 프롬프트를 기준으로 분석했다.

### 3.2 최종 프롬프트

```
# 역할
너는 사용성 테스트(UT) 관찰 기록을 정리하는 UX 리서처야.
첨부한 자료만 근거로, 관찰된 사실을 시간순으로 기록해 줘.

# 프로젝트 맥락
- 서비스: 어쩌집 v0.1 — 자취방에 문제가 생겼을 때 다른 자취생들의 해결 사례를 찾아보고, 긴급 상황에서는 바로 행동으로 연결해 주는 앱
- 참여자: [P03] / 진행자: [참석자 1] / 관찰자: [참석자 3]
- 참여자에게 읽은 과업:
  "설거지를 하려고 싱크대 수납장을 열었는데 아래쪽에 물이 새고 있는 상황입니다. 그런데 어디서 물이 새는지 정확히 모르겠고 일단 이걸 해결했으면 좋겠습니다. 앱에서 문제를 해결하는 방법을 찾아보세요. 다 했다고 생각하면 알려주세요."
- 관찰자용 체크포인트:
  1 · 진입: 문제 해결 사례를 검색하는 방법을 스스로 선택
  2 · 수행: 선택한 검색 유형에 따라 절차를 수행해 해결 방법까지 도달
  3 · 확인: 알맞은 사례의 해결 방법을 확인한 뒤 끝났다고 선언
- 판정 기준: 독립 성공(힌트 없이 완료) / 도움 후 성공(경로 힌트 후 완료) / 실패(오답·포기·사전 종료 기준 도달)

# 첨부 자료
1. 손 촬영 영상: 참여자가 휴대폰을 조작하는 손과 화면을 찍은 영상. 화면이 흐리거나 반사·각도 때문에 잘 안 보이는 구간이 있음.
2. 음성 스크립트(텍스트): 자동 음성 인식이라 오탈자가 있음. 화자는 "참석자 1/2/3"으로 표기됨.

# 반드시 지킬 규칙
1. 카카오톡 알림 무시: 화면 상단이나 중간에 뜨는 카카오톡 알림(배너, 팝업, 알림음)은 프로토타입이 아니라 촬영에 쓴 실제 휴대폰의 알림이다. 화면 전환, 참여자 행동, 체류 시간 계산에 포함하지 말 것. 단, 참여자가 알림을 실수로 눌러 프로토타입을 벗어났다면 "외부 알림으로 이탈"이라고 별도로 기록할 것.
2. 확인된 것만 쓰기: 화면이 잘 안 보이면 추측하지 말고 "화면 미확인"으로 적을 것. 손 동작은 보이는데 누른 대상이 안 보이면 "○○ 위치 탭(대상 미확인)"처럼 보이는 만큼만 적을 것.
3. 확실도 표시: 화면 이름, 누른 버튼 등 판단이 들어간 항목에는 [확실] / [추정] 중 하나를 붙일 것.
4. 발언은 원문 그대로: 직접 발언은 스크립트 원문을 따옴표로 옮기고, 음성 인식 오류로 보이는 단어는 고치지 말고 옆에 (→ 추정 단어)로 표기할 것.
5. 사실과 해석 분리: 관찰 기록(1~3번 출력)에는 해석을 넣지 말고, 해석은 4번 출력에만 쓸 것.
6. 시간 맞추기: 영상과 스크립트의 시작점이 다를 수 있다. 진행자가 과업 문구를 읽기 시작하는 시점을 기준(00:00)으로 맞추고, 차이가 있으면 몇 초 보정했는지 먼저 알려줄 것.
```

## 4. AI가 실제로 분석한 방법

AI는 영상을 사람처럼 연속으로 재생해 보지 않는다. 영상을 **장면 사진(프레임)**과 **소리 크기**로 바꾼 뒤 읽었다.

### 4.1 영상 → 장면 사진

1. **장면 추출:** 영상에서 1초마다 한 장씩 장면을 뽑았다. 각 장면에 영상 시각을 노란 글씨로 찍어, 사진만 봐도 몇 분 몇 초인지 알 수 있게 했다.
2. **휴대폰 부분만 자르기:** 손 촬영 영상은 휴대폰이 있는 부분만 잘라 키웠다. 화면 녹화는 그대로 썼다.
3. **한 장에 모아 보기:** 1초 장면 20~24장을 한 장의 사진에 바둑판처럼 모아, 20초 구간의 흐름을 한눈에 볼 수 있게 했다.
4. **흐린 장면 확대:** 화면 전환 직전·직후처럼 판단이 어려운 장면은 크게 다시 뽑아 확인했다.

```
# 사용한 명령의 예 (ffmpeg)
ffmpeg -i 영상.mp4 -vf "fps=1,crop=…,drawtext=text='%{pts\:hms}'…" s_%03d.jpg   # 1초마다 장면 + 시각 표시
ffmpeg -f concat -i 목록.txt -vf "tile=8x3" t_000.jpg                          # 24장을 한 장으로
```

### 4.2 소리 → 말한 구간

- 영상의 소리를 1초 단위로 나눠 크기(dB)를 계산했다. 소리가 큰 구간은 누군가 말한 구간이다.
- 이 '말한 구간'을 스크립트의 발화 시각과 비교해 시간 차이를 찾았다.
- 작업 환경에서 음성 인식 프로그램을 쓸 수 없어, 말의 내용은 팀이 준 스크립트만 근거로 했다.

### 4.3 세 자료의 시간 맞추기

| 참여자 | 기준 시간 | 스크립트 | 다른 영상 | 맞춘 근거 |
|---|---|---|---|---|
| P01 | 화면 녹화 | 화면 녹화와 같음 (±5초) | 손 촬영 = 화면 녹화 − 42초 | 손 촬영이 과업 설명 이후에 시작되어, 과업 설명부터 담긴 화면 녹화를 기준으로 삼음 |
| P02 | 손 촬영 | 손 촬영 + 1분 45초 (±2초) | 화면 녹화 = 손 촬영 + 1초 | 진행자 설명이 끝나는 시점, 화면 전환 6곳 |
| P03 | 손 촬영 | 손 촬영 + 17초 (±5초) | 화면 녹화 = 손 촬영 + 8초 | 화면과 발언 내용이 맞는 지점 3곳, 화면 전환 6곳 |

- **스크립트 ↔ 영상:** '단계 3 연결부 너트 화면'과 "연결부 너트를…" 발언처럼, 화면 내용과 발언 내용이 맞는 지점을 기준점으로 삼았다.
- **손 촬영 ↔ 화면 녹화:** '분석 중' 화면, 카메라 화면처럼 눈에 띄는 화면 전환 시점을 두 영상에서 찾아 차이를 계산했다.

### 4.4 화면·행동 판별

- **화면 이름:** 화면에 보이는 제목(예: '메시지 만들기', '주변 업체 찾기')을 그대로 썼다. 제목이 보이면 [확실], 일부만 보이면 [추정]이다.
- **누른 것:** 화면 녹화에는 터치 표시가 없어, '바뀌기 전 화면'과 '바뀐 후 화면'을 비교해 무엇을 눌렀을지 판단했다. 손 촬영에서 손가락 위치가 함께 보이면 [확실], 화면 변화로만 판단하면 [추정]이다.
- **입력 내용:** 화면 녹화에서 키보드로 입력하는 글자를 장면마다 읽어 기록했다. 예: "싱크대 화분 수납장에 물이 셌어요"(P03)
- **체류 시간:** 같은 화면이 연속으로 나온 장면 수로 계산했다. 1초 간격이라 ±1초 오차가 있다.
- **화자 판단:** 스크립트의 '참석자 번호'는 세션마다 역할이 달랐다. 과업 문구를 읽는 사람은 진행자, 앱을 조작하며 혼잣말하는 사람은 참여자로 판단했다. 화자 표기가 섞인 구간은 [화자 추정]으로 표시했다.

## 5. 분석 단계별 진행

### 5.1 1단계 — 스크립트만으로 기록

- **입력:** P01 스크립트, 템플릿 이미지, 예시 작성문
- **결과:** 템플릿 07(사건 기록)의 발언 칸, 08(사후 질문), 09(문제 정의) 일부
- **한계:** 화면·행동과 결과 칸을 채울 수 없었다. "여기랑 이거"처럼 화면을 가리키는 말의 대상을 알 수 없었다.

### 5.2 2단계 — 손 촬영 영상 + 스크립트 (P02, P03)

- **입력:** 손 촬영 영상, 스크립트, 분석 프롬프트
- **결과:** 화면 체류 타임라인, 사건 기록, 체크포인트 요약, 문제 후보, 확인 필요 목록
- **한계:** 손에 가려 무엇을 눌렀는지 안 보이는 구간이 많았다. 입력한 글자와 버튼 문구는 읽기 어려웠다.

### 5.3 3단계 — 화면 녹화로 보강 (P02, P03)

- **입력:** 화면 녹화 + 기존 기록
- **한 일:** 화면 녹화를 손 촬영과 시간을 맞춘 뒤, [추정]과 '진입 방법 미확인'으로 남긴 칸을 확인했다. 수정 내용은 본문에 바로 반영하고 변경 이력은 따로 두지 않았다.
- **화면 녹화로 결론이 바뀐 예:**
  - P02 커뮤니티 문제: 처음에는 '목록이 문제로 걸러지지 않는다'로 봤다. 화면 녹화를 보니 해결 사례 페이지에서 들어가면 걸러져 있었고, **하단 탭으로 들어갈 때만 필터가 풀렸다.** 문제 정의를 이에 맞게 고쳤다.
  - P03 업체 찾기 문제: 처음에는 '업체 찾기 진입점이 안 보인다'로 봤다. 화면 녹화를 보니 **메시지를 보낸 뒤 홈으로 자동 이동해서** 보던 문제를 잃어버린 것이었다. 이것이 수정사항 5번의 근거가 되었다.
  - P03 용어 문제: 화면 녹화에서 참여자가 '패킹' 문구를 **길게 눌러 찾아보기 메뉴를 띄운 장면**이 확인되었다. 스크립트의 "해킹이 뭐죠"가 "패킹이 뭐죠"라는 것도 이 장면으로 알 수 있었다.

### 5.4 4단계 — 세 자료를 한 번에 (P01)

- **입력:** 손 촬영 영상, 화면 녹화, 스크립트, 분석 프롬프트 + 인스타그램 알림 무시 지시
- **한 일:** 앞 단계의 방법을 한 번에 적용했다. 이 세션에서 처음 발견된 문제(음성 입력이 비어 있어도 분석이 진행됨)도 문제 후보에 넣었다.

### 5.5 제외한 알림

| 참여자 | 알림 | 구간 | 처리 |
|---|---|---|---|
| P01 | 인스타그램 | 3:41~3:43 | 화면 전환·체류 시간에서 제외 |
| P02 | 카카오톡 | 3:06~4:33 | 화면 전환·체류 시간에서 제외 |
| P03 | 카카오톡 | 2:55~5:28 | 화면 전환·체류 시간에서 제외 |

세 세션 모두 참여자가 알림을 눌러 프로토타입을 벗어난 장면은 없었다.

## 6. 기록에서 수정사항까지

1. **세 기록 비교:** 세 참여자의 문제 후보(U-01~U-05)를 나란히 놓고, 두 명 이상에게서 반복된 문제와 한 명에게서 강하게 나타난 문제를 구분했다.
   - 반복된 문제: 해결 단계 용어(P01·P03), 긴급 모드의 용도(P01·P02)
   - 한 명에게서 강하게 나타난 문제: 업체 선택 근거(P03), 메시지 전송 후 이동(P03)
2. **팀 결정:** 팀이 기록을 검토하고 고칠 항목 6개를 메모로 정했다. AI가 제안한 문제 후보 중 일부(커뮤니티 필터, 글쓰기 필수 항목 등)는 이번 수정에 넣지 않았다.
3. **기술 확인:** 업체 정보는 카카오맵 로컬 API가 제공하는 범위(업체명·주소·전화번호·장소 링크)와 리뷰 수집의 저작권 문제를 확인한 뒤 수정 방향을 정했다.
4. **문서화:** 수정 항목마다 인사이트, UT 근거, 수정 이유, 수정 전·후를 `UT1_수정사항.md`에 정리하고, 바뀐 기능을 `PRD.md`에 반영했다.

## 7. 한계와 주의할 점

- **1초 간격의 한계:** AI는 1초마다 뽑은 장면만 봤다. 1초보다 짧은 터치나 빠른 스크롤은 놓쳤을 수 있다.
- **터치 위치 미확인:** 화면 녹화에 터치 표시가 없어, 일부 '누른 것'은 [추정]으로 남았다.
- **음성 인식 오류:** 말의 내용은 자동 음성 인식 스크립트에만 의존했다. 화자 표기가 섞이거나 단어가 깨진 구간이 있다. 각 기록의 '확인 필요 목록'에 정리했다.
- **해석은 가설:** 문제 후보의 원인 가설과 개선 가설은 AI의 해석이다. 실제 수정 여부는 팀이 판단했고, 효과는 다음 UT에서 확인한다.
- **판정은 팀이:** 체크포인트 판정(독립 성공 / 도움 후 성공 / 실패)은 AI가 하지 않고 비워 두었다.
- **테스트 환경 차이:** 세션마다 프로토타입의 시작 상태가 달랐다(예: P02의 '최근 확인한 문제'에 과업과 같은 문제가 미리 있었음). 결과를 비교할 때 감안해야 한다.

### 8.1 준비할 것

| 자료 | 권장 사항 |
|---|---|
| 화면 녹화 | 가장 중요한 자료. 세션마다 반드시 녹화 |
| 손 촬영 영상 | 휴대폰 부분만 크게 나오게 촬영. 화면 녹화가 있으면 손 동작 확인용 |

| 파일 이름 | `P04_화면녹화.mp4`처럼 참여자 코드를 붙임 |

- **용량 줄이기:** 파일이 너무 크면 H.264(.mp4), 10fps, 비트레이트 2Mbps, 모노 오디오로 내보낸다. 1초 간격으로 분석하므로 프레임 수를 줄여도 결과에 영향이 없다.
- **테스트 전 초기화:** 프로토타입의 '최근 확인한 문제'와 마이의 문제 기록을 비운 상태로 시작한다.
- **알림 끄기:** 촬영용 휴대폰은 방해 금지 모드를 켜 두면 알림 처리 과정을 줄일 수 있다.

### 8.2 분석 순서

1. 3.2절의 프롬프트에서 참여자 코드, 진행자·관찰자 번호, 과업 문구를 바꾼다.
2. 화면 녹화, 손 촬영 영상, 스크립트를 함께 첨부하고 프롬프트를 보낸다. 다른 알림이 떴다면 무시하라는 지시를 덧붙인다.
3. AI가 알려준 시간 보정 값을 먼저 확인한다.
4. [추정] 항목과 '확인 필요 목록'을 팀이 영상·녹음으로 직접 확인한다.
5. 체크포인트 판정을 팀이 채운다.
6. 기록을 `UT_P0n.md`로 저장소에 올린다.
