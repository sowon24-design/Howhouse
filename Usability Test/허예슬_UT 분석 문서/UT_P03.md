## 한눈에 보기

- 시작 화면의 '최근 확인한 문제'에는 과업과 같은 문제가 없었다. 참여자는 **사례 탭 → 직접 입력**으로 문제를 입력했고, 1:48에 해결 방법 화면에 도착했다. 5:40쯤 "제 상황은 끝난 것 같은데요"라고 **완료를 선언**했다.
- 해결 단계 화면에 **66초** 머물렀다. 단계 3 '연결부 너트를 손으로 조이거나 패킹을 교체해요'의 **문구를 길게 눌러 텍스트 선택 메뉴(복사하기·찾아보기·번역)를 띄웠고**, "패킹이 뭐죠", "너트 같은 거도 잘 모른다"고 말했다. **용어를 몰라 따로 찾아보려 한** 신호다.
- 메시지를 보낸 뒤 홈으로 자동 이동하자, **문제 상세로 돌아가는 길을 찾느라 홈 → 사례 → 커뮤니티 → 마이를 거쳐** '우리 집 문제 기록'에서 다시 들어갔다 (23초, 3:16~3:38).
- 주변 업체 화면에 **70초** 머물렀다. 업체 카드에는 평점, 리뷰 수, 후기 태그가 있었다. 하지만 "이걸로는 선택하기 좀 힘들 것 같다"며 **리뷰 내용, 가격, 출동 속도**를 알고 싶다고 했다. 전화가 부담스럽다고 말했지만, 결국 첫 번째 업체의 '전화'를 눌렀다 (4:49).
- 커뮤니티에 "누수해결😊" 글을 올린 직후 완료를 선언했다. 이후 약 1분 동안 커뮤니티 검색과 마이의 집 정보 화면을 둘러보았다.

## 0. 기록 기준

### 시간 보정

- **기준 시간은 손 촬영 영상**이다. 이 문서의 모든 시각은 손 촬영 영상 시간이다.
- **손 촬영 0:00 = 스크립트 00:17** (오차 ±5초). 스크립트 시각은 손 촬영 시간에 0:17을 더하면 된다.
  - 근거: 화면과 발언 내용이 맞는 지점을 기준으로 삼았다.
    - 단계 3 '패킹' 문구 선택(2:15)과 "해킹이 뭐죠(→ 패킹이 뭐죠) 연결부 너트를…"(스크립트 02:29)
    - '전화' 탭(4:49)과 "또 전화를 해볼까"(스크립트 05:05)
    - 글 등록 직후(5:35)와 "제 상황은 끝난 것 같은데요"(스크립트 05:05 블록 끝부분)
  - 블록마다 차이가 몇 초씩 달라 오차가 P02보다 크다.
- **화면 녹화 = 손 촬영 + 약 8초** (오차 ±1초). 화면 녹화 시각에서 8초를 빼면 손 촬영 시간이 된다.
  - 근거: 화면 전환 시점 6곳을 맞춰 보았다.
    - 사례 탭: 손 1:10 / 화면 1:18
    - 분석 중 화면: 손 1:41 / 화면 1:49
    - 커뮤니티 글: 손 2:54 / 화면 3:02
    - 업체 화면: 손 3:39 / 화면 3:47
    - 새 글 작성: 손 5:04 / 화면 5:12
    - '사례가 등록됐어요' 토스트: 손 5:35 / 화면 5:43
- 과업 문구를 읽기 시작한 정확한 시점은 단어 단위로 확인할 수 없었다.

### 제외한 것

- **카카오톡 알림**: 약 2:55~5:28에 화면 상단에 알림 배너가 표시됨 (화면 녹화로 확인). 실제 휴대폰의 알림이므로 화면 전환과 체류 시간 계산에서 모두 제외했다. 참여자가 알림을 누른 장면은 없다.
- **화면 녹화 마지막 6:45~6:46**: 녹화를 끝내려고 제어 센터를 연 장면이라 제외했다.

### 표기

- `[확실]` 화면 문구가 보여 확인됨 / `[추정]` 일부만 보이거나 앞뒤 맥락으로 판단함
- `(→ ○○)` 음성 인식 오류의 추정 원문 / `(→ ?)` 원래 말을 추정할 수 없음
- `[시점 추정]` 스크립트가 덩어리 단위라 문장별 정확한 시점은 확인되지 않음
- `[화자 추정]` 스크립트의 화자 표기와 실제 화자가 다를 가능성이 있음
- 화면 녹화에는 터치 표시가 없다. 그래서 '들어온 방법'은 **화면 변화와 손 촬영을 함께 보고 판단**했으며, 직접 눌린 장면이 보이지 않으면 [추정]으로 남겼다.

## 4. 문제 후보 (템플릿 09 · 해석)

### U-01 · 해결 단계의 용어를 몰라 실제로 따라 하기 어려움

| 항목 | 내용 |
|---|---|
| 문제 | 해결 단계가 '연결부 너트', '패킹'처럼 부품 이름 위주로 안내되어, 부품을 모르는 사용자는 실제로 따라 하기 어렵다. |
| 관찰 근거 | E-04 (2:15): 단계 3 문구를 길게 눌러 '찾아보기' 메뉴를 띄우고 "패킹이 뭐죠"라고 말함. E-05 (2:17~2:33): 너트를 잘 모른다고 말하며 단계 3에 30초 머묾. |
| 사용자 영향 | 앱 밖에서 용어를 찾아봐야 하고, 해결 방법을 확인한 뒤에도 직접 조치하지 못하고 업체를 찾는 쪽으로 넘어간다 (E-07). |
| 원인 가설 | 단계 안내가 부품 이름과 동작 위주이고, 부품의 생김새와 위치를 보여주지 않는다. 함께 있는 일러스트도 아이콘 수준이라 실제 부품을 알아보기 어렵다. |
| 개선 가설 | 단계 3의 '너트'·'패킹'을 누르면 실제 사진과 위치 표시가 뜨도록 한다. |
| 재검증 기준 | 새 참여자가 힌트 없이 단계 3을 읽고 너트와 패킹이 어디 있는지 말할 수 있는가? |

> 참고: 앞서 정리한 다른 세션의 스크립트(01:37)에도 "텍스트로만 돼 있으면 잘 어려울 것 같아"라는 같은 취지의 발언이 있다.

### U-03 · 업체 목록 정보만으로 선택하기 어려움

| 항목 | 내용 |
|---|---|
| 문제 | 업체 카드에 평점, 리뷰 수, 후기 태그는 있지만 리뷰 내용과 가격이 없어 업체를 고르기 어렵다. |
| 관찰 근거 | E-09 (3:39~4:48, 70초 체류, "이걸로는 선택하기 좀 힘들 것 같습니다", "리뷰 개수는 보이는데 볼 수가 없어서"). 카드에는 '리뷰 132개'와 '연락을 빠르게 받아요 48', '친절해요 37', '견적 후기 많아요 21' 같은 태그가 있었다. |
| 사용자 영향 | 다른 서비스(당근)를 쓰겠다고 말했다. 전화가 부담스럽다고 했지만 다른 연락 방법이 없어 결국 '전화'를 눌렀다 (E-10). |
| 원인 가설 | 업체를 고를 때 필요한 정보(리뷰 내용, 가격대)가 화면에 없다. 출동 속도는 '24시간 출동해요' 태그로 일부만 드러난다. |
| 개선 가설 | 업체 카드에 '리뷰 한 줄 미리보기'를 추가하고, 전화 외에 '문자로 문의하기'를 둔다. |
| 재검증 기준 | 새 참여자가 힌트 없이 업체 하나를 고르고 그 이유를 말하는가? |

> 참고: 기술 검토 결과 네이버·카카오 로컬 API로는 리뷰·영업시간 데이터를 가져올 수 없다. 개선안을 정할 때 이 제약을 함께 검토해야 한다. 문자 문의는 이미 검토된 'sms: 링크로 내용 미리 채우기' 방식과 연결할 수 있다.

### 참고 · 관찰 메모

- **완료 시점**: 해결 단계를 확인한 뒤가 아니라 커뮤니티에 글을 등록한 직후에 완료를 선언했다 (E-12). 글을 쓰면서 "해결했어요"라고 말한 것으로 보아, 해결 사례를 공유하는 것까지를 과업의 끝으로 받아들였을 가능성이 있다.
- **글쓰기 필수 항목**: '어떤 이야기인가요?'가 필수인데 화면 맨 위에 있어, 제목·내용·태그를 다 쓴 뒤에도 '글 올리기'가 비활성이었다 (E-11). 참여자는 "사진이 필수입니까?"라고 물었다. 실제로 사진 칸에는 '선택 사항'이 표시되어 있었다. 비활성 이유를 사진으로 오해했을 가능성이 있다. [추정]
- **메시지 자동 작성**: 메시지 만들기 화면에 12초 머물고 '메시지 앱에서 보내기'까지 눌렀다. 부정적인 발언은 없었다 (E-07).
- **직접 입력 인식**: "싱크대 화분 수납장에 물이 셌어요"처럼 오타가 섞인 문장에서도 '싱크대 아래에서 물이 새요'를 예상 문제로 맞게 보여주었다 (E-02).

## 5. 확인 필요 목록

- [ ] **화자 표기**: 스크립트의 화자 표기와 실제 화자가 다를 수 있는 구간이 있다. 녹음을 다시 들어 확인한다.
  - 01:09 블록 끝 "하모스남자 망크대…": 참석자 2로 표기되어 있지만, 참여자가 입력 내용을 말한 것으로 보인다.
