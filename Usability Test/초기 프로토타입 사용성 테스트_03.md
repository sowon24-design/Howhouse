**02 검증할 범위와 질문**

연구 질문은 관찰할 행동을, 결정 질문은 결과를 보고 바꿀 것을 정한다.

**Core Feature**　문제 입력 → 문제 파악 → 유사 해결 사례 탐색 → 해결 방법 선택 

**사용자 목표**　자취 중 발생한 문제를 사용자가 스스로 서비스에 전달하고, 자신에게 적합한 해결 사례를 찾아 실제 해결 방법까지 선택할 수 있는가?

**연구 질문**　사용자가 별도의 조작 안내 없이 자신의 문제를 적절한 방식으로 입력하고, 문제를 확인한 뒤 유사한 해결 사례까지 스스로 찾아갈 수 있는가? 

**결정 질문**　사용자가 문제 입력부터 해결 사례 탐색까지 막히는 지점이 있다면, 문제 입력 방식·문제 파악·사례 탐색 중 어느 단계의 구조를 수정해야 하는가? 

**검증 가설**　사용자는 사진·음성·글 중 자신의 상황에 적합한 방식으로 문제를 설명하고, 서비스가 제시한 문제 정보를 확인한 후 자신과 유사한 해결 사례를 찾아 적절한 해결 방법을 선택할 수 있다.

**08 사후 질문과 사실 / 해석 분리**

과업이 끝난 뒤 기능 이해와 혼란을 묻는다. 답변을 유도하지 않는다.

**Q1 · 작동 이해**　진행자 별도 질문 없음. 과업 중 발언 → "어 이거 설명해주는건가?"

**Q2 · 막힌 순간**　진행자 별도 질문 없음. 과업 중 발언 → "어? 저 업체도 봐야하는데. 업체가 사라졌어요"

**연구자 해석 / 가설**　

1\) 사용자는 해결 방법 안내가 어떻게 작동하는지는 이해하지만, 내용을 이해하는 데에 있어 배경지식이 없어 어려워한다.  
2\) 사용자는 집주인에게 메시지를 보낸 이후 바로 업체 찾기로 연결되기를 기대한다.
