# 소원 담당: 분석 기능과 화면 연결

이 폴더는 소원의 프론트 작업 위치입니다. 최신 사용자 요청에 따라 수동 샘플 분석 함수·상태 알림·취소·검사를 추가했습니다. **현재 실행·연결 안내는 [INTEGRATION.md](./INTEGRATION.md)를 먼저 읽으세요.** 실제 LLM/API·서버·사진 분석은 미연결입니다. 최종 API 데이터 형식도 확정하지 않았습니다.

아래는 초기 세팅 당시의 요구와 자료 확인 기록입니다. 이후 공유된 예슬·연우 답변 및 최신 main과 달라진 부분은 INTEGRATION.md가 우선합니다. 특히 A04·A05는 최신 main에서 예슬이 구현했으므로 소원이 중복 구현하지 않습니다. 메시지 초기 본문은 대상별 문장을 순서대로 합치는 최신 연우 구현을 따릅니다. 당시 사례 수 57개와 미정 항목은 현재 데이터·결정 상태를 의미하지 않습니다.

## 역할과 향후 배치

| 담당자 | 범위 |
| --- | --- |
| 소원 | 글·사진 분석 흐름, 기존 사례 검색·적합성 판단, 필요한 경우 새 해결책 생성, 프롬프트·응답 검증·실제 API 연결, 분석 대기·실패·중단, A04·A05 |

추후 분석 화면, 서버를 호출하는 분석 클라이언트, API 없이 확인할 샘플, 담당 미리보기를 이 폴더에 둡니다. 세부 하위 폴더는 해당 작업 때 만듭니다. 서버 코드의 위치·구성은 미정입니다. 이 폴더에 프론트 코드를 둔다고 비밀 키가 보호되지는 않습니다.

입력과 결과를 주고받는 함수·콜백을 화면 이동과 분리합니다. 소원은 이동 목적지와 필요한 데이터를 명시하고, 실제 이동은 예슬이 연결합니다. 함수 이름과 데이터 구조는 아직 확정하지 않습니다.

## 최신 분석 요구사항 — 구현 전 기록

1. 사용자 글·사진으로 문제 상황을 파악합니다. 글만, 사진만, 글+사진을 받을 수 있습니다.
2. 준비된 사례에서 관련 사례를 찾고 증상·조건·조치가 적합한지 판단합니다.
3. 적합한 기존 사례가 있으면 그 사례의 원본 내용을 사용합니다. 사례 ID로 원본 데이터를 조회하는 방식을 우선 검토합니다.
4. 적합한 사례가 없고 정보가 충분할 때만 새 해결책을 생성합니다.
5. 분석 불가 또는 안전하게 안내할 수 없을 때는 실패 처리합니다.

**기존 사례가 없다는 이유만으로 실패 처리하지 않습니다.** 기존 사례를 선택했을 때 LLM이 원본을 불필요하게 다시 쓰거나 공동 시트를 수정하게 하지 않습니다. 번호·분류 등 관리/식별 데이터와 사용자에게 제공할 내용을 구분하며, 모든 열을 LLM 생성 항목으로 삼지 않습니다.

적합성 임계값, 시간 제한, 재시도 횟수, FAIL 조건은 미정입니다. 추가 정보 안내를 대화형 추가 질문 기능으로 확대하지 않습니다.

- 위 공동 시트가 현재 운영 기준인지, S~AB의 의미가 문서와 같은지 확인해 주세요. 실제 열·빈 값·검수 상태도 함께 확인해야 합니다.
- A열 번호가 정렬·행 이동·추가·삭제 후에도 유지되는 고유 ID인가요? ID 조회 실패와 잘못된 ID는 어떻게 처리하나요?
- 사례 조회·검색용 데이터를 앱 파일, 서버, 시트 조회 중 어디서 제공하나요? 갱신·접근 방식과 소원이 사용할 읽기 경로가 필요합니다.

- 기존 사례 결과와 생성 결과를 어떤 구분값과 데이터로 B02·B03에 전달할까요? 기존 사례는 ID로 원본을 가져오는 방식을 우선 검토해 주세요. 영상·문의 버튼 분기도 함께 맞춰야 합니다.
- 빈 값, 필수 항목 누락, 잘못된 ID, 원본 조회 실패에 대한 처리와 사용자 안내는 무엇인가요?

## 실행과 검사

팀 기준은 `.nvmrc`의 Node.js 24.15.0, `package.json`의 npm 11.12.1입니다. engines 허용 범위는 Node.js >=24.15.0 <25입니다. 아래 명령은 npm이 준비된 터미널에서 **저장소 루트**에서 실행합니다.

```powershell
npm ci
npm run dev
npm run build
npm run verify:foundations
```

미리보기 주소는 터미널에 표시됩니다. 기본은 `http://127.0.0.1:5173/#components`, 색상은 `/#colors`입니다. 종료는 실행한 터미널에서 Ctrl+C입니다. `build`는 TypeScript 검사와 배포용 파일 생성을 포함하며, `verify:foundations`는 공통 에셋·폰트를 검사합니다. 출시 화면·실제 분석 API 검증을 대신하지 않습니다.

초기 세팅에서 공통 컴포넌트·아이콘·스타일·DESIGN.md·CONTRACT.md·App.tsx·main.tsx·화면 이동·의존성 구성은 변경하지 않습니다. commit·push·PR도 별도 요청 전에는 진행하지 않습니다.
