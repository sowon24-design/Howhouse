# 무료 팀원 전용 시험 배포 준비

> 최신 결정: 앱을 사용하는 모든 시험 사용자가 별도 로그인 화면 없이 자동 임시 인증으로 분석하며, 시험 단계 분석 횟수 제한은 두지 않는다. 현재 구현/준비 상태는 [TRIAL_SERVER.md](TRIAL_SERVER.md)를 따른다. 아래 초대 계정/호출 제한 결정 대기 내용은 이전 제안이다.

2026-11-01 사용자 선택: 무료 팀원 전용 시험 배포 **준비**. 공개 배포/신규 결제/계정 생성은 하지 않는다.
현재 동작하는 배포는 PC + USB 폰 Chrome이다. 외부 서버 주소나 APK는 아직 없다.

## 제안 구성 (아직 선택·구축 전)

- 프론트: Render 무료 Static Site (기존 Vite dist).
- 분석 서버: Render 무료 Node Web Service.
- 로그인/영구 비용 기록·캐시: Supabase Free의 Auth/Postgres.
- 실제 OpenAI 사용료는 별도다. 서버가 무료여도 새 모델 호출은 과금된다.

이는 지금 코드를 그대로 올리는 배포 명령이 아니라 다음 단계 구현안이다.
Render 무료 서버는 15분 무활동 뒤 잠들고 로컬 파일은 재시작/배포 때 사라질 수 있다.
현재 .local 기반 한도를 그대로 두면 비용 기록이 초기화되므로 외부 서버에서 사용할 수 없다.
무료 DB는 보관/정지/사용량 제한이 있으며 영구 무중단 서비스로 약속하지 않는다.
공식 자료: [Render Free](https://render.com/docs/free), [Node 버전](https://render.com/docs/node-version),
[Supabase Free/요금](https://supabase.com/docs/guides/platform/billing-on-supabase),
[비활성 프로젝트 정지](https://supabase.com/kb/faqs/platform/free-project-pausing), [Auth](https://supabase.com/docs/guides/auth).
무료 한도와 조건은 실제 계정 생성 직전에 다시 확인한다. 자동 유료 전환/유료 옵션을 켜지 않는다.

## 외부 연결 전에 필요한 코드 작업

| 현재 로컬 구현 | 시험 서버에 필요한 변경 | 완료 기준 |
| --- | --- | --- |
| baseUrl/VITE_ANALYSIS_API_BASE_URL 설정 구현 (기본 PC 주소 유지) | 실제 HTTPS 서버 주소 적용 및 인증/허용 정책 연결. API 키는 서버 secret만 사용 | USB 없이 폰에서 접속, 혼합 콘텐츠 없음 |
| loopback Origin/Host + 임시 토큰 | 정확한 프론트 Origin + 팀원 인증 토큰 검증 + 허용 팀 계정 목록 | 비로그인/허용 외 계정은 모델 호출 전 거절 |
| .env 파일 | 호스팅 secret 설정에서 서버만 읽기 | 키가 번들/로그/응답/Git에 없음 |
| 파일 호출 기록 | DB 트랜잭션으로 사용자별/팀 전체 호출 예약 | 동시 요청/재시작/재배포 뒤에도 한도 유지 |
| 로컬 공용 답변 파일 | 사용자별 암호화 저장·조회 격리·만료·삭제 | 다른 팀원의 결과/입력 접근 불가 |
| process 내부 중복 요청 공유 | 배포 인스턴스 간 중복/진행 상태 정책 | 여러 인스턴스에서 한도 우회 불가 |
| PC에서만 실행 | PORT/바인딩/health 경로/배포 실행 entry 분리 | 무료 cold-start와 분석 90초 제한을 구분 |
| 입력 사진 원본 전송 | 처리 목적·외부 AI 전송·보관/삭제 안내 | 팀원이 동의한 개인정보 없는 테스트 자료만 사용 |

새 로그인은 현재 앱의 닉네임 설정과 별개의 시험 접속 제한이다. 예슬과 화면 위치를 맞춘다.
CORS나 프론트에 넣은 공유 비밀번호만으로 팀 전용을 보장하지 않는다.
개발 서버를 0.0.0.0/공개 터널로 노출하거나 HTTPS·인증 검사를 해제하지 않는다.
무료 서버의 잠들기 지연을 유료 자동 재시도로 해결하지 않는다. 서버 준비 확인 뒤 사용자 버튼으로 시작한다.

## 필요한 결정·계정

1. 소원이 관리하는 Render/Supabase 계정을 사용할지, 이미 있는 팀 서버를 사용할지 선택.
2. 시험에 허용할 팀원 계정과 운영/키 관리 담당 (실제 이메일은 공개 Git 문서에 기록하지 않음).
3. OpenAI 잔액 확인 뒤 팀 전체 신규 호출 한도·기간. 현재 로컬 개발 한도를 임의 확대하지 않음.
4. 시험 결과 보관/삭제 기간과 시험 종료일. 현재 로컬 7일 정책을 자동으로 다중 사용자 정책으로 확정하지 않음.

가입/약관 동의/보안 키 입력은 계정 소유자가 직접 처리한다. 키를 채팅이나 PR에 붙이지 않는다.
계정이 준비되면 인증/DB 어댑터부터 구현 → 무료 자동 검사 → 팀 계정 1개로 접속 확인 → 허용된 API 1회 → 팀 시험 순으로 진행한다.
위 선행 조건이 충족되기 전에는 '외부 배포 완료'로 보고하지 않는다.

## 다음 단계 검수

비로그인 차단, 타 사용자 격리, 한도 원자성, 재배포 후 한도 유지, 캐시 0회 호출,
취소/시간 초과/오프라인 입력 유지, 휴면 복귀, 금액 확인, 시험 종료 후 접근 차단을 검증한다.
Android APK/WebView 배포는 또 다른 검사이며 현재 USB Chrome 성공으로 대신하지 않는다.
