# 현재 분석 연결 — 2026-11-01

추가 검증·남은 작업은 [REMAINING.md](REMAINING.md), 폰 USB 준비는 [ANDROID_USB.md](ANDROID_USB.md).

사용자가 생성 결과 미정 항목의 결정·답변 재사용·AI 화면 통합을 승인한 뒤의 기준 문서다.
이전 단계 문서의 ‘생성 미연결’, ‘연우 합의 대기’, ‘샘플이 기본’ 설명을 대체한다.
현재 목표는 PC와 USB 폰 Chrome 시연이다. 외부 배포와 APK/WebView 검증은 다음 단계이며 완료한 것으로 간주하지 않는다.

## 화면과 모델 사용

| 화면 | 구현 동작 | 추가 유료 모델 호출 |
| --- | --- | --- |
| A01/B01 | 준비된 사례를 선택해 원본 조회 | 없음 |
| A02/A04 | 글/사진을 서버로 전송, 저장 답변 확인 → 없으면 기존 사례 판단과 필요한 경우 생성 | 새 입력의 유효한 답변이 없을 때 1회 |
| B02 | existing은 원본 ID 조회, generated는 메모리의 내용을 직접 표시 | 없음 |
| B03 | 기존/생성 결과의 문의 문장 합치기·선택·직접 편집·복사 | 없음 |
| A05 | 정보 부족/안전 안내 불가, 재입력 시 입력 보존 | 자동 호출 없음 |
| F02 | 단절 시 분석 취소, 연결 확인 뒤 분석은 A02 복귀 / 일반 화면은 유지한 상태로 복귀 | 없음 |
| D/E 및 기타 화면 | 기존 닉네임·설정·정보 화면 동작 유지 | 없음 |

LLM을 다른 화면마다 다시 호출하지 않는다. 문의 문장은 분석 응답에 포함한다.
기본은 실제 모드다. 무료 수동 샘플은 개발 도구에서 선택한다.
분석 결과 B02 뒤로/완료는 홈, B03 뒤로는 B02, 복사는 화면을 유지한다.
일반 화면은 F02 아래에서 마운트를 유지하므로 B03 편집 내용도 보존한다.
결과와 입력은 프론트 메모리에만 보관하며 새로고침/앱 종료로 사라진다.

## 확정한 생성 내용 계약

최종 성공은 두 종류뿐이다. `needs-generation` 중간 결과는 외부로 반환하지 않는다.

```ts
{ source: 'existing', caseId: '욕실·수도:1' }
// 또는
{ source: 'generated', solution: {
  title: string,
  description: string,
  supplies: string[],
  steps: { title: string; description: string }[],
  contacts: { landlord: string[]; company: string[] }
} }
```

위 solution은 서버 전송 형식이다. 프론트의 `toGeneratedSolution`이 B 화면용 번호·고정 레이블·빈 메타데이터를 붙인다.
제목/설명과 1~8개 단계는 필수, 빈 문자열/잘못된 타입/추가 필드는 거절한다.
준비물이 없으면 [], 필요하지 않은 문의 대상은 [], 대상별 문장은 순서대로 최대 4개다.
문장 배열이 비어 있으면 해당 문의 대상과 버튼을 숨긴다. 별도 최초 본문을 생성하지 않는다.
문의 문장은 증상과 점검 요청만 담으며 확인 안 된 원인·책임·비용을 확정하지 않는다.
이름·호수·주소·전화번호 등 개인정보를 문의 문장에 재기재하지 않도록 모델에 지시한다.
사진·영상 URL, 관리 번호, 배상 책임, 소요 시간은 모델 생성 대상에서 제외한다.
해당 B02 항목은 빈 값으로 숨기며 모델이 허위 정보를 채우게 하지 않는다.
생성 화면 식별자는 `generated:<requestId>`이며 기존 사례 조회 ID로 쓰지 않는다. 공동 CSV/시트를 수정하지 않는다.

기존 사례 판단 → 적합한 기존 사례가 없고 정보가 충분한 경우만 생성하는 순서를 한 요청의 지시문에 명시한다.
숫자 점수 기준이나 자동 재시도는 도입하지 않는다. 위험/정보 부족은 생성 대신 실패로 처리한다.
구조 검증은 서버와 프론트 양쪽에서 수행한다. 이는 모델 내용의 안전·정확성을 보증하지 않으며 실제 주거 사진 평가가 필요하다.

## 답변 재사용과 비용 보호

1. 사용자 글은 앞뒤 공백/NFC만 정규화한다. 전체 글과 순서가 같은 사진 원본 바이트·MIME가 모두 일치해야 재사용한다.
2. 모델·프롬프트/스키마 해시·분석 버전·사례 데이터 버전도 같아야 한다. 다른 증상·조건·사진을 유사도만으로 합치지 않는다.
3. ‘오늘/어제/내일/방금/지금’ 같은 시간 표현이 있으면 날짜도 키에 포함한다. 시간에 따른 상태 변화에는 새 입력/사진이 필요하다.
4. 성공하고 검증한 existing/generated만 저장한다. 실패/거절/취소된 요청의 늦은 응답은 저장하지 않는다.
5. 같은 요청이 동시에 오면 모델 요청 1개를 공유한다. 한 화면만 취소해도 다른 화면의 요청은 유지하며 마지막 대기자가 취소하면 상위 요청도 중단한다.
6. 저장 답변의 재사용 유효기간은 개발 PC 기준 7일, 최대 100개다. 서버를 재시작해도 유효한 답변은 재사용한다.
   만료된 답변은 반환하지 않으며 다음 저장 시 파일에서 정리한다. 7일 정각의 자동 파일 삭제 작업은 아니다.
7. 캐시를 먼저 확인하므로 개발 유료 호출 한도를 소진해도 유효한 저장 답변은 반환할 수 있다.
8. 사례 자료는 변동 사용자 글보다 앞쪽의 안정적인 프롬프트로 배치한다. 별도 유료 예열/긴 보관 옵션을 켜지 않는다.
   OpenAI 측 입력 캐시 할인은 적용 여부/토큰 보고를 확인해야 하며, 로컬 답변 재사용(모델 호출 0회)과 다르다.

원본 글·사진을 저장하지 않는다. 입력 비교 키는 HMAC이고 답변 파일은 AES-256-GCM으로 암호화한다.
`server/analysis/answers.local`, `answer-key.local`, 호출 기록은 Git에서 제외된다.
키 파일을 읽을 수 있는 로컬 계정으로부터 데이터를 숨기는 완전한 보호는 아니다.
현재는 소원 PC의 개발용 저장소다. 공개/다중 사용자 배포에는 사용자별 격리·인증·삭제/보관 정책이 추가로 필요하다.
암호화 키 없이 answers.local 파일을 복사해도 재사용할 수 없다. 키/캐시를 PR에 넣지 않는다.
`vite.config.ts`에서 Vite 기본 차단 목록을 유지하고 `**/server/**`, `**/*.local` 접근을 추가 차단한다.
서버 키/답변 파일을 public 폴더에 두지 않는다. 이 보안 설정은 프론트 의존성을 바꾸지 않는다.

## 오류와 F02

기존 `getAnalysisFailureKind`를 유지한다. 연결 불가, 서버 HTTP/상위 API 오류, 응답 형식 오류를 구분한다.
`server-busy`는 다른 분석 진행, `budget-limit`은 실제 개발 호출 한도다.
모델 자체 거절은 `model-refusal`로 A05에 연결하며 서버 오류로 오인하지 않는다.
지원하지 않는/빈/4MiB 초과 사진과 6000자 초과 글은 전송 전에 거절하며 서버에서도 다시 검사한다.
브라우저 offline 이벤트 또는 서버 연결 불가 시 F02에서 확인한다. 연결 불가만으로 물리적인 인터넷 단절을 단정하지 않는다.
`checkAnalysisConnection({verifyUpstream:true})`은 `/health?upstream=1`을 호출한다.
서버는 키 없이 OpenAI `/v1/models`에 한 번 접속하고, 예상된 401 등으로 네트워크 경로만 확인한다.
모델을 호출하거나 토큰을 생성하지 않으며 사용자 입력·API 키를 보내지 않는다. 5초 제한은 이 연결 확인용이다.
이 확인은 계정 잔액/실제 분석 성공을 보증하지 않는다. 자동 분석·자동 재시도·온라인 이벤트에 의한 자동 복귀는 없다.
연결 확인 결과가 유효한 경우에만 F02에서 복귀한다. 분석은 사용자가 A02 버튼을 눌러야 새로 시작한다.
F02 진입 시 복귀 주소를 고정하고 hashchange/popstate를 라우터보다 먼저 처리한다.
복구 중 주소가 홈으로 바뀌어 원래 화면을 해제하거나 입력을 지우는 것을 막는다.
새로고침/탭 종료로 이미 잃은 메모리 입력을 복원하는 기능은 아니다.
사용자 승인에 따라 프론트 전체 요청과 서버 모델 작업은 각각 최대 90초로 제한한다. `analysis-timeout`은 A05로 안내하고 재입력 시 글·사진을 유지한다. 자동 재시도는 없으며 늦게 도착한 결과는 반영·저장하지 않는다. 서버의 시간 제한은 모델 작업 시작 시점부터이며 프론트 제한은 세션/업로드/응답을 포함하므로 먼저 종료될 수 있다.
서버 작업 중단은 최선을 다해 시도하며 이미 발생한 비용 중단/환불은 보장하지 않는다.

## 실행과 검사

저장소 루트에서 두 PowerShell 창으로 실행한다.

```powershell
node server/analysis/server.mjs
npm run dev -- --strictPort
```

두 줄은 각각 별도 창에서 실행한다. 화면은 http://127.0.0.1:5173/#problem, 서버는 8787, 종료는 각 창의 Ctrl+C.
키는 기존 `server/analysis/.env`에 그대로 두고 VITE_ 변수나 프론트에 옮기지 않는다.
추가 라이브러리/유료 DB/배포 서비스는 설치·가입하지 않았다.
초기 3회 한도는 사용자 요청의 추가 구현/테스트에 맞춰 누적 총 10회로 조정했다.
서버 재시작으로 횟수가 초기화되지 않는다. `node server/analysis/server.mjs --max-calls=3`처럼 더 낮출 수 있다.
명령줄에서는 최대 10회까지만 허용한다. 횟수 제한은 정확한 달러 예산을 보증하지 않으며 실제 청구는 OpenAI Usage에서 확인한다.

```powershell
node --test src/analysis/*.test.mjs server/analysis/*.test.mjs
npm run build
npm run verify:foundations
```

무료 샘플: 개발 도구 → 무료 샘플 모드 → 기존/생성 결과 선택 → 도구 접기 → 분석 → 도구의 성공/실패 재현.
실제 분석은 자동으로 결과로 넘어간다. 샘플을 실제 API 완료로 보고하지 않는다.

## 파일과 팀 영향

- `solution.ts`, `http-client.ts`, `client.ts`, `samples.ts`, `index.ts`: 생성 계약·검증·B 화면 어댑터·샘플/실제 함수.
- `AnalysisResultFlow.tsx`, `ConnectivityBoundary.tsx`, `ProblemPreview.tsx`: 기존 B02/B03/A/F 화면을 재사용한 연결.
- `ProblemScreen.tsx`, `AnalysisScreen.tsx`: 실제 요청 오류 안내, 안전상 분석 불가 안내, 보장하지 않는 ‘최대 1분’ 문구 제거. 디자인/스타일은 유지한다.
- `App.tsx`: 전체 분석 결과를 메모리에 보관하고 분석 결과 경로로 이동. 예슬 쪽 통합 시 이 부분을 공유한다.
- `src/solutions/B02.tsx`, `b02.css`: 표시하지 않는 사례 ID/분류 필드를 필수 입력에서 제외하고, 사진이 없는 결과에서 헤더·제목이 겹치지 않도록 기존 헤더를 문서 흐름에 둔다. 사진이 있는 기존 사례의 배치는 유지한다.
- `server/analysis/matcher.mjs`: 기존 사례 우선 선택과 조건부 생성의 단일 요청/엄격한 응답 검증.
- `answer-cache.mjs`, `service.mjs`: 암호화 저장·무효화·중복 호출 합치기·취소·비용 보호.
- `connectivity.mjs`, `server.mjs`: 무료 연결 확인과 실제 서버 경로.
- `deadline.ts`와 각 `.test.mjs`: 90초 종료·취소·늦은 결과 차단 및 문의 문장 전달을 실제 OpenAI 없이 검증.
- `vite.config.ts`: 서버 폴더/로컬 답변 파일의 개발 웹 서버 노출 차단. 공통 실행 보안을 위한 추가 설정이며 포트/라이브러리는 바꾸지 않는다.

공통 컴포넌트·스타일·디자인 문서·의존성은 변경하지 않았다. commit/push/PR은 별도 요청 전까지 하지 않는다.
이전 문서 변경 필요: ‘기존 사례 없으면 실패’와 샘플/미연결 설명은 현재 흐름에 맞춰 공통 문서에서 나중에 정리해야 한다.
Android 실기기에서는 localhost가 휴대폰 자신이므로 서버 주소/HTTPS/인증·배포는 별도 연결·검증이 필요하다.
