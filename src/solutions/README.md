## 공동 시트 실제 확인

[기능정의에 지정된 공동 사례 시트](https://docs.google.com/spreadsheets/d/1UIo0I-zIWh8y1aIkGIBD6Q0YrpeR86JxVrCtXDWJ-YU/edit)를 연결 도구로 읽었다. 접근 가능하다.

- 실제 탭: `욕실·수도`, `난방·전기`, `가전`, `해충·곰팡이`, `책임 판단 기준`.
- 확인 범위: 욕실·수도 `A1:AB3`, 다른 사례 탭 각각 `A1:AB2`, 책임 판단 기준 `A1:D3`. 전체 데이터의 완전성·고유 ID 중복·빈 값 분포를 전수 검증한 것은 아니다.
- A~R 실제 헤더: 번호 / 분류 / 사례(증상) / 예상 원인(AI 추측) / 해결 제목 / 준비물 / 총 예상 소요 시간 / 배상책임 주체 / 판단 참고 / 1단계 제목·설명 / 2단계 제목·설명 / 3단계 제목·설명 / 4단계 제목·설명 / 유튜브 링크 첨부.
- 읽은 네 사례 탭의 제목 행은 S~AB가 비어 있고, 데이터 행에는 S 집주인·T 전문업체·U~X 집주인용 문장·Y~AB 전문 업체용 문장이 있다. 열의 의미는 기능정의와 대조했다. 헤더를 새로 쓰지 않았다.
- 읽은 첫 사례 번호는 각각 1, 15, 29, 44이다. A의 번호를 최종 고유 ID로 확정하지 않는다.
- 시트는 이미 작성된 사례·단계·문장을 포함한다. 모든 열을 LLM이 생성하거나 사례를 열 때마다 재생성한다고 가정하지 않는다.
- 최초 메시지 본문은 별도 제공 대상이다. 선택 문장 U~AB를 임의로 이어 붙여 최초 본문으로 만들지 않는다.
- 문의 버튼은 책임 주체 H가 아닌 S/T에 따른다. 집주인+전문 업체 / 집주인만 / 둘 다 없음의 분기가 정의돼 있다. T만 있는 경우와 공백 판정은 확인 전 구현하지 않는다.
- 욕실→화장실, 수도→수도·수질, 전기→전기·조명은 기능정의를 따른다. 해충·곰팡이의 사례별 분리는 자료가 필요하다.

## 최신 요구와 문서 변경 필요 목록

1. 기능정의 4.7·4.8·Q07·검증 항목은 직접 입력 경로와 생성 결과를 연결해 설명한다. 최신 요청은 기존 사례 우선 검색 후, 적합한 사례가 없고 정보가 충분할 때만 생성한다. 결과의 출처와 화면 진입 경로를 분리하는 내용으로 추후 동기화해야 한다.
2. 직접 입력 후 기존 사례가 선택됐을 때 영상·문의 표시를 소원·예슬과 합의해야 한다. 생성 결과의 영상 영역과 바로 아래 구분선 숨김은 유지한다. 입력 경로만으로 생성 결과라고 판단하지 않는다.
3. AGENTS.md·src/README.md 등의 화면 담당 미정 문구는 이번 역할 배정과 다르다. 루트 README의 병합 전 브랜치 안내도 현재 main 병합 상태와 다르다. 공통 문서 수정은 이번 범위 밖이다.
4. 기능정의의 단계 정렬 설명은 앱 영역 기준 X=24px, 마지막 카드 끝 여백, 직접 스크롤·터치·화살표 상태 동기화까지 최신 요구로 보완할 필요가 있다.

## 이후 화면별 결정과 작업 순서

1. 데이터·이동·샘플·독립 미리보기 계약 합의 → 연우가 다음 단계 지시.
2. B01부터 한 화면씩: 해당 Figma 재조회, 기능정의와 미정 동작 확인, 공통/화면 전용 요소 구분, 구현·직접 확인.
3. B02 본문·단계 카드 → 책임 설명/평가·의견 UI. 실제 의견 수집은 별도 외부 연결 작업이다.
4. B03 수신자·최초 본문·문장 선택·직접 편집·복사와 B05-1 포함 상태.
5. 같은 합의 샘플로 데이터 연결 → 예슬 통합 전에 실행법·완료/미완료·오류·데이터·콜백 전달.

각 화면 전에는 빈 값·초기 선택·취소·복귀를 확인한다. 판단 참고 초기 접힘, 첫 단계 이전 버튼, 평가의 상호 배타성·보존도 미정이다.

문의 구현 전에는 본문 출처, 선택 문장 추가/교체/순서, 직접 편집과 병합, 취소·바깥 닫기·탭 전환 보존, 복사 실패와 재클릭 타이머를 확인한다. 문자 앱 자동 실행·메시지 전송은 추가하지 않는다.

의견 구현 전에는 완료 안내 문구·닫힘, 공백/길이, 중복 제출, 실제 수집처·API·처리 담당을 확인한다. 완료 안내 UI와 실제 저장 성공을 구분하며, 미연결이면 미연결이라고 표시한다.
