## 현재 구현과 미연결 항목

루트에서 npm ci, npm run dev를 실행하고 터미널 주소의 아래 경로를 엽니다.

| 경로 | 구현 | 미연결·보류 |
| --- | --- | --- |
| /#components | 공통 상태·동작 예제 | 실제 화면 정책과 구분 |
| /#home | A01, 입력·마이·카테고리 B01→B02→B03 | 실제 인기 사례·월, 분석 결과 연결 |
| /#problem | A02 입력·사진, A04 대기·A05 실패 | 성공→B02, 실제 분석·카메라 |
| /#onboarding | E01~E04·닉네임→홈 | 프로필·완료·동의 저장, 키보드 위 CTA |
| /#my | D01·D02·D08~D12, 링크·복사 | AI 활용 정보 상세, 최종 운영 문구 |
| /#system | F01·F02 수동 미리보기 | 자동 시작·통신 판정·복구 |

- 소개 단계만 localStorage에 저장합니다. 닉네임은 메모리이며 새로고침 시 초기화됩니다. E04에서 E03으로 돌아가면 약관 체크를 다시 선택합니다.
- 사진은 한 번에 한 장, 최대 5장입니다. 문제 초안은 입력 복귀 시 유지, 홈 이동·새로고침 시 초기화합니다. 앱 종료·Android Back은 후속 검증 대상입니다.
- 분석은 테스트 상태 전환입니다. 로컬 취소·늦은 응답 무시는 실제 서버 취소 완료를 의미하지 않습니다.
- D12는 test.email.com을 복사하고 알림은 총 1.5초입니다. 정책 본문은 임시이며 Notion 공개 접근 여부는 별도 확인합니다.
- E02 dissolve는 각각 1000ms, 시작은 이미지/제목/본문 0/500/1000ms입니다.
- 화면 결합 뒤 닉네임 기기 저장·설정 완료 분기·테스트 초기화를 진행합니다. 문제 초안 영구 저장은 하지 않습니다.

## main PR에 포함할 파일

폴더만 복사하면 의존성이 빠집니다. 아래 변경을 함께 검토합니다. 이 안내 작성은 commit·push·병합을 의미하지 않습니다.

- src/app-screens/ 전체: 화면·CSS·JSON·SVG·PNG·README
- src/App.tsx: 미리보기 경로, 닉네임·문제 초안 메모리 연결
- package.json 및 package-lock.json: 사진 재배치 등에 사용하는 motion 의존성
- src/components/ui/Dialogs.tsx: 약관 전문 재사용용 Dialog export
- src/components/ui/ui.css: CTA pressed 색 즉시 적용
- DESIGN.md 및 src/components/CONTRACT.md: 이미 승인된 눌림 효과·Dialog 규칙
- README.md, src/README.md, AGENTS.md: 실행·분업·통합 안내

docs/화면별_기능정의.md에는 이전 작업의 로컬 수정분이 이미 있습니다. 사용자 결정대로 기능정의는 다른 브랜치에서 정리하므로 **이번 PR에서는 제외**합니다. 기존 수정은 삭제하지 않습니다. 일괄 git add . 대신 위 파일을 명시적으로 선택하고 staged diff를 확인하세요. 다른 브랜치 작업 전에도 기능정의 수정분을 별도로 보존하세요.

연우·소원은 main 반영 후 자기 작업을 보존하고 최신 main을 담당 브랜치에 병합합니다. 공유 App.tsx·package 파일을 한쪽 것으로 통째로 덮어쓰지 말고 양쪽 기능·의존성을 유지합니다.

## 2026-10-31 사용자 합의

이 절은 기존 기능정의와 차이가 있는 최신 합의 기록이다. 공통 문서 본문은 이번 준비 단계에서 수정하지 않았다.

- 앱 입력: `analysisUserText: string`, `analysisUserPhotos: File[]`(최대 5개).
- 서버 전달: FormData의 같은 이름 필드. 사진 필드는 파일마다 반복 추가. 파일 제한과 API 주소·응답·취소 형식은 소원과 최종 확인한다.
- 예슬이 메모리에서 입력 원본을 관리하고 요청 시점의 값을 분석 기능에 전달한다.
- 실패 후 복귀, 분석 중 뒤로·Android Back, A05 ‘다시 문제 알려주기’: 입력 화면으로 돌아가 글·사진 유지.
- 홈 이동·앱 종료·새로고침: 문제 글·사진 초기화. 초안을 영구 저장하지 않는다.
- 위 초기화는 **문제 입력 초안**에만 적용한다. 약관 동의·닉네임·소개 이어보기까지 초기화하는 규칙이 아니다.
- A05 재입력 복귀는 즉시 재분석하지 않는다. 사용자가 분석 버튼을 눌러 새 요청을 시작한다.
- 분석 중 X: 분석 취소 후 홈으로 이동하고 입력 초기화.
- 모든 분석 화면 이탈: 요청 취소·후속 작업 및 자동 재시도 중단. 이전 요청/취소 요청의 늦은 결과는 이동·상태 변경에 사용하지 않는다.
- 요청 ID와 취소 전달은 소원과 맞춘다. 연결 단절 시 취소 보장이나 이미 처리한 비용 취소를 약속하지 않는다.
- 기존 사례 우선 검색→적합한 사례면 원본 사용→없고 정보가 충분할 때만 생성. 사례 없음 자체는 실패가 아니다.
- 오프라인 F02와 분석 실패 A05를 구분한다. 분석 중 오프라인 복구 시 새 분석을 자동 중복 요청하지 않는다. 기존 요청 상태 확인 불가 시 중단 처리; 복구 후 정확한 표시 화면은 소원과 맞춘다.
- API 키는 서버에서 관리하고 프론트/VITE_ 변수·GitHub·로그에 넣지 않는다.

- 기본 주소 `/` 또는 `/#`는 설정 완료 시 홈, 미완료 시 온보딩으로 진입한다. 소개 중간 진행 위치는 기존 이어보기 규칙을 유지한다. 명시적인 #home/#onboarding/#components 등은 개발 미리보기 주소로 유지한다. F01 자동 초기화·F02 네트워크 연결은 별도 단계다.
- 홈/온보딩 하단 개발용 안내·테스트 도구 → '테스트 초기화 · 처음부터 시작': 닉네임·설정 완료·소개 진행 위치와 현재 입력 초안을 지우고 환영 화면으로 이동한다. 다른 저장 항목은 삭제하지 않는다.
- 저장 거부 시 실행 중 메모리 값은 유지하고 홈 개발용 도구에 실패를 표시한다. 손상된 저장값은 미완료로 취급한다.
- 문제 글·사진은 저장하지 않는다. 홈 이동·새로고침 시 초기화, 분석 실패·재입력 시 메모리 보존 규칙을 유지한다.
- 같은 브라우저의 같은 origin에서만 공유한다. localhost, 127.0.0.1, Wi-Fi IP 및 다른 포트는 저장 공간이 다르다. Android 저장 유지·키보드 CTA는 후속 검증 대상이다.
- 검증: build, profile-storage.test.mjs, 브라우저 기본 주소 미완료→온보딩/완료→홈, 재접속 닉네임 유지, 초기화 후 환영 화면 확인. 테스트 프로필은 초기화해 두었다. API·Android·push 없음.
- 소원 담당 src/analysis는 수정하지 않고 createSampleAnalysisClient를 사용한다. 글·사진은 App 메모리에서 보관하고 분석 모듈에는 analysisUserText / analysisUserPhotos로 전달한다.
- A02 시작 → running A04. 개발용 안내·테스트 도구의 성공 버튼 → 기존 사례 욕실·수도:1의 B02, 실패 버튼 → A05. 실제 API 호출이나 입력 내용에 따른 사례 검색은 하지 않는다.
- 분석 결과로 진입한 B02는 뒤로·완료 모두 홈이다. 카테고리 경유 B02의 뒤로는 B01, 인기 문제 경유는 홈이다.
- A04 뒤로는 요청을 취소하고 A02로 복귀한다. A05 다시 문제 알려주기도 A02 복귀이며 글·사진을 유지하고 자동 재분석하지 않는다. X는 취소 후 홈으로 이동하며 입력을 초기화한다. 화면 이탈 시 요청을 정리하고 취소·이전 응답은 현재 화면에 반영하지 않는다.
- 실행: npm run dev -- --port 5174 → http://127.0.0.1:5174/#problem. 입력 후 CTA를 누르고 하단 개발용 안내·테스트 도구에서 성공·실패를 선택한다. 취소 후 응답 재현 버튼으로 입력 화면 유지도 확인할 수 있다.
- HTTP Wi-Fi 주소의 randomUUID 호환성 수정은 사용자 결정으로 보류한다. localhost로 확인하고 Android 연결 시 실제 실행 환경을 검증한다.
- 생성 결과 초안, 실제 API, F02 자동 복구, 영구 저장, Android Back은 이번 범위 밖이다. 닉네임 기기 저장·최초 진입 분기·테스트 초기화는 전체 연결 확인 후 별도 단계로 진행한다.
- 브라우저 확인: 텍스트 입력→A04→실패→입력 보존, 취소 후 샘플 응답 무시, 성공→B02→뒤로 홈. 사진 파일 보존은 같은 메모리 상태를 재사용하며 실제 파일 선택 회귀 검증은 별도 확인 항목이다.

## Android 사진 연결 (2026-10-31)
- `@capacitor/camera` 8.2.6: A02에서 시스템 카메라와 사진 선택기를 호출한다. B 화면/분석 모듈은 수정하지 않는다.
- Android 사진 선택은 남은 장수를 limit으로 전달한다. 1장 남으면 단일 선택. Android 13+ 시스템 선택기에서 선택 개수 제한을 지원한다. 구형 선택기가 초과 결과를 반환하면 일부만 잘라 넣지 않고 재선택 안내를 표시한다. 웹은 기존 1장 선택을 유지한다.
