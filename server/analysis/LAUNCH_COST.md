# 공개 출시 비용 보호 — 2026-11-06

## 확정 정책과 실제 상태

- 사용자 결정: OpenAI 월 예산 $10, 임시 사용자 ID별 한국 시간 하루 신규 분석 5회.
- OpenAI Default project에서 월 $10 및 Enforce a hard limit을 켜고 Limit enforced 표시를 확인했다. 모든 키가 같은 프로젝트를 공유하면 그 호출도 같은 한도에 포함된다. 키 값은 읽거나 변경하지 않았다.
- OpenAI 지출 반영은 즉시가 아니어서 소액 초과 가능성이 있다. 이는 청구 금액의 절대 보증이 아니다. 공식 안내: https://developers.openai.com/api/docs/guides/spend-limits
- 아래 DB 정책과 예약 함수는 로컬 구현·격리 SQL 검사까지 완료했고 실제 Supabase 적용 및 서버 배포는 아직 하지 않았다.

## 호출 흐름

1. 입력·인증을 검증한다. 일치하는 사용자별 저장 답변은 먼저 반환한다.
2. 동일 사용자·동일 입력의 진행 중 요청은 합친다. 새 모델 호출만 DB 예약 함수를 호출한다.
3. DB 트랜잭션 잠금 안에서 사용자별 한국 날짜와 기존 기록, 전체 동시 예약을 검사한 뒤 호출 기록을 삽입한다. 앱·서버 재시작으로 카운터가 초기화되지 않는다.
4. 서버만 OpenAI를 호출한다. 자동 재시도는 하지 않는다.
5. 실패·취소도 비용이 발생했을 수 있어 예약 횟수를 자동 환불하지 않는다. 잘못된 입력·한도 거절·저장 답변 재사용은 신규 예약을 만들지 않는다.

## 정책 및 운영

- `howhouse_analysis_policy.daily_user_calls=5`: 한국 자정에 새 날짜로 계산한다. 원본 글·사진을 신규 저장하지 않는다.
- `max_concurrent_calls=3`: 여러 서버의 예약을 합산한다. 사용자 화면의 분석 제한은 기존 90초이며, 서버 중단 뒤 남은 예약은 120초 임대 기간 후 동시 예약 계산에서 제외한다. 실제 제공업체 작업·비용 중단을 보장하지 않는다.
- `new_calls_enabled=false`: 신규 모델 예약을 중단한다. 유효한 저장 답변 조회와 평가·의견 저장은 별도 기능이다.
- 새 RPC는 서비스 전용이며 일반 앱 사용자는 정책 조회·수정과 직접 예약이 불가능하다.
- `remainingCalls:null`은 미리 계산한 숫자를 제공하지 않는다는 뜻이다. 더 이상 무제한 허용을 의미하지 않는다. 최종 허용 여부는 DB가 판단한다.
- 임시 ID는 삭제·재설치로 재생성 가능하다. 사람 단위 제한을 보장하지 않는다. 월 프로젝트 지출 한도는 이러한 ID 변경에도 적용되지만, 공개 출시 전 앱 진위 확인 등 추가 남용 대응을 검토해야 한다.
- OpenAI의 지출·크레딧 관련 429는 `budget-limit`, 요청 속도 초과는 `server-busy`로 구분한다. 원문 메시지·키는 앱에 반환하지 않는다.

## 적용 순서와 검증

1. `launch-quota.sql` 검토 및 적용 승인. 기존 정책이 있으면 자동 덮어쓰지 않는다.
2. Supabase에 적용 후 5회·3개 예약·신규 허용 값 및 RLS·RPC 권한 확인.
3. 검토된 서버 코드 배포. DB 함수가 없거나 읽기 실패 시 유료 분석을 허용하지 않는다.
4. 유료 모델 호출 없이 DB 예약·거절·한국 날짜·권한을 시험한다. 실제 모델·최종 APK 검사는 별도 수행한다.

최신 main bdf3707 기준 전체 160개 검사(skip 0), build 및 verify:foundations 통과. SQL 검사는 별도 PGlite 모듈을 사용했고 프로젝트 의존성을 추가하지 않았다. 다중 연결 실환경 잠금 경쟁과 운영 적용 여부는 별도 확인이 필요하다.
