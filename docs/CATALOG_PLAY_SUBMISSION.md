## 제출 순서

1. 콘텐츠 원본 사용 권리, 문의 메일 처리 조건, 이전 데이터 권리 행사 경로, 정책 시행일 확정.
2. 개인정보·약관 웹 본문 공개 및 앱/스토어와 버전 일치 확인. 준비 명령: `node scripts/prepare-catalog-policies.mjs`. 생성 HTML은 검토용이며 아직 게시하지 않음.
3. 공식 앱 아이콘 512×512, 대표 이미지 1024×500, 실제 앱 스크린샷 준비. AI 분석 화면·가짜 인기 통계를 이미지와 설명에 넣지 않음. 현재 개발 화면을 최종 출시 스크린샷으로 확정하지 않음.
4. 새 앱 실기기 확인 후 `release-approval.json`의 확인 완료 항목만 갱신. 테스트를 나중에 한다는 요청을 통과로 간주하지 않음.
5. 사용자가 기존 AAB/APK 업로드가 없음을 확인했다. 첫 업로드는 package ID `com.howhouse.app`, versionCode `1`, versionName `1.0`. 기준은 `src/catalog/app-release.json`. QA용 `.catalogqa` APK는 제출하지 않음. 이후 업데이트는 기존 코드보다 증가시킴.
6. 기존 업로드 키로 서명한 출시 AAB 생성. 키·비밀번호는 로컬/서버 비밀 저장만 사용하고 채팅·Git·VITE 설정에 넣지 않음. Play App Signing 등록 및 인증서 일치 확인.
7. 내부 검토 후 비공개 테스트 트랙 제출. Console에 필요한 콘텐츠 설문·데이터 보안·심사용 접근 안내·국가/배포 대상 완료.
8. 계정에 요구되는 비공개 테스트와 프로덕션 액세스 신청 후 일반 공개 출시 심사 제출. 과거 확인한 계정은 이 절차가 필요하므로 테스트 없이 공개 제출 가능하다고 보고하지 않음.
