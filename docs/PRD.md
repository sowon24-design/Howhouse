## 1. 서비스 정의와 목표

**한 줄 정의:** 자취생 생활문제 해결 서비스.

자취방 생활문제를 처음 겪는 대학생이 비슷한 실제 해결 사례를 바탕으로 문제의 심각도와 다음 행동을 스스로 판단하도록 돕습니다. 누수처럼 긴급한 상황에서는 판단 단계를 줄이고 즉시 실행할 임시조치와 연락 행동으로 연결합니다.

원문 목표는 학기 안에 iOS 앱으로 출시 가능한 범위를 완성하는 것입니다. 출시 일정과 완료 기준은 팀이 확인합니다.

## 2. 문제 정의와 배경

자취 초보 대학생은 누수·악취·해충·보일러 고장 등을 발견해도 검색 결과의 원인 후보가 너무 많아 무엇부터 확인할지 모릅니다. 해결책 자체뿐 아니라 현재 상황이 얼마나 심각한지, 지금 무엇을 해야 하는지 알고 싶어 합니다.

원문은 책임 소재의 불확실성보다 불편의 심각도, 일정·방문 전 정리 부담, 낯선 사람을 집에 들이는 부담이 문제 해결을 미루는 주요 원인이라고 설명합니다.

### 원문에 기재된 조사 배경 — 근거 확인 필요

- 대학교 UX 수업 캡스톤 프로젝트로 자취 경력 3년 이내 대학생을 인터뷰·설문했습니다.
- 150개 인사이트를 어피니티 다이어그램으로 묶어 정보 탐색·타인 의존·미루기의 세 테마를 도출했습니다.
- 사용자 투표와 로파이 롤플레잉 검증을 거쳐 해결사례 도서관과 SOS 모드를 우선 범위로 정했습니다.
- **팀 확인:** 조사 자료 링크, 참여자 수, 진행 시점, 검증 결과를 연결해야 합니다. 이 문서에는 해당 근거가 첨부되어 있지 않습니다.

## 3. 대상 사용자

- 주 사용자: 자취 생활문제를 처음 겪는 대학생.
- 조사 대상 범위: 자취 경력 3년 이내 대학생(원문 기준).
- 사용 기기: iOS 앱.
- 카테고리: 라이프스타일 / 일상.

### 원문 페르소나: 김서윤

서울 동작구 상도동의 다세대주택 3층 원룸에 사는 22세 대학생으로, 자취 6개월 차입니다. 검색·지도·카카오톡에는 익숙하지만 수리와 시설 지식은 거의 없습니다. 평일 낮에는 수업으로 집을 비우고, 방문 일정 조율과 낯선 사람의 방문을 부담스러워합니다. 집주인에게 연락하기 전 문제의 범위를 판단하고 스스로 적절히 대응하고 싶어 합니다.

> 페르소나의 나이·거주지·주거 형태는 원문 사례이며 전체 사용자의 필수 조건이 아닙니다. 조사 기반인지 예시 설정인지 팀 확인이 필요합니다.

## 4. 핵심 기능과 범위

| 기능 | 사용자 행동과 제공 내용 |
| --- | --- |
| 해결사례 도서관 | 생활공간·증상을 선택하거나 사진·음성·텍스트로 문제를 입력하고, 유사한 자취생 사례와 순서형 해결 단계를 확인합니다. |
| SOS 모드 | 음성 호출 또는 앱의 긴급 진입점으로 접근합니다. 사진 기반 상황 확인 후 물 확산 방지 등 임시조치부터 밸브 차단·집주인 연락까지 순서대로 안내합니다. |
| 연락 메시지 초안 | 연락이 필요한 상황에서 메시지 초안을 제공하고 사용자가 직접 검토·수정·전송합니다. |

### 차별점

일반 검색이나 커뮤니티처럼 정보를 나열하는 데서 그치지 않고, 유사 사례를 통해 문제의 심각도를 가늠하고 다음 행동을 선택하게 돕습니다. 일반 상황은 경험 탐색 중심, 긴급 상황은 즉시 행동 중심으로 흐름을 구분합니다.

### 원문에서 제외한 범위

- 수리업체 직접 예약·중개.
- 비용 또는 법적 책임의 확정 판단.
- 긴급 상황을 과소 안내하는 진단·보장. 서비스 범위는 행동 안내와 기록 지원으로 제한합니다.

> 입력 방식별 구현 범위, 음성 호출 방식, 사례 확보 방식은 원문에 구체화되어 있지 않으므로 별도 합의가 필요합니다.

## 5. 사용자 시나리오

### 일반 상황: 욕실 악취

1. 사용자가 욕실 악취를 발견하고 사례 모음에서 욕실과 냄새·배수구를 선택합니다.
2. 유사 사례를 살펴보며 배수구 이물질이나 트랩 문제가 원인 후보임을 확인합니다.
3. 자신의 배수구 사진을 촬영하여 상태를 다시 확인합니다.
4. 원문 사례의 해결 단계를 따라 조치한 뒤 냄새가 줄었는지 확인합니다.
5. 문제가 해결되지 않으면 집주인 연락으로 이어집니다.

### 긴급 상황: 싱크대 아래 누수

1. 사용자가 누수를 발견하고 SOS 모드를 열어 사진을 촬영합니다.
2. 서비스가 물 확산 방지를 위한 임시조치를 안내합니다.
3. 차단 밸브 위치 확인과 잠금 단계를 안내합니다.
4. 집주인에게 보낼 메시지 초안을 사용자가 수정하고 직접 전송합니다.

> 위 내용은 제품 사용 흐름의 예시입니다. 실제 안전 안내 문구와 상황별 안내 순서는 검증 후 확정해야 합니다.

## 6. 성공 기준

원문이 제시한 성공 방향은 학기 내 iOS 앱 출시 요건 충족, 일반 문제에서 유사 사례를 찾아 다음 행동 선택, 긴급 문제에서 임시조치부터 연락까지 수행하는 것입니다.

**원문에는 목표 수치·표본 수·측정 기한이 없습니다. 아래 측정 정의는 검토용 제안이며, 목표는 팀 합의 전까지 미정입니다.**

| 성공 기준 / 지표 | 측정 방법 제안 | 목표 / 기한 |
| --- | --- | --- |
| 일반 문제 과업 완료 | 유사 사례를 찾아 다음 행동을 선택한 참여자 수 / 일반 문제 과업 참여자 수 | 미정 |
| 사례 열람 비율 | 사례를 열람한 사용자 수 / 사례 모음에서 문제 탐색을 시작한 사용자 수 | 미정 |
| 해결 단계 확인 비율 | 해결 단계를 확인한 사용자 수 / 사례 모음에서 문제 탐색을 시작한 사용자 수 | 미정 |
| SOS 첫 조치 확인 비율 | 첫 조치를 확인한 사용자 수 / SOS 모드에 진입한 사용자 수 | 미정 |
| 긴급 문제 과업 완료 | 임시조치부터 연락까지 모의 과업을 완료한 참여자 수 / 긴급 문제 과업 참여자 수 | 미정 |
| 연락 메시지 완성 비율 | 초안을 수정해 완성한 사용자 수 / 연락 메시지 작성 과업을 시작한 사용자 수 | 미정 |
| iOS 출시 준비 | 팀이 합의한 출시 요건 체크리스트 충족 여부 | 학기 내 목표, 구체 날짜·요건 미정 |

테스트는 실제 위험 상황을 만들지 않는 모의 시나리오로 진행하는 것을 제안합니다. 열람·확인·완성의 판정 조건, 테스트 참여자 수, 과업별 통과 기준은 함께 정합니다. 행동 안내를 확인했다는 사실만으로 실제 문제가 해결됐다고 판단하지 않습니다.

## 7. 위험 요소와 대응 방향

- **사진 분석 오류:** 부정확한 분석이나 낮은 촬영 품질로 잘못된 행동을 권할 수 있습니다. 재촬영·직접 선택 경로와 안전 우선 안내가 필요합니다.
- **사례 신뢰성·개인정보:** 커뮤니티 사례에 잘못된 정보와 개인정보가 포함될 수 있습니다. 출처 검토 및 신고·숨김 기준이 필요합니다.
- **업체 정보 최신성:** 수리업체의 실시간 예약 데이터 확보가 어려워 직접 예약은 제외합니다.
- **안내 범위:** 비용·책임을 확정하거나 긴급도를 과소평가하지 않도록 행동 안내·기록 지원의 범위를 정합니다.
