## 1. 긴급 모드 삭제

### 인사이트

사용자는 문제 상황에서 '이게 긴급한가'를 먼저 판단하고 별도 진입점을 고르지 않는다. 일반 입력과 긴급 입력이 같은 모양이면 두 번째 진입점은 "왜 두 개냐"는 혼란만 만든다. 또 정말 급하다고 느끼면 사용자는 앱보다 전화를 먼저 떠올린다.

### UT 근거

- **과업에 쓰지 않음:** 과업을 해결하는 데 긴급 모드를 쓴 참여자는 없었다. P03은 긴급 모드에 한 번도 들어가지 않았다.
- **두 진입점이 중복으로 보임:** P01은 홈과 긴급 모드 입력 화면(카메라·음성·직접 입력)을 네 번 오간 뒤 "굳이 여기랑 이거 두 개를 할 필요"라고 말했다. (UT_P01 4:21~4:47)
- **긴급의 기준을 모름:** P02는 긴급 흐름을 두 번 반복한 뒤 "뭐가 어떤 기준으로 긴급인 건지"라고 말했다. (UT_P02 3:26~4:12)
- **급하면 전화:** P01은 긴급 모드를 만든 이유를 듣고 "그렇게 긴급하면은 전화를"이라고 답했다. (UT_P01 05:21)
- **의도치 않은 전환:** 사례 카테고리의 [긴급] 항목('변기 물이 역류해요')을 누르면 해결 사례 페이지가 아니라 긴급 흐름으로 바로 넘어갔다. (UT_P01 5:56)

### 왜 이렇게 고쳤나

긴급 모드는 과업에서 쓰이지 않았고, 둘러본 참여자에게는 홈 입력과의 차이를 이해시키지 못했다. 진입점을 개선하기보다, 하나의 입력 흐름으로 모든 문제를 다루는 쪽이 사용자의 실제 행동과 맞다고 판단했다. 이에 따라 긴급 모드에 딸린 진입점과 설정도 함께 삭제했다.

### 수정 내용

| 위치 | 수정 전 | 수정 후 |
|---|---|---|
| 하단 탭 | 가운데에 빨간 '긴급 모드' 버튼 | 버튼 삭제 |
| 긴급 모드 화면 | 입력 방법 선택 → 긴급 카메라·음성·입력 → 긴급 단계 1~3 → 완료 | 화면 전체 삭제 |
| 사례 카테고리 | [긴급] 항목을 누르면 긴급 흐름으로 이동 | 모든 항목이 일반 해결 사례 페이지로 이동 |
| 마이 › 집 정보 | 'SOS 음성 호출 문구'(시리 등록) 입력 칸 | 항목 삭제 |
| 메시지 만들기 | '긴급 연락' 라벨, "급한 상황이라 최대한 빨리 연락 부탁드려요." 기본 문장 | 라벨 삭제, 일반 문장으로 교체 |
| PRD | 핵심 기능에 SOS 모드, 긴급 시나리오, SOS 성공 지표 | SOS 관련 내용 삭제, '범위에서 제외한 기능'에 명시 |

## 2. 해결 단계 용어 풀어 쓰기

### 인사이트

사용자가 해결 단계에서 막히는 지점은 '무엇을 하라'는 지시가 아니라 '그게 무엇인지'다. 부품 이름을 모르면 단계를 읽고도 손을 대지 못하고, 앱을 떠나 따로 찾아보려 한다.

### UT 근거

- **텍스트만으로 어려움:** P01은 단계 3 '연결부 너트를 손으로 조이거나 패킹을 교체해요'에서 16초 머물며 "텍스트로만 돼 있으면 잘 어려울 것 같아"라고 말했다. (UT_P01 1:31~1:47)
- **앱 밖에서 찾아보려 함:** P03은 같은 문구를 길게 눌러 '찾아보기' 메뉴를 띄우고 "패킹이 뭐죠", "너트 같은 거도 잘 모르고"라고 말했다. (UT_P03 2:15~2:33)

### 왜 이렇게 고쳤나

두 참여자가 같은 단계에서 같은 이유로 막혔다. 용어를 앱 밖에서 찾게 하면 흐름이 끊기므로, 용어가 나오는 그 자리에서 바로 뜻을 알 수 있게 했다.

### 수정 내용

| 수정 전 | 수정 후 |
|---|---|
| 연결부 너트를 손으로 조이거나 패킹을 교체해요. | 연결부 너트(배수 호스와 배관을 잇는 둥근 조임 부품)를 손으로 조이거나, 패킹(연결 부위 사이에 끼우는 고무 링)을 교체해요. |

낯선 부품·용어가 나오는 다른 단계에도 같은 방식으로 괄호 안에 쉬운 설명을 붙인다.

## 3. 단계 카드의 상세 이미지 삭제

### 인사이트

펼쳐야 보이는 아이콘 수준의 그림은 실제 부품을 알아보는 데 도움이 되지 않는다. 사용자는 그림을 보고 나서도 여전히 용어를 몰랐다.

### UT 근거

- **그림을 봐도 이해 못함:** P03은 단계 3·4에서 아코디언을 펼쳐 라인드로잉 이미지를 봤지만, 그 뒤에도 "너트 같은 거도 잘 모르고"라고 말했다. (UT_P03 2:16, 2:40)

### 왜 이렇게 고쳤나

상세 이미지는 용어 이해를 보완하지 못하면서, 카드를 펼치는 조작과 화면 길이만 늘렸다. 용어 이해는 2번의 풀어 쓰기로 대신하고 이미지는 삭제했다.

### 수정 내용

| 수정 전 | 수정 후 |
|---|---|
| 단계 카드를 펼치면 라인드로잉 상세 이미지 표시 | 아코디언과 상세 이미지 삭제 |

## 4. 주변 수리업체 찾기를 카카오맵 API 기준으로 통일

### 인사이트

사용자는 업체 목록에서 '어디에 맡길지 고를 근거'를 찾는다. 평점과 리뷰 수만으로는 고르지 못하고, 근거를 얻을 수 있는 익숙한 서비스로 옮겨 간다. 또 모르는 업체에 바로 전화하는 것을 부담스러워한다.

### UT 근거

- **목록만으로 선택 못함:** P03은 주변 업체 화면에 약 70초 머물렀지만 "이걸로는 선택하기 좀 힘들 것 같습니다"라고 말했다. (UT_P03 3:39~4:48)
- **원하는 근거:** 리뷰 내용("리뷰 개수는 보이는데 볼 수가 없어서"), 가격, 출동 속도를 알고 싶다고 했다.
- **전화 부담:** "바로 이렇게 전화를 하는 게 좀 부담되네요"라고 말했다.
- **다른 서비스로 이동:** "당근에서 찾아볼 것 같습니다"라고 말했다.

### 왜 이렇게 고쳤나

사용자가 원한 '고를 근거'(리뷰 내용·가격)는 카카오맵 로컬 API가 제공하지 않는 정보다. 다른 서비스 화면을 수집해 보여주는 것은 저작권·데이터베이스권 문제가 있어 할 수 없다. 프로토타입에 있던 평점·리뷰 수·후기 태그·영업 여부도 실제 출시 버전에서는 보여줄 수 없는 예시 데이터였다.

그래서 앱은 '내 문제에 맞는 주변 업체를 찾아 주는 것'까지만 맡고, 리뷰와 영업 정보 같은 판단 근거는 카카오맵으로 연결해 확인하게 했다. 부담을 준 앱 안의 전화 버튼은 삭제했다.

### 수정 내용

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 업체 검색 | 예시 데이터 | 현재 위치 기준으로 문제 유형에 맞는 검색어(예: 싱크대 누수 → '설비', '배관')로 카카오맵 로컬 API 검색 |
| 업체 카드 | 업체명, 평점, 리뷰 수, 후기 태그, 거리·영업시간, 영업중 표시, '전화' 버튼 | 업체명, 주소, 전화번호 |
| 상세 정보 | 없음 | '카카오맵에서 보기'로 카카오맵 장소 URL 연결 |
| 전화 걸기 | 앱 안에서 '전화' 버튼으로 연결 | 삭제 |

## 5. 메시지 전송 후 해결 사례 페이지로 복귀

### 인사이트

집주인에게 메시지를 보내는 것은 문제 해결의 끝이 아니라 중간 단계다. 사용자는 연락을 해 둔 뒤 업체도 함께 알아보려 한다.

### UT 근거

- **전송 후 홈으로 이동:** 세 참여자 모두 메시지를 보낸 뒤 '전송했어요 (시연)' 안내와 함께 홈으로 이동했다.
- **보던 문제로 돌아가지 못함:** P03은 메시지를 보낸 뒤 업체를 보려 했지만, 홈으로 이동하는 바람에 홈 → 사례 → 커뮤니티 → 마이를 거쳐 문제 기록에서 다시 들어갔다. 약 23초가 걸렸고 "업체가 사라졌어요"라고 말했다. (UT_P03 3:16~3:38)

### 왜 이렇게 고쳤나

메시지를 보낸 뒤 사용자가 다음으로 하려는 일은 같은 문제 안에서 이어진다. 전송 후 홈으로 보내면 맥락이 끊겨 보던 문제를 다시 찾아야 한다. 그래서 전송 후에는 출발한 해결 사례 페이지로 돌아가게 했다.

### 수정 내용

| 수정 전 | 수정 후 |
|---|---|
| 메시지 앱으로 보낸 뒤 홈으로 이동 | 메시지 작성을 시작한 해결 사례 페이지로 돌아감. 같은 화면의 '근처 수리 업체 찾기'로 바로 이어갈 수 있음 |

## 6. 메시지 만들기 화면 구조 변경

### 인사이트

조작하는 곳과 결과가 보이는 곳이 떨어져 있으면 사용자는 기능을 이해하지 못한다. 같은 내용을 두 곳에 보여주면 화면만 길어지고, 정작 확인해야 할 결과는 화면 밖으로 밀려난다.

### UT 근거

- **기능을 이해하지 못함:** 블록을 껐다 켜면 아래 미리보기의 문장이 사라졌다 다시 생기는데, 참여자들이 이 기능을 잘 이해하지 못했다.
- **결과를 확인하려고 스크롤:** P01은 보낼 내용의 체크를 껐다 켜며 미리보기가 어떻게 바뀌는지 확인하느라 16초 동안 스크롤을 오갔다. (UT_P01 1:59~2:14)
- **첫 화면에 결과가 없음:** 블록 목록과 미리보기에 같은 문장이 두 번 나와 화면이 길어졌고, 미리보기는 스크롤해야 보였다.

### 왜 이렇게 고쳤나

문제의 원인은 같은 문장을 '고르는 곳'과 '확인하는 곳'으로 나눠 보여준 구조였다. 두 영역을 메시지 카드 하나로 합쳐, 문장을 빼고 넣는 결과가 누른 자리에서 바로 보이게 했다. 개발 용어인 '블록'과 의미가 모호한 취소선도 함께 없앴다.

### 수정 내용

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 구조 | '보낼 내용' 블록 목록 + 아래 '메시지 미리보기' | 메시지 카드 하나 |
| 문장 빼기·넣기 | 블록의 체크를 끄고 켬 → 아래 미리보기에서 문장이 사라지거나 생김 | 메시지 카드의 문장 옆 ✕를 누르면 빠지고, 아래 '문장 추가하기' 칩(+)으로 내려감. 칩을 누르면 다시 메시지에 들어감 |
| 용어·표시 | "각 블록의 문장을…", "블록을 뺐다 끼며…" 설명 문구, 꺼진 문장은 취소선 | '블록'이라는 말과 설명 문구 삭제, 취소선 삭제. 추가할 수 있는 문장은 '+ 칩'으로 구분 |
| 상단 | 두 줄 제목 + 설명 + 받는 사람 카드 | 한 줄 제목, 받는 사람 카드 한 줄로 압축 |
| 첫 화면 | 블록 목록만 보이고 미리보기는 스크롤해야 보임 | 메시지 전체와 '메시지 앱에서 보내기' 버튼이 함께 보임 |
