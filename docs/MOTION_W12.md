# 어쩌집 마이크로 인터랙션 동작 정의

## 1. 적용 영역과 목적

버튼을 눌렀다는 반응을 분명하게 보여주고, 화면이 바뀔 때 앞뒤 화면이 연결되어 보이도록 했다. 목록과 텍스트는 읽는 순서에 따라 나타나게 했다. 화면의 최종 크기·색상·배치는 유지한다.

- 공통 CTA·메시지 대상 전환·리스트 버튼: 축소 후 탄성 복원(팝)
- A01 카테고리 아이콘: 눌림 축소
- 홈의 파란 버튼 → 검색창: 몰핑
- 검색 결과·사례 목록: 순차 등장(스태거)
- 메시지 본문·문제 제목: 어절·음절별 순차 등장
- 복사 완료 토스트: 바운스 피드백
- 홈 ↔ 마이페이지: 프로필 아이콘·카드의 마스킹 몰핑

‘스프링’은 탄성을 계산하는 방식, ‘바운스·팝’은 튀는 움직임의 인상이다. 버튼 효과의 명칭은 ‘축소 후 탄성 복원’으로 사용한다. 목록의 ‘샤랄라’는 항목마다 시차를 두는 ‘순차 등장(스태거)’으로 표현한다.

## 2. 동작 정의표

최종 구현의 동작을 기준으로 정리했다. 시간은 ms 단위이며 1,000ms는 1초다.

| 적용 영역 | 사용자 동작 | 상태 | 모션 | 순서 |
| --- | --- | --- | --- | --- |
| 공통 CTA·메시지 대상 전환·리스트 버튼 | 버튼을 누르거나 집주인·수리기사를 선택한다. | 기본 → 눌림 → 복원. 대상 탭은 선택 상태도 바뀐다. | CTA·리스트는 90ms 동안 96%로 작아졌다가 320ms 동안 탄력 있게 돌아온다. 대상 탭은 96%→102.5%→100%로 320ms 동안 움직이고, 색상은 240ms 동안 바뀐다. | 눌리는 반응을 먼저 보여준다. 손을 놓으면 복원하거나 선택 상태로 바뀐다. 화면 이동은 기다리게 하지 않는다. |
| A01 카테고리 아이콘 | 원하는 카테고리를 누른다. | 기본 → 눌림 → 해당 카테고리로 이동 | 아이콘만 90%로 줄어들고, 해제하면 원래 크기로 돌아온다. 전환은 180ms다. 글자는 움직이지 않는다. | 누르는 동안 작아지고, 놓으면 해당 목록으로 이동한다. 취소하면 원래대로 돌아온다. |
| 홈의 파란 버튼 → 검색창 몰핑 | 홈의 파란 검색 버튼을 누른다. | 홈 → 검색 입력 화면 | 버튼이 검색창의 위치·크기·모서리 모양으로 변한다. 위치는 약간 탄력 있게 움직이고, 색은 누른 뒤 150ms 안에 회색으로 바뀐다. | 이동이 끝나기 약 300ms 전부터 검색창이 200ms 동안 드러난다. 추천 검색어는 그보다 80ms 뒤에 10px 올라오며 320ms 동안 나타난다. |
| 검색 결과·사례 목록 순차 등장 | 검색하거나 카테고리 목록에 들어간다. | 목록 진입 → 목록 표시 | 화면에 보이는 항목들이 12px 아래에서 올라오며 나타난다. 각 항목은 280ms, 항목 간 간격은 45ms다. | 위에서 아래 순서로 나타난다. 기다리는 시간은 최대 225ms로 제한한다. 사례에서 뒤로 돌아올 때는 반복하지 않는다. |
| 메시지 본문·문제 제목 순차 등장 | 문의 메시지에 처음 들어가거나 대상을 바꾼다. 해결 방법 화면에 들어간다. | 새 메시지·제목 표시 → 전체 내용 표시 | 메시지는 어절마다 45ms 간격·260ms 등장, 문제 제목은 음절마다 75ms 간격·433ms 등장이다. 둘 다 5px 올라오면서 선명해진다(흐림 3px→0, 투명도 0→100%). | 왼쪽부터 읽는 순서대로 나타난다. 메시지는 누르면 바로 전체 내용을 편집할 수 있다. 긴 메시지의 등장 지연 합계는 1,500ms 이하로 제한한다. |
| 복사 완료 토스트 바운스 | 복사하기를 누른다. | 복사 성공 → 완료 알림 → 알림 종료 | 알림이 8px 아래·96%에서 올라와 2px 위·102.5%를 거쳐 제자리로 돌아온다. 표시와 사라짐을 합쳐 1,500ms다. | 실제 복사에 성공한 다음 알림을 띄운다. 잠시 유지한 뒤 사라진다. 여러 번 눌러도 알림을 쌓지 않는다. |
| 홈 ↔ 마이페이지 마스킹 몰핑 | 프로필 아이콘을 누르거나 마이페이지에서 뒤로 간다. | 홈 ↔ 마이페이지 | 원형 영역이 프로필 카드로 커지고, 돌아갈 때는 다시 원형으로 줄어든다. 내용은 확대·축소하지 않고 마스크만 움직인다. 그라디언트는 마스크 전체를 채운다. | 진입 시 나머지 내용은 150ms 뒤부터 약 183ms 동안 나타난다. 복귀는 약 267ms로, 닉네임은 시작부터 75ms, 나머지 마이 텍스트는 100ms 동안 사라진다. 홈 내용은 약 83ms 뒤부터 183ms 동안 나타나고, 축소가 끝나면 프로필 아이콘을 바로 보여준다. |

### 공통 조건

- 움직임 줄이기 설정에서는 이동·확대·순차 등장 효과를 생략하고 내용을 바로 보여준다.
- 비활성·로딩 버튼에는 눌림 팝을 적용하지 않는다.
- 본문은 처음부터 완전한 문자열로 보관한다. 모션 중 복사·메시지 앱 연결을 해도 일부 문장만 전달되지 않는다.
- 집주인·수리기사별 편집 내용은 유지한다. 같은 대상 탭을 다시 눌러 본문 모션을 반복하지 않는다.
- 프로필 축소는 D01→A01에서만 실행한다. 검색 화면에서 홈으로 돌아올 때는 재생하지 않는다.
- 홈·마이 전환은 이전 화면 위에 다음 화면을 겹쳐 보여준다.

## 3. 제공 코드 분석

### Command Button — 버튼이 검색창으로 이어지는 구조

출처: [DesignBookmark Command Button](https://designbookmark.com/motion#db-command-button). 사용자가 제공한 React 코드 기준.

| 확인한 코드 | 쉽게 풀어 쓴 동작 | 어쩌집 적용 |
| --- | --- | --- |
| `pressTarget … 0.97` | 누르면 버튼이 97%로 작아진다. | 눌렀다는 피드백을 주는 원리를 참고했다. 공통 버튼은 96%로 정했다. |
| `layout`, `width: open ? width : "auto"` | 버튼과 입력창을 같은 외곽 안에서 크기만 바꾸며 연결한다. | 홈 버튼에서 다음 화면의 검색창으로 위치·크기·라운드가 이어지도록 했다. |
| `openSpring(bounce)`, 기본 강성 300·감쇠 28 | 펼쳐질 때 탄성이 생기며, 감쇠값이 작을수록 반동이 커진다. | 검색창은 강성 260·감쇠 22·질량 1.05를 사용한다. |
| `SWAP` 180ms, 지연 60ms | 외곽과 내부 문구를 서로 다른 시간에 바꾼다. | 위치와 색상·내용을 분리했다. 회색 전환은 150ms 디졸브로, 추천 검색어는 이동 후반에 표시한다. |

핵심: ‘버튼이 사라지고 새 입력창이 생김’보다 ‘누른 버튼이 검색창으로 바뀜’으로 보이게 한다.

### Streaming Reply — 단어별 시간차

출처: [DesignBookmark Streaming Reply](https://designbookmark.com/motion#db-streaming-reply). 사용자가 제공한 HTML·JavaScript 코드 기준.

| 확인한 코드 | 쉽게 풀어 쓴 동작 | 어쩌집 적용 |
| --- | --- | --- |
| `a.split(' ')` | 문장을 공백 기준으로 나눈다. | 메시지 본문은 어절, 짧은 문제 제목은 음절로 나눴다. |
| `after(i * .07, …)` | 다음 단어를 70ms씩 늦게 시작한다. | 메시지는 45ms, 제목은 75ms 간격으로 정했다. |
| 단어별 위치·불투명도·`blur(… * 4)` 조절 | 단어가 아래에서 올라오며 흐린 상태에서 선명해진다. | 5px 상승·3px 흐림 해제를 적용했다. |
| 자동으로 다음 문장을 재생하는 타이머 | 데모는 여러 문장을 반복한다. | 자동 반복은 사용하지 않는다. 화면 진입·대상 변경 때만 실행하고 편집하면 끝낸다. |

핵심: 글자를 실제로 생성하는 기능이 아니라 이미 있는 문장을 읽는 순서대로 보여주는 연출이다.

### Goo Thinking — 작은 영역에서 큰 영역으로 확장

출처: [DesignBookmark Goo Thinking](https://designbookmark.com/motion#db-goo-thinking). 사용자가 제공한 두 HTML 자료 기준.

| 확인한 코드 | 쉽게 풀어 쓴 동작 | 어쩌집 적용 |
| --- | --- | --- |
| `filter:url(#dotgoo)` | 가까운 점들이 붙는 것처럼 보인다. | 점이 붙는 필터는 사용하지 않았다. |
| `W = S(64, 240, 24)`, `H = S(40, 240, 24)` | 작은 64×40 영역의 너비·높이를 따로 움직인다. | 작은 원형 프로필 영역이 큰 카드로 이어지는 원리를 참고했다. |
| `W.t = wrap.offsetWidth`, `H.t = answer.offsetHeight + 22` | 내용에 맞춰 영역을 펼친다. | 실제 카드와 아이콘의 위치·크기를 읽어 그 사이를 전환한다. |
| `later(.12, … A.t = 1)` | 펼침과 내용 등장을 따로 제어한다. | 카드 내용은 마스크로 드러내고 나머지 텍스트는 이동 중간에 등장시킨다. |

핵심: 로딩 점과 자동 반복을 가져오는 대신, ‘작은 영역이 큰 정보 영역으로 이어지는 관계’를 참고했다. 마스크와 화면 디졸브는 어쩌집의 구조에 맞춰 적용했다.
