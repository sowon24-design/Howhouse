# 최신 main 이후 출시 전 진행·운영 적용 계획

기준 main: 3b9ed3603988604c8cad2f37c62416f2ccc8beaa (PR #56 병합 확인). 운영 환경을 조회하거나 변경한 결과가 아닌 코드 기반 적용 계획이다.

네트워크 보완과 로컬 관찰 결과는 [동의 전후 네트워크 점검](PRECONSENT_NETWORK_AUDIT.md)을 따른다. Android 실기기 및 실제 서버 검증 완료와 구분한다.

## 진행 순서

1. 로컬 보완: 기존 사례 화면 자동 평가 조회가 신규 Auth 가입·토큰 갱신을 유발하지 않도록 수정. 유효한 기존 세션만 사용한다. 세션이 없으면 조회를 생략하고 평가·의견 직접 제출 기능은 유지한다. 이 조치가 평가 제출 자체의 처리 근거 검토를 완료한 것은 아니다.
2. 새 설치/기존 설치/만료 세션에서 E03 거부 → 기존 사례 → 평가·의견 → A02 동의 → 분석 → 철회 → 삭제의 네트워크를 확인한다. 사진 미리보기·외부 링크의 자동 요청도 포함한다. 비밀 토큰·원문을 캡처 파일에 남기지 않는다. 현재 실기기 확인은 미완료다.
3. 예슬이: docs/policies/의 6개 본문을 기존 Notion URL에 반영. 개정 버전과 비로그인 접근·모바일 표시를 확인한다. 이 작업에서 직접 게시하지 않는다.
4. 계약/공개 자료와 운영 설정으로 부수 로그·지원 처리 범위와 적용 근거를 확정한다. 업체 회신 대기를 선행 조건으로 두지 않는다. 확인하지 못한 국가·기간은 만들어 쓰지 않는다. 미확정 항목을 표시만 지워 출시 승인하지 않는다.
5. 아래 운영 변경을 시험 환경에서 검증하고, 결과 확인 후 실제 적용한다.
6. 최종 앱 후보에서 동의 저장 영수증·분석·철회·삭제·의견·캐시·사진·재시도·취소를 검증한다. 최종 서명 AAB 및 Play Console 항목은 실제 후보 기준으로 확인한다.

## 운영 변경 전 설명

### Supabase DB

- 최신 main의 server/analysis/release-data.sql 다음 consent-evidence.sql 순으로 적용한다. 기존 feedback/cache 관련 스키마는 기존 문서와 실제 상태를 먼저 대조한다.
- 추가되는 항목: 레거시 현재 상태 보존, 문서 원문/해시, 동의·철회 이벤트, 서버 전용 RPC/권한. 기존 사용자를 새 동의자로 자동 전환하지 않는다.
- 기존 테이블을 삭제하지 않는다. 시험 DB에서 재적용·트랜잭션 롤백·권한·Auth 삭제 cascade·동의 없이 분석 차단을 확인한다.
- 운영 직전 백업/스키마 내보내기와 복구 가능 여부를 확인한다. 새 데이터는 보존하고 장애 시 서버/앱 배포를 중단한다. 증빙 테이블을 삭제해 되돌리지 않는다.

### Render 서버

- DB 준비 후 같은 동의 문서 버전의 서버를 배포한다. RELEASE_DATA_ENABLED=1은 기존 구형 앱과의 호환에 영향을 준다. 구형 앱 차단·재동의 안내와 배포 시점을 맞춘다.
- PRIVACY_DOCUMENT_READY=1은 공개 문서/외부 삭제 페이지 준비 상태다. 승인 파일과 별개이며, 값을 켜는 것만으로 분석 동의가 승인되지 않는다. 삭제 페이지는 분석 동의 승인과 독립해 접근 가능해야 한다.
- policy-approval.json의 analysisConsentApproved는 아직 false다. 본문/Notion/처리 범위/통합 검증의 완료 근거 없이 true로 바꾸지 않는다.
- 서버 키·캐시 암호화 키는 기존 값을 유지하고 공개 저장소나 VITE_ 환경에 복사하지 않는다. 처리 지역, 로그/보유 설정, 정리 작업 실제 실행을 운영 계정에서 확인한다.
- /health, /privacy, /terms, /data-deletion을 배포 후 확인한다. health 성공만으로 동의·삭제·분석 성공을 판정하지 않는다.
- 신규 동의 영수증의 eventId/recordedAt/hash, 문서·화면 버전, 서버 증빙을 대조하고 그 뒤 테스트 계정으로 분석 1회를 명시적으로 실행한다. 유료 요청은 사전 설명 후 수행한다.
- 장애 시 신규 분석을 중단하되 철회·삭제 경로는 유지한다. RELEASE_DATA_ENABLED=0으로 분석 동의 검사를 없애는 복구는 사용하지 않는다.

### 앱 및 Play

- 서버·앱 동의 버전 일치, 최종 정책 승인과 공개 URL 확인 후 VITE_RELEASE_PRIVACY_READY=1로 최종 빌드한다. 승인 검사 우회나 test 모드 파일을 출시하지 않는다.
- versionCode는 Play에서 이미 사용한 값을 확인한 뒤 정한다. 서명 키는 운영자 관리로 유지한다.
- 실제 AAB의 네트워크/권한/SDK, 삭제 URL, 데이터 보안 답변, 동의 거부 시 사례 조회, 사진, 오류·철회·삭제를 대조한다.
- 스토어 제출·운영 DB 변경·서버 배포는 이번 로컬 보완에서 실행하지 않았다.
