## 2. 법적 근거 검토에서 보완한 점

개인정보 보호법 28조의8 1항은 별도 동의 외에 계약 이행에 필요한 위탁·보관, 동등성 인정 등 경로를 둔다. 처리별 사실과 근거를 나눠 판단해야 한다. DPA 또는 EU SCC 계약이 있다는 사실만으로 한국법 요건 전체를 충족했다고 판정하지 않는다.

추가 확인: 개인정보위는 2025-09-16 EU·EEA 30개국의 GDPR 적용 수령자에 대한 동등성 인정을 안내했다. 이는 인정 범위에 해당하는 이전의 독립된 근거가 될 수 있으므로, EU 로그 국가가 구체적으로 답변되지 않았다는 이유만으로 Supabase 사용이 언제나 불가능하다는 결론은 과도하다.

다만 다음은 이 자료만으로 확정하지 않았다: Supabase Pte. Ltd.와 계약한 우리 흐름에서 실제 로그 수령자가 그 인정 범위에 해당하는지, 어떤 비EU 지원·재이전이 포함되는지, 부수 기록 보관·권리행사의 적용 범위. 수령자가 EU에 있다는 설명과 계약 법인 소재지를 구분한다. 동등성은 일반 수집·이용·위탁·안전조치·권리행사 의무까지 없애는 것이 아니다.

## 3. 처리별 적용 후보와 남은 공백

| 처리 | 확인 사실·적용 후보 | 이번 판단 |
|---|---|---|
| 서울 DB/Auth 본체 | 기존 서울 기록, 임시 인증·증빙·암호화 저장. 국내 수집/위탁 근거와 부수 국외 경로는 분리 | 외국 법인이라는 이유만으로 모든 DB 저장 위치를 외국으로 쓰지 않음 |
| Supabase EU 로그 | 공식 FAQ의 EU 저장, 동등성 인정 범위 적용 후보 | 수령자·GDPR 적용 및 재이전 연결 확인 없이 적용 완료로 확정하지 않음 |
| 비EU 지원·보안 접근 | 공식 FAQ의 글로벌 지원 및 미국 계열사, 필요한 범위 접근 | EU 동등성으로 포괄하지 않음. 항목·목적·국가·보관과 적법 근거 대조 필요 |
| Render 싱가포르 처리 | 요청 중 글·사진·토큰 처리, 앱 원문 영구 미저장, 위탁 계약 | 사용자 분석 요청에 필요한 처리와 부수 운영/지원 처리를 구분. 서버 지역만으로 전체 처리 국가를 확정하지 않음 |
| OpenAI 미국 지정 요청 | 기존 지정 주소·store:false·학습 공유 비활성 기록, 위탁 DPA | 분석 본문과 악용감시/지원 예외를 구분. 응답 저장 비활성은 전체 무보관 근거가 아님 |
| 기기 밖 평가·신고 | UUID·평가·암호화 의견 등 | 분석 동의가 평가 전체를 자동 포괄한다고 승인하지 않음 |

계약 이행 필요성 근거도 필요한 고지사항 공개/통지를 따진다. EU 경로가 성립해도 다른 비EU 경로를 자동 해소하지 않는다. 모든 보유 기준에 반드시 숫자 일수가 있어야 한다고 단정하지 않지만, 일반 DPA 계약기간을 모든 내부 기록의 삭제 보장으로 옮겨 쓰지도 않는다.

이 문서는 운영 검토 자료이며, 앱 고지 본문이나 동의 버전을 변경하지 않았다. 확인하지 못한 국가·기간을 임의로 채우지 않는다. 현재는 일부 법적 경로가 추가 확인됐지만, 전 경로의 출시 적합성이 확정된 상태는 아니다. 업체 이메일 답변 대기를 선행 조건으로 추가하지 않았다. 부족한 사실을 공개 계약/운영 범위/구성 통제로 닫을 수 있는지를 검토하고, 닫히지 않으면 해당 경로의 기반 조정이 필요하다.

## 4. v5 연결 검증 결과

신규 `server/analysis/consent-lifecycle.test.mjs`는 실제 createPrivacyClient → loopback HTTP createAnalysisServer → createReleaseStore → PGlite에 실제 SQL을 적용한 구조다. Auth는 합성 계정 검사, AI는 가짜 응답, 사용 한도 ledger는 시험용 대체물이다. 실제 운영 Auth·OpenAI·한도·암호화 캐시 검증을 대신하지 않는다.

## 5. 아직 실행하지 않은 최종 단계

- 실제 폰/최종 호환 앱의 v5 동의 영수증·사진 분석·철회·삭제. 폰이 없어 실행하지 못했다.
- 실제 운영 계정의 시험 동의 생성/삭제, 유료 사진 분석. 승인 차단을 우회해 실행하지 않았다.
- 노션 반영은 예슬이 담당으로 별도 유지. 본 작업에서 게시하거나 완료 처리하지 않았다.
- 운영 분석 승인 true, 공개 privacy/terms 전환, AAB 제출은 실행하지 않았다.

다음 운영 변경이 필요하면 먼저 공개할 내용: 승인 파일을 true로 하면 신규 동의 접수·분석 및 일부 공개 페이지가 열리므로, 남은 고지 근거와 최종 후보를 확인한 후에만 배포한다. 이미 1로 확인된 두 서버 플래그를 다시 설정하거나 DB SQL을 중복 적용할 이유는 없다. 실제 검사에는 합성 입력·테스트 소유 계정만 사용하고 유료 호출 범위를 사전에 설명한다.
