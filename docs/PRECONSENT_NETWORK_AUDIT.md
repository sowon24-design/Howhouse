# 동의 전·거부·철회 후 네트워크 점검

기준: main 3cff37d(PR #57 포함)과 통합한 로컬 브랜치 codex/launch-passive-auth. 운영 Supabase·Render·OpenAI·Notion은 변경하지 않았다.

## 발견과 보완

- 기존 사례의 YouTube 썸네일은 lazy 이미지였으므로 스크롤만으로 i.ytimg.com에 요청했다. 동의 거부 후 사례 열람에서도 재현했다. no-referrer는 IP 접속 자체를 차단하지 않는다.
- 영상 링크와 200px 미리보기 영역은 유지한다. 최초에는 로컬 안내를 표시하고 기존 공통 Button으로 미리보기 불러오기를 제공한다. 이 버튼을 직접 누른 뒤에만 원격 썸네일을 요청한다. 영상 링크를 직접 열 수 있으며 원격 미리보기 로딩과 독립적이다.
- 평가의 자동 상태 조회는 현재 서비스·현재 버전의 로컬 동의 영수증과 유효한 기존 세션이 모두 있을 때만 실행한다. 없거나 만료/철회 상태면 자동 인증·자동 조회를 생략한다. 실제 서버 권한 판정은 기존 서버 검증을 유지한다.
- 직접 평가·의견 제출은 기존 명시적 사용자 동작 경로를 유지한다. AI 동의를 평가 저장의 법적 근거로 일괄 대체한 것이 아니다. 평가 제출의 별도 처리 근거·고지는 기존 출시 검토 항목에 남아 있다.

## 재현

Node 24와 로컬 Chrome이 필요하다. 다음은 가짜 공개 설정이며 비밀 키가 아니다. 기존 .env 파일을 덮어쓰지 않는다.

```powershell
$env:VITE_ANALYSIS_API_BASE_URL='https://analysis.audit.invalid'
$env:VITE_ANALYSIS_AUTH_URL='https://auth.audit.invalid'
$env:VITE_ANALYSIS_AUTH_PUBLISHABLE_KEY='sb_publishable_audit_fixture'
$env:VITE_RELEASE_PRIVACY_READY='1'
node node_modules/vite/bin/vite.js build --mode release-preview --outDir '../network-audit-dist'
node scripts/audit-preconsent-network.mjs '../network-audit-dist' '../network-audit-output'
```

전용 프로세스/작업 폴더에서 실행한다. 가짜 주소로 만든 빌드는 배포·제출하지 않는다. 검사 도구는 전달한 빌드가 release-preview/개발도구 비표시/privacyReady=true인지 확인한다. 마지막 값은 UI 검사용 플래그이며 정책 승인 파일을 true로 바꾸지 않는다. 출력은 요청 시점·메서드·호스트/경로이며 토큰·문제 글·사진은 기록하지 않는다. Chrome 경로가 다르면 CHROME_PATH를 지정한다.
