# 어쩌집 접근성 검토 및 개선 리포트

- 검토·정리일: 2026-11-10
- 기준: [접근성 점검 가이드](ACCESSIBILITY.md), WCAG 2.2 A·AA 및 Android 터치 영역 권장사항
- 대상: A01·A02·B01·B02·B03. 화면별 실제 검사 범위는 아래에 구분
- 결론: **이번에 채택한 디자인 개선은 B02 준비물 텍스트 색상 변경 1건이다. 나머지는 기존에 반영된 접근성 요소의 검증으로 정리한다.**
- 전체 WCAG 준수 또는 Android 접근성 통과를 선언하는 리포트는 아니다. 이번 문서 수정에서 앱 검사나 자동 스캔을 새로 실행하지 않았다.

## 1. 대상 사용자와 목표

한 손으로 휴대폰을 사용하고 작은 글자를 확대해 읽는 자취생을 가상 사용자로 설정했다. 기존 사례를 찾고 해결 단계를 읽거나 문제를 입력하고 문의 메시지를 작성할 때, 낮은 대비·작은 조작 영역·불명확한 안내 때문에 어려움을 겪지 않도록 하는 것이 목표다. 실제 사용자 인터뷰나 장애 당사자 테스트를 수행한 것은 아니다.

팀은 기존 디자인 과정에서도 AA 대비와 요소 크기를 점검하며 제작했다. 이번 워크숍에서는 변경 개수를 늘리기보다, 기존 설계의 적용 여부와 실제 확인하지 못한 부분을 구분했다.

## 2. 채택한 개선 — B02 준비물 텍스트 색상

| 항목 | 내용 |
| --- | --- |
| 개선 전 근거 | 이전 로컬 구현에서 글자 `#5F6979` / 배경 `#DEE5F0`의 계산 대비 약 4.38:1. 일반 글자 기준 4.5:1에 미달 |
| 채택한 변경 | 준비물 글자색을 진한 기본 글자색 `#19212E`로 변경. 순수 검정은 아님 |
| 변경 범위 | 해당 화면의 준비물 글자색. 공통 디자인 시스템·원본 컴포넌트의 일괄 변경은 아님 |
| 목적 | 버튼의 크기·배치·시각적 리듬을 유지하면서 글자를 더 분명하게 구분 |
| 개선 후 실측 | 2026-11-10 Figma 준비물 버튼 2개 확인. 글자 `#19212E`, 배경 약 `#DEE5F0`, 글자 크기 14px. 글자·배경·상위 레이어 불투명도 100% |
| 대비 계산 | Figma 원본 sRGB 소수값을 선형화해 상대 휘도 계산: `(밝은 색 휘도 + 0.05) / (어두운 색 휘도 + 0.05)` = **12.71:1**. HEX는 표시용 반올림이며 계산에는 원본값 사용 |
| 판정 | 해당 조합은 WCAG 1.4.3 일반 글자 AA 기준 **4.5:1 충족**. 변경 전 코드 조합 4.38:1과 구분하여 기록 |
| 측정 범위 | 지정 Figma B02의 준비물 버튼 2개. 화면 전체나 Android 실행 결과의 판정은 아님. 노드: `I916:9932;725:31184`, `I916:9932;725:31205` |

입력창 스트로크 추가 등 나머지 제안은 디자인의 균형과 필요성을 검토한 뒤 채택하지 않았다. 해당 제안을 개선 완료로 기록하지 않으며, 이 문서 작업에서 Figma나 앱을 추가 수정하지 않는다.

## 3. 기존에 반영된 요소의 검증

아래는 이전 검토 당시 확인한 내용으로, 이번에 새로 구현한 개선사항이 아니다.

| 화면·항목 | 확인한 기존 구현 | 확인 방법·범위 |
| --- | --- | --- |
| A01 버튼·이미지 | 마이·카테고리·인기 문제에 접근 가능한 이름과 button 역할 제공. 장식 캐릭터·아이콘의 중복 낭독 방지 처리 | 로컬 웹 DOM·접근성 트리 확인 |
| A01·B01 좁은 화면 | 320px에서 긴 텍스트 줄바꿈 확인 | 홈·화장실 카테고리, 320px |
| A01·B02 가로 너비 | 확인한 화면의 문서 너비 320px | 로컬 웹 계산 크기 확인 |
| B01 목록 구조 | 사례 목록에 ul/li 구조와 목록 이름 제공 | DOM 확인 |
| B02 펼침·평가 상태 | 비용 설명에 aria-expanded·aria-controls, 평가 버튼에 이름·선택 상태 제공 | DOM·접근성 트리 확인 |
| B02 해결 단계 | 세로 나열로 단계 읽기에 가로 드래그가 필수가 아님 | 화면·구현 확인 |
| B02 해결 완료 시트 | modal dialog, 첫 버튼 초점 이동, Shift+Tab 순환, Escape 닫기, 닫힌 뒤 원래 버튼으로 초점 복귀·테두리 확인 | 해결 완료 시트의 웹 키보드 검사 |
| 단색 글자 대비 | 보조 글자/기본 배경 5.32:1, B01 기본 글자/목록 배경 14.39:1, 흰 글자/primary 버튼 6.41:1 | 해당 단색 조합의 상대 휘도 계산 |

실행 검토 환경은 `feature/app-screens`의 당시 작업본, Vite 로컬 웹, Chromium 기반 인앱 브라우저였다. A01 → B01 화장실 → B02 배수구 악취 → 해결 완료 시트 경로와 320×640, 시트의 640×320 CSS px 조건을 확인했다. 자동 검사 도구의 전체 스캔 결과는 아니다.

## 4. 워크숍 정리와 성찰

기존 디자인에서 대비와 크기를 고려한 덕분에, 화면 전체를 바꾸기보다 준비물 텍스트의 대비를 보완하는 작은 개선을 채택했다. 입력창 스트로크처럼 제안된 변경도 그대로 적용하지 않고 디자인의 균형과 필요성을 함께 판단했다.

접근성 검토는 수정한 요소의 개수로 판단하기 어렵다. 기존에 반영된 요소를 근거와 함께 검증하는 것도 의미가 있으며, 시안의 대비·크기 확인과 실제 앱의 읽기·초점·확대 검증은 분리해야 한다. 이번 결과는 **채택한 개선 1건과 대비 재측정 + 기존 구현의 제한된 검증**으로 제시한다.

발표 자료에는 준비물 글자색 변경 전후와 기존 검증 표를 사용한다. 준비물 텍스트 대비는 AA 기준을 충족하지만, 이를 앱 전체의 AA 충족으로 표현하지 않는다.
