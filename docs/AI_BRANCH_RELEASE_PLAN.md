# AI 유지 브랜치의 선택 반영·출시 적용 계획

2026-11-12 / PR62 `codex/ai-release-privacy` / 동의 본문 `2026-11-12-v9`.
목표는 글·사진 AI 분석이 가능한 앱이다. AI 없는 main은 수정하거나 이 브랜치로 전체 병합하지 않는다. Supabase Free·동의 증빙·철회·삭제·서버 평가/신고를 유지하고 로그인은 후속으로 둔다.

실제 Render·앱 적용의 최신 실행 순서는 `AI_LIVE_APPLICATION_RUNBOOK.md`를 따른다. 같은 저장소의 특정 후보 SHA 수동 배포를 사용하면 Render 연결 브랜치를 바꾸거나 main에 병합할 필요가 없다. 이번에 서명·버전 입력 지원과 소스 기대값 JSON 도구를 준비했지만 실제 키 사용·서명·배포·계정 설정 변경은 하지 않았다.

## 최신 main에서 가져온 변경

비교 대상 `origin/main=6dea025`, AI 버전 이전 HEAD `47c6d2b`. main PR66/67의 공통 사례 62개·검토 단계·분류·이미지와 기존 CSV 수정, 목록 표시용 문구, 예상 시간 표시 정리, 닉네임 입력 콜백을 선택 반영했다. 화면 이동 시 닉네임 초안이 사라지지 않도록 AI 온보딩의 부모 상태에 연결했다. 생성 AI의 예상 시간은 원래 응답 그대로 유지한다.

추가 사례는 앱만 추가하면 서버와 목록 해시가 달라지므로 서버 `loadCatalog()`도 같은 CSV·검토 단계로 115개를 구성한다. 실제 Vite로 로드한 프론트 모듈과 서버의 직렬화 본문을 비교해 완전히 같음을 확인했다. 카탈로그 버전은 `650ad40675d7f38722f92b5e135e4fd7d16d2d52d5c3b1e723e70043a38e2b87`이다.

main의 포장된 영상 썸네일을 재사용하여 해당 영상은 앱 내부 이미지를 표시한다. 없는 썸네일만 기존의 명시적 불러오기 기능을 유지한다. 새로운 YouTube API·키·서드파티 인증은 추가하지 않았다. 실제 영상 열기는 기존 외부 링크 동작을 유지한다.

AI 제거용 main 진입점·Vite/Capacitor/Android 설정, 사례 전용 정책·승인값, 서버 평가를 대체하는 로컬 평가 변경, 준비물 링크 제거는 반영하지 않았다. AI 브랜치의 빌드 확인표에 `variant=ai`, `aiEnabled=true`, `serverStorage=true`를 추가하여 두 버전의 산출물을 구별한다. 이는 배포 승인 플래그를 켠다는 뜻이 아니다.

## 사진과 개인정보가 있는 입력의 처리

사진 분석에는 정리한 이미지의 픽셀과 문제 글을 분석 서버·OpenAI로 전송한다. 사진 전송 자체를 없애야만 사용할 수 있다는 전제는 아니다. 원본 파일명·EXIF·GPS는 제거하지만 얼굴·집 주소·문서 내용 등 픽셀 속 정보나 글 속 개인정보는 자동 익명화되지 않는다.

현재 코드에는 이름이나 개인정보가 발견되면 모든 분석을 일괄 거절하는 기능이 없다. 정상 주거 문제 설명에 식별 정보가 섞였다는 이유만으로 요청 생성이 실패하지 않음을 합성 입력으로 확인했다. 이는 실제 모델이 모든 사진·요청에 반드시 답한다는 뜻은 아니다. 이미지 손상·한도·동의 거부·안전상 거절 등 기존 제한은 유지한다. 안전 정책을 우회하거나 민감·타인 정보를 수집하는 기능을 추가하지 않는다. 불필요한 개인정보 제외 안내와 출력에서 이름·주소·전화번호·호수 등을 재기재하지 않도록 하는 기존 지침은 유지한다.

## 검증 결과와 범위

후속 Android 후보의 변경 부분 검증도 완료했다. 홈 배치 없는 사례의 상세 경로 오류를 수정하고 새 APK에서 닉네임 초안·추가 사례 단계·포장 썸네일·YouTube/쿠팡 외부 Intent를 확인했다. `ANDROID_AI_CANDIDATE_DELTA_VALIDATION.md`가 최신 결과다. 아래의 '새 APK 미검증'은 선택 반영 직후의 기록이며 이 후속으로 보완했다. 실제 운영·최종 서명 검증은 계속 별도다.

- 타입 검사·자동 테스트 240개 통과, 실패/건너뜀 0(PGlite 포함). 추가 사례가 모델의 기존 사례 결과로 정상 인정되고 검토 단계가 유지되는 회귀 검사를 포함한다.
- 실제 프론트와 서버: 각각 115개, 직렬화 본문과 버전 해시 일치.
- release-preview 합성 설정 빌드 통과. 큰 청크 경고는 유지되며 추가 이미지와 목록으로 앱 크기·AI 입력량이 늘어난다. 실제 모델 비용·응답 품질을 이번에 유료 호출로 측정하지 않았다.
- 로컬 헤드리스 브라우저: 신규 앱 번들에서도 동의 전/거부·사례 열람·만료/기존 세션·철회 후 수동 요청 없음. 요청 기록은 명시적으로 누른 철회에 대한 합성 응답 처리 2건(OPTIONS/POST)뿐이다. 실제 외부 요청은 모두 차단했다. 소스의 분석 승인 false는 그대로다.
- v9 본문·해시와 WebView 로컬 SQL 흐름은 `ANDROID_V9_OFFLINE_VALIDATION.md`의 이전 소스 `11a8065` 검증을 재사용한다. 이번 사례·UI 선택 반영 이후 Android APK를 새로 설치하여 검증한 것은 아니며 최종 출시 후보 검증에 포함한다. 사진 전처리 코드는 변경하지 않았다.

공개 Notion·운영 DB·실제 모델·계정·운영 환경변수는 변경하지 않았다. 본문이 변하지 않아 동의 버전 v9 및 예슬이 전달 파일은 유지한다.

## 운영 적용 전에 설명할 변경과 순서 — 아직 실행하지 않음

1. 예슬이가 v9 정책 6개를 공개 반영한 뒤 URL·본문/해시를 확인한다. 완료되기 전에는 `notionSyncVerified`를 true로 쓰지 않는다.
2. AI 브랜치의 출시 후보 커밋을 고정한다. main으로 병합할 필요는 없다. 기존 Render가 별도 브랜치·자동 배포 off였으므로 후보 커밋을 실제로 어떻게 배포할지 먼저 공유한다. AI 없는 앱이 이미 Play에 등록·배포됐다면 동일 applicationId의 교체 업데이트인지 별도 앱인지, 사용된 versionCode보다 높은지 확인해야 한다. 이 브랜치의 기존 versionCode를 그대로 제출하지 않는다.
3. 승인 범위에서 본문 검토·실연결 검증을 위한 승인 파일과 공개 준비 플래그를 조정하고 분석 서버에 같은 후보 코드를 적용한다. 승인값을 켜는 일은 이번 작업에 포함하지 않는다. 기존 RELEASE_DATA_ENABLED/PRIVACY_DOCUMENT_READY 표시값1을 다시 설정하지 않고 Live 실행 반영을 확인한다. 추가 SQL 마이그레이션은 이번 선택 반영에 필요하지 않다.
4. 기존 미국 API 주소·모델·store:false, 같은 Supabase DB/Auth, 동의 v9와 카탈로그 버전을 서버·앱에서 대조한다. 앱만 먼저 배포하면 현재 운영의 구 카탈로그와 달라 분석이 거절될 수 있으므로 서버를 맞추고 신앱을 검증한 후 배포한다. 서버 교체가 기존 AI 앱에 미치는 영향도 함께 확인한다. 공급자나 요금제를 바꾸지 않는다.
5. 후보 Android 앱으로 실제 동의→글·사진 분석→결과 표시→평가/신고→철회 후 차단→삭제를 확인한다. 소유자가 허용한 테스트 계정·사진을 사용하고 추가 API 비용을 사전에 알린다. 기존 테스트 결과를 새 후보의 운영 성공으로 대신하지 않는다.
6. 후보 커밋과 일치하는 최종 서명 산출물, 카메라/보관함·네트워크·사용자 삭제 경로, 스토어 개인정보·데이터 보안 내용을 점검한 뒤 제출한다. 실패 시 이전 AI 없는 main을 자동 덮어쓰지 않는다.

로그인은 이후 추가 가능하며 `LOGIN_FEASIBILITY_V9.md`를 따른다. 공급자 내부의 미공개 국가를 이번 코드 작업으로 새로 확정했다거나 적법성 보증을 받았다고 기록하지 않는다. 모든 요청의 실제 내부 서버 추적이나 업체 답변을 추가 출시 선행 조건으로 요구하지 않는다.
