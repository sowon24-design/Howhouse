# 휴대폰 테스트 이후 제출까지 — AI 없는 버전

2026-11-10. 현재 결과물은 검증용 QA APK이며 Play 제출용 AAB가 아니다.

## 기기 없이 준비한 항목

- 소원 Notion 6개 본문을 앱에 동기화. JSON 원문 및 단락 자료, 전달 Markdown/HTML 준비.
- 첫 제출 ID com.howhouse.app, versionCode 1, versionName 1.0. QA ID는 .catalogqa.
- 기존 아이콘, 대표 이미지 및 화면 이미지 초안, 스토어 설명/권한·데이터 보안 작성 근거 준비.
- AI/서버 모듈 번들 차단, 네트워크 차단 CSP, Android 최소 권한·백업 제외 및 출시 승인 차단 유지.

## 다음 순서

1. 공개 문서 시행일 확정 및 로그인하지 않은 방문자의 본문 접근 확인. Gmail 문의 운영 절차와 이전 AI 기록 권리행사 경로, 이미지별 제3자 권리 검토를 마무리한다. 단지 GPT 제작 사실만으로 사용권 검토를 완료 처리하지 않는다.
2. 휴대폰에서 시작·연령 확인, 정책 6개 스크롤, 검색/카테고리, 준비물·영상 외부 이동/복귀, 문장 편집·복사·뒤로가기, 오프라인, 설정 초기화·재시작을 확인한다. 기존 앱과 별도 QA 앱으로 테스트한다.
3. 확인한 항목만 출시 승인 파일에 기록한다. 자동 통과 또는 임의 승인하지 않는다.
4. 최종 UI의 스토어 스크린샷을 확정하고 기존 업로드 키로 서명 AAB를 만든다. 비밀번호는 사용자만 입력한다.
5. Play Console 데이터 보안·대상 연령·콘텐츠 등급·광고 없음·접근 안내·개인정보 URL·지원 이메일을 실제 동작과 대조해 작성한다. 외부 이메일 문의까지 무조건 수집 없음이라고 단정하지 않는다.
6. 비공개 테스트를 진행하고 계정에 표시된 프로덕션 액세스 조건을 충족한 뒤 공개 심사에 제출한다. 사용자 계정은 앞서 비공개 테스트/액세스 신청이 필요하다고 확인했다.

공식 근거(2026-11-10 재확인): https://support.google.com/googleplay/android-developer/answer/14151465
해당 신규 개인 계정에는 최소 12명이 연속 14일 참여한 비공개 테스트가 요구된다. 충족 후에도 프로덕션 액세스 신청과 검토는 별도다.

이번 작업은 서명 키 변경·기존 DB 삭제·서버 배포·Play 업로드·Git 게시를 포함하지 않는다.

## 2026-11-10 시행일·콘텐츠 검토 후속

시행일은 사용자 결정에 따라 2026-11-10으로 확정했다. 소원 Notion 6개 및 앱/전달 문서에 반영했다. 공개 개인정보/이용약관 뷰의 본문·날짜도 확인했다. 기존 정리 페이지의 이전 미확정 안내는 당시 기록이며 최신 근거는 CATALOG_PRIVACY_CONTENT_FINAL_REVIEW.md다.

사용자는 참고 자료 없는 GPT 직접 생성·타인 얼굴/로고/캐릭터 없음, 문의 이메일 수신/답장 및 계정 보안 완료를 확인했다. 이미지 38개·아이콘의 시각 점검, Pretendard 라이선스 보존, 외부 링크/클립보드/메일 처리 대조와 운영 절차 준비를 마쳤다. 전기 위험 3개 사례를 catalog 전용으로 보완하고 테스트 7개를 통과했다.

남은 검증: 기존 AI 기록 권리행사 처리의 실제 운영 점검, 새 버전 휴대폰 테스트, 최종 서명 AAB·스토어 항목 제출·Play 비공개 테스트/프로덕션 접근. 이전 AI 기록을 무단 삭제하지 않는다. 앱 문서 공개는 법률 자문·심사 승인 보장이 아니다.

## 전환 계획 검토 완료 범위

위의 legacyDataTransitionReviewed=false 기록은 코드 경로 대조 전 중간 상태다. 후속 검토에서 다음 전환 계획을 확인하여 legacyDataTransitionReviewed=true로 기록했다: 새 앱은 이전 인증 세션/서버 자료에 접근하지 않음, 기존 자료를 임의 삭제하지 않고 승인된 보관 정책을 유지함, 새 앱 초기화와 구분해 고지함, 권리행사 접수 이메일의 실제 접근 및 보안 설정을 운영자가 확인함, 기존 서버의 삭제/정리 코드 경로와 운영 절차를 대조함.

이 확인값은 전환 계획 검토를 뜻하며 현재 DB cron 활성화나 실제 삭제 성공을 검증했다는 의미가 아니다. 그 검증 결과를 만들어내거나 기존 서버를 수정하지 않았다. 실제 요청이 접수되면 담당자가 최소 식별 확인 후 기존 운영 절차로 처리해야 한다. 새 앱을 설치하거나 초기화하는 것만으로 이전 자료가 삭제된다고 안내하지 않는다.

출시 승인은 Android 실기기 확인 전까지 차단한다. preview APK를 Play 제출용으로 바꾸지 않았고, 서명 AAB/Play 제출 및 commit/push는 하지 않았다.
