## 이번 동의 저장 보완: 로컬 구현, 실제 DB 미적용

- 기존 `howhouse_release_users`에 수집·이용과 국외 이전 각각 `accepted`, `consent_version`, `consent_at`을 추가한다. 기존 동의 필드는 호환 목적으로 유지한다.
- 두 항목이 모두 명시적으로 true인 경우에만 분석용 동의를 접수한다. 한 항목만 선택하거나 누락하면 접수하지 않는다. 거부 시 서버에 동의자로 저장하지 않는다.
- 서버 시각으로 기록하며, 철회 시 두 상태를 false로 변경한다. 현재의 필수 처리 두 항목을 함께 철회하는 API이고, 한 항목만 따로 철회하는 새 UI 계약은 추가하지 않았다.
- 과거 통합 동의 기록을 새 두 항목에 자동 동의한 것으로 채우지 않는다. 클라이언트·서버 영수증 버전은 `2026-11-10-v2`로 맞춰 예전 로컬 확인값만으로 새 동의를 생략하지 않는다. 이 버전은 저장 계약의 개정이며 미확정 법률 문서를 승인했다는 뜻이 아니다.
- 기존 `createPrivacyClient().consent({ageAtLeast14:true, processingAccepted:true, overseasAccepted:true})`와 `withdraw()` 호출 형태를 유지한다. 성공 응답을 받은 뒤에만 UI를 다음 단계로 연결한다. 체크박스가 보인다는 이유로 자동으로 true를 전달하지 않는다.
- 실제 분석 호출은 별도 시작 함수로 수행하며, 동의 저장만으로 사용자 글·사진을 자동 전송하지 않는다.
- `server/analysis/release-data.sql`은 재적용 가능한 테이블 변경과 기존 RPC 갱신을 포함한다. SQL 검토 후 적용 → 서버·클라이언트 같은 영수증 버전 배포 → 실제 테스트 순서가 필요하다. 아직 실제 DB·Render에 적용하지 않았다. 이전 클라이언트는 재동의·업데이트 안내가 필요하다.
- 일반 앱 사용자의 DB 직접 접근 권한은 확대하지 않는다. 기존 사용자 삭제·계정 만료와 함께 해당 행이 삭제되는 보관 기준을 유지한다.

서비스 제공자 예외가 성립하는지 확인한 뒤 ‘공유’ 여부를 판단한다. HTTPS 전송과 DB 암호화는 전송 중 암호화 근거가 되지만, 처리 서버·AI 제공자가 복호화하는 구조를 종단간 암호화로 설명하지 않는다. 삭제 가능 여부는 정상 접근 가능한 외부 삭제 페이지와 실제 삭제 검증을 근거로 입력한다. 로그인 화면이 없다는 이유로 임시 계정의 삭제 기능을 없애지 않는다. 광고·결제·추적 기능을 새로 추가하지 않았으며 해당 신고는 최종 SDK·앱 구성과 대조한다.

AI 생성 콘텐츠 신고는 앱 안에서 접수되고 운영자가 실제 검토할 수 있어야 한다. 이메일 주소만 적어 두고 기존 신고 동작을 완료했다고 표시하지 않는다.
