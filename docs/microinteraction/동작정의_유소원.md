## 1. 선정 영역과 근거

A01 홈의 검색 배너, 8개 카테고리, 인기 문제 목록을 선정했다. 모두 화면 이동의 시작점이지만 기존에는 주로 밝기·배경색만 바뀌어 눌린 대상과 이동 의도를 구분하기 어렵다. 배너에는 전체 면의 얕은 압축, 카테고리에는 아이콘만 압축, 목록에는 오른쪽 화살표 이동을 적용한다. 레이아웃·문구·이미지 비율·목적지는 기존 Main을 유지한다. 효과에 의한 이해도 개선은 설계 가설이며 사용자 실험으로 측정하지 않았다.

기존 Main에도 버튼 색상, 일부 일러스트, 시트·탭·아코디언 모션이 있었다. 이를 신규 성과로 계산하지 않는다. 이번 신규 변경은 홈 3개 영역의 변형 모션과 키보드·취소 상태 보완이다.

## 2. 동작 정의표

공통 easing: `cubic-bezier(.4,0,.2,1)` (기존 `--ui-ease`). 복귀 시간 160ms는 기존 `motion.color_ms`를 재사용한다. 새 scale 값은 이번 과제의 설계값이며 원본 Figma의 수치라고 주장하지 않는다.

## 3. 레퍼런스·코드 분석과 적용

### Motion 공식 제스처 예제
https://motion.dev/docs/react-gestures (2026-11-22 확인)

예제의 `whileTap`을 ① 주 포인터 누름 ② 임시 변형 유지 ③ 같은 대상에서 해제 시 tap ④ 영역 밖 해제 시 tapCancel로 분해했다. 예제의 scale .9를 그대로 복사하지 않고 배너 .98 / 아이콘 .94로 범위를 줄였다. 기존 React/native button을 유지하면서 `usePressFeedback`이 입력 상태를, CSS가 모션을 담당한다. 키보드 실행은 native click을 사용하므로 수동 onClick 호출에 따른 중복 실행을 피한다. Motion의 드래그 내부 3px 취소 규칙 전체를 구현한 것은 아니다.

### MDN 움직임 줄이기
https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion (2026-11-22 확인)

OS 설정 감지 → 비필수 움직임 제거 → 상태 의미 유지로 분해했다. reduce에서 scale·이동·전환을 없애고 기존 밝기/색상을 남긴다.

### 실제 Main 분석
- `HomePressButton.tsx`: 포인터 처리만 존재, 키보드 상태 및 창 blur 처리가 없었음.
- `Rows.tsx`: 같은 포인터 상태 처리가 중복됨. 공통 훅을 재사용해 키보드/취소 처리를 일치시킴.
- `home.css`: 기존 밝기 .94, 원본 색·간격을 재사용. `:active` 잔류가 명시적 취소 상태보다 우선하지 않도록 보완.
- `DESIGN.md` / `src/components/CONTRACT.md`: 기존 160ms, easing, native button, 포커스, reduced-motion 규칙을 준수.
- Figma 에이전트 대신 요청의 대안인 레퍼런스·실제 코드 분석 경로를 사용했다. Figma 파일/브랜치는 생성하거나 수정하지 않았다.
