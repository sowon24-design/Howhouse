# 실제 연결 적용 전 로컬 준비 검사

2026-11-12. PR62의 실제 적용 절차를 준비했으며 운영 설정·배포·Notion·실제 API·DB를 변경하지 않았다.

## 추가한 준비

- Android release 서명 환경변수4개와 버전코드/이름 입력 지원. 프로세스 환경에서만 읽고 값은 출력하지 않는다. 기존 main의 사례 전용 파일·빌드 타입은 가져오지 않았다.
- release 빌드에 variant=ai·aiEnabled/serverStorage=true 확인을 추가하여 다른 버전의 자산을 잘못 패키징하지 않도록 했다. 기존 정책 해시·미국 요구·개발 도구/공개 준비 검사를 유지한다.
- 키 또는 버전 입력이 없으면 서명 없는 출시 산출물을 정상으로 만들지 않도록 `verifyAiReleaseInputs`를 추가했다. debug 빌드에는 이 입력을 의무화하지 않는다.
- `scripts/ai-candidate-manifest.mjs`: 고정 커밋·동의 버전/양쪽 해시·115개 카탈로그 버전·공개 페이지 URL·승인 상태를 소스만으로 출력한다. 외부 요청·환경파일/키 조회·DB 조회·승인 변경은 하지 않는다.
- 실제 작업 순서는 `AI_LIVE_APPLICATION_RUNBOOK.md`에 명시했다. 특히 Render의 기존 브랜치 latest가 아닌 지정 SHA를 배포하고, 기존 공개 플래그는 표시/실행을 대조하며 빠진 경우만 보완한다.

## 통과한 검사

- 정책6개 동기화 검사·타입 검사.
- 소스 기대값 JSON 생성: 동의2026-11-12-v9,115개, 기존 정책·동의·카탈로그 해시 유지. 승인2개false 그대로.
- 실제 오프라인 Gradle에서 서명 입력 없는 `verifyAiReleaseInputs`가 의도한 오류로 실패함을 확인.
- 실제 오프라인 Gradle에서 숫자가 아닌 HOWHOUSE_VERSION_CODE를 입력하면 구성 단계에서 의도한 오류로 실패함을 확인.

실제 서명 키를 열거나 새 키를 만들지 않았으며 서명 APK/AAB는 생성하지 않았다. 합성 입력만으로 '서명/Play 등록 정상'을 주장하지 않는다. 앞서 통과한 Android 후보 UI·실연결 및 사진 검증을 반복하지 않았다. 이번 변경은 앱 제품 화면·분석·동의 본문을 수정하지 않는다.
