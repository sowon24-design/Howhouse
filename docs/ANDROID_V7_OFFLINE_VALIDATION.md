## APK·실기기 범위

PR62 코드로 web release-preview 및 Android debug APK를 새로 빌드했다. 별도 applicationId `com.howhouse.validation`에만 설치했다. 운영 주소·키 대신 `.invalid` 합성 설정을 사용하고 공개 준비·분석 승인값은false로 유지했다. developerTools=false, requiredProcessingRegion=us, policySha256=`90322e46b6f9bafa277a43a8ca7c737d1b566372b0d9b3879440b3c9b5b5a4bc`가 실제 앱과 소스에 일치했다. Android16 WebView에서 확인했다. 최종 서명 스토어용 빌드는 아니다.

실제 WebView의 클라이언트 통합 검증은 전용 로컬 하네스와 합성 인증·모델, 실제 PGlite SQL을 사용했다. 허용 전용 서버 의존성은 하네스에만 주입했고 앱 소스 승인값은 바꾸지 않았다. 합성 모델2회, 실제 OpenAI 호출0회, 운영DB 쓰기0회. 정상 앱의 미승인 버튼을 눌러 AI 성공 화면까지 갔다고 주장하지 않는다. v6의 별도 실제서비스 검증과 구분한다.

카메라·보관함의 사용자 사진을 이번에 새로 촬영·전송하지 않았다. 이전 v6 물리 기기에서 해당 경로를 확인했고 사진 처리 코드는 동일하지만, 이번 v7 검증은 합성 사진 중심이다. 최종 서명 앱의 카메라·보관함·네트워크·평가 포함 실서버 확인은 배포 단계의 잔여다.

로컬 환경에서 Java21 경로를 지정하여 오프라인 Gradle 빌드를 완료했다. Capacitor 동기화가 만든 PC 전용 경로는 복원하고 PR에 포함하지 않는다. 검증 후 앱 종료·ADB 포워딩 제거. 운영 설정·main 변경 없음.
