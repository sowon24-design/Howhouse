# Supabase 없는 어쩌집 검토

> 이후 사용자 결정(2026-11-10): **AI를 사용하지 않는 기존 사례 중심 앱으로 전환**한다. 이 문서는 선택 전 비교 자료이며, 현재 실행 계획은 `CATALOG_TRANSITION.md`를 따른다. AI 유지안을 현재 권장 구현으로 해석하지 않는다.

- 작성일: 2026-11-10
- 기준: main `3a1ec48bf9fe672d9b0171213aa41de1215063d2`
- 검토 브랜치: `codex/ai-without-supabase`
- 상태: 구조 검토. 기능 변경·실서버 변경·기존 DB 삭제·배포는 하지 않음.

## 결론

Supabase 없이도 기존 GPT 글·사진 분석, 기존 사례 선택, 새 해결 방법 및 문의 초안 생성을 유지할 수 있다. AI 요청에는 DB가 필수로 필요하지 않다. 다만 현재 앱은 Supabase의 인증·동의·비용 제한·신고 기능까지 사용하므로 환경변수만 지워서는 작동하지 않는다.

‘Supabase를 없애는 것’과 ‘어떤 서버에도 데이터를 지속 저장하지 않는 것’은 다르다. 파일·SQLite·KV·메일함을 대안으로 쓰면 별도 저장과 처리 업체 검토가 남는다. 다른 저장소를 사용하면서 완전 무저장이라고 표현하지 않는다.

## 선택 가능한 세 가지 구성

### A. AI 유지 + 서버 DB 없이 시험 운영

흐름: 앱 → 키를 보관하는 분석 서버 → OpenAI → 앱.

- 글·사진은 요청 처리에 필요한 메모리에서만 다루고 앱 자체 서버에 원본을 지속 저장하지 않는 구조를 설계할 수 있다.
- 기존 사례는 앱에 포함된 데이터로 제공한다. 분석 결과와 수정한 문의 문장은 기기에서 유지할 수 있다.
- 서버 메모리에서 중복 요청 병합·단기 캐시·동시 요청 제한을 수행할 수 있다.
- 단말 저장은 앱 삭제·기기 변경 시 사라질 수 있으며, 사진을 포함한 캐시의 필요성부터 줄인다. 개인별 답변을 공동 사례로 자동 편입하지 않는다.
- 서버 재시작 후 일별 사용량·동의 기록·신고가 사라지므로 이 구성만으로 현재 공개 출시 요건을 완료했다고 할 수 없다.
- 서버가 서명한 동의 영수증을 기기에 보관하는 방식도 검토 가능하지만, 증빙 충분성·기기 분실·철회·재전송 방지는 별도 검토해야 한다. 기기 체크박스 값만 믿고 유료 분석을 허용하지 않는다.

용도: 팀 내 기능 확인을 먼저 진행할 때. 기존 공개 서비스를 이 방식으로 즉시 전환하지 않는다.

### B. AI 유지 + Supabase만 제거, 최소한의 지속 저장

- 앱 → 분석 서버 → OpenAI 흐름은 A와 같다.
- 원본 글·사진·생성 답변의 서버 장기 저장은 없애고, 필요한 최소 동의 증빙·비용 장부·신고만 별도 저장하는 방향이다.
- 이 안은 Supabase를 없앨 수 있지만 ‘DB/저장소 없이 운영’하는 안은 아니다. 새 저장 업체·지역·보관·권한 정책을 확인해야 한다.
- SQLite는 외부 DB 서비스 없이 운영할 수 있지만 DB이며 영속 디스크가 필요하다. 현재 Render Free의 임시 파일시스템에 두면 재시작·재배포·휴면 시 잃을 수 있다.
- 무료 유지 조건에서 새 저장소를 도입하는 비용·정책 확인이 추가된다. 새로운 업체를 고르면 당일 출시가 보장되는 것은 아니다.

용도: AI를 유지하며 공개 출시용 운영 기록을 안정적으로 관리할 때. 업체 선택과 최소 수집 범위를 확정한 후 구현한다.

### C. AI 제외 + Supabase 제거, 기존 사례 중심 앱

- 유지: 기존 사례 탐색·조회, 준비물/해결 단계, 준비물 검색 링크, 사례 기반 문의 문장 편집·복사.
- 검토 후 제거 또는 대체: 사진 AI 분석, 새 해결 방법 생성, 생성 문의 초안, 분석 대기·실패·문제 확인 흐름, 서버 저장 평가·의견·신고, 임시 계정·서버 삭제 기능.
- 문제 글의 단순 검색을 추가하더라도 AI 분석으로 표시하지 않고, 사진 분석 결과를 가짜로 반환하지 않는다. 현재 사례 탐색과 신규 텍스트 검색 구현은 구분한다.
- 평가는 기기 내 표시로 줄이거나 제거할 수 있으나 운영자에게 저장됐다고 안내하지 않는다.
- YouTube·쿠팡·Notion 등 외부 연결, 앱에 남은 SDK·네트워크 요청은 계속 점검한다. ‘AI 없음 = 개인정보 처리 없음’으로 단정하지 않는다.
- 앱 소개·스크린샷·이용약관·개인정보 문서·데이터 보안 답변을 축소된 실제 기능에 맞춘다.

용도: AI를 빼는 축소 출시를 선택할 때. 현재 요청에서는 예비안이며 아직 적용하지 않는다.

## 비용 보호에 관한 중요한 구분

- 승인된 월 10달러·기기 기반 하루 5회 정책을 임의로 폐지하지 않는다.
- 최신 OpenAI 공식 문서는 프로젝트/조직의 강제 지출 한도와 알림을 구분한다. 알림은 호출을 막지 않으며, 강제 한도도 집계·적용 중 소액 초과 가능성이 있다. 실제 계정에서 설정 가능 여부와 적용 범위를 확인해야 한다. 이번 작업에서는 계정 설정을 바꾸지 않았다.
- 강제 지출 한도는 전체 비용 보호에 도움을 주지만, 한국 시간 기준 기기별 하루 5회 제한이나 신고·동의 기록을 대신하지 않는다.
- 단말만 저장하는 횟수는 앱 데이터 삭제·재설치로 초기화될 수 있다. 메모리 카운터는 서버 재시작으로 초기화된다. 이를 강제 제한이라고 보고하지 않는다.
- 앱에 고정 비밀 토큰을 넣거나 CORS만 설정하는 것은 공개 API 남용 방지를 대체하지 않는다. OpenAI 키는 계속 서버 환경변수에서만 관리한다.

## 개인정보와 Google Play에 남는 사항

Supabase를 제거하면 향후 Supabase로 보내는 처리는 없앨 수 있지만, Render의 요청 처리와 OpenAI의 글·사진 처리 및 관련 안내는 남는다. `store:false`는 OpenAI의 모든 보관을 없애는 설정이 아니다. 별도 승인받은 ZDR/MAM은 현재 없다.

Google Play는 생성형 AI 앱에 앱 밖으로 나가지 않고 운영자에게 부적절한 결과를 신고할 수 있는 기능을 요구한다. 따라서 AI를 유지하면서 신고를 단말에만 저장하거나 이메일 앱 열기로 대체하면 충분하다고 단정할 수 없다. 실제 접수·검토 경로를 설계해야 한다.

기존 Supabase 데이터는 새 앱에서 사용하지 않는 것과 삭제하는 것을 구분한다. 계정·운영 기록을 자동으로 폐기하거나 기존 동의 증빙을 지우지 않는다. 전환 시 잔존 데이터·보관 의무·안전한 정리 계획을 따로 확정한다.

## 권장 진행 순서와 이번 완료 범위

1. AI 제거를 먼저 선택하지 않고, Supabase 없는 AI 흐름을 별도 브랜치에서 검토한다. **이번에 브랜치 생성·의존성 검토 완료.**
2. 다음 구현 범위를 선택한다: A의 시험용 무DB 분석 / B의 공개용 최소 저장 / C의 AI 없는 축소 앱. 선택 전 운영 정책과 화면을 임의로 삭제하지 않는다.
3. 선택한 안에 맞게 인증·비용 제한·동의·신고 연결 계약부터 확정한다. 화면 담당자에게 변경 파일·영향을 공유한다.
4. 앱의 실제 네트워크 요청을 검사하여 Supabase 호출이 0건인지 확인하고, 글·사진 분석·기존/생성 결과·취소·90초 제한·문의 문장 유지·중복 요청·한도·신고 실패를 검증한다.
5. 개인정보 문서·Play 데이터 보안 항목·Android 실기기 검증 후 PR로 검토한다. 기존 서버 전환은 별도 승인 후 수행한다.

이번에는 이 검토 문서만 추가했다. 실제 무Supabase 모드·축소 앱 구현, API 유료 호출, 원격 게시, DB 작업, 서버 배포는 하지 않았다.
