# Google Play 등록에서 LLM 관련 확인할 항목

이 문서는 입력 초안과 최종 확인 순서다. 등록 항목은 최신 Play Console 화면과 실제 서버 적용 상태에 맞게 최종 확인한다. 앱 등록만으로 공개되지 않는다.

## 2026-11-10 진행 상태

- 개인정보·자동 인증 보완은 PR #57(https://github.com/sowon24-design/Howhouse/pull/57)로 게시했다. 팀원 승인 2개를 확인한 뒤 동시에 갱신된 main `3b9ed36`을 통합했다. 보호 규칙을 우회하지 않는다.
- 최신 main의 D01 관리 진입·동의 증빙·본문 단일 원본·정책 승인 분리를 보존했다. 본문 보완 후 동의 버전은 `2026-11-10-v5`이며 6개 정책 내보내기 파일과 manifest를 재생성·검사했다. 실제 Notion 반영과 운영 DB 적용은 별도다. 전체 자동 검사 225개를 통과했다.
- 사용자가 별도 사용자 DB 수동 백업·내보내기가 없다고 확인했다. 소스 코드 백업과 사례 CSV는 사용자 DB 백업으로 계산하지 않았다.
- 실서버 `/health`는 HTTP 200, 미국 분석 지역 설정을 반환한다. `/privacy`, `/terms`, `/data-deletion`은 HTTP 503이므로 아직 제출 URL로 사용할 수 없다. HTTPS/HTTP localhost 출처의 CORS 사전 요청은 204, 임의 출처는 403이다. 유료 분석·가입·DB 변경 없이 검사했다.
- Supabase의 새 답장도 DPA의 약관 포함 안내이며 로그 국가·보관기간에 대한 개별 답변은 아니다. 주요 DB·Auth·Storage의 서울 리전과 별도 운영 로그·지원의 국외 처리를 구분한다. 서울 저장만으로 모든 처리를 국내라고 고치지 않는다. [지역 문서](https://supabase.com/docs/guides/platform/regions), [이전 FAQ](https://supabase.com/legal/privacy-resources/data-residency-and-transfers-faq).
- 최신 별도 Consent QA 앱의 홈·기존 사례 열람과 평가 저장 차단을 사용자가 확인했다. 이 앱은 INTERNET 권한이 없으므로 외부 YouTube 썸네일이 깨지는 현상을 실제 출시 앱의 영상 오류로 단정하지 않는다. 실제 사례 썸네일은 인터넷이 가능한 360px 브라우저에서 로드 완료와 480×360 원본 크기를 확인했다.
- 사용자의 최종 요청에 따라 별도 신고 버튼과 글자는 제거했다. ‘답변이 도움이 되었나요?’에서 부정 평가를 새로 선택하면 신고 시트가 열린다. 평가 저장과 신고 제출은 별개이며 시트를 닫아도 평가 선택·신고 초안을 유지한다. 부정 평가 해제 또는 긍정 평가에는 신고 시트를 열지 않는다. 360px 브라우저에서 진입·닫기·초안 보존·선택 해제·긍정 평가를 확인했다. B02의 작은 평가 버튼 스타일도 공통 버튼에 적용되지 않게 범위를 좁혔다.
- 지정 Figma 아이콘 `646:7003`의 `651:7024` 원본으로 Android의 기본 Capacitor 아이콘을 교체했고, 사용자가 폰에서 정상 변경을 확인했다. `resources/app-icon/howhouse-play-512.png`는 Play용 512×512 후보이며 아직 업로드하지 않았다. Android 식별자·버전·서명은 변경하지 않았다.
- 미승인 release-preview 자산으로 `:app:preReleaseBuild`를 실행하면 차단되는 것을 확인했다. 개발 도구 숨김은 웹 빌드 확인표에서 확인하며, 최종 서명 AAB와 실제 서버 연결 검증을 대신하지 않는다.

## 비공개 테스트와 공개 출시

이 계정은 비공개 테스트·프로덕션 액세스 신청이 필요하다고 사용자가 확인했다. 최종 후보를 준비해 최소 12명이 연속 14일 참여한 뒤 실제 피드백·수정 내용을 근거로 액세스를 신청한다. 승인 이후 프로덕션 출시 심사를 제출한다. 아직 테스터 참여를 시작하거나 완료한 것으로 기록하지 않았다. [Google 공식 테스트 요건](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ko).

## 소원 확인 순서

1. Play Console에 등록한 어쩌집 앱을 연다. 최종 앱 식별자는 첫 파일 업로드 전에 팀과 대조한다. 기존 개발 식별자는 `com.howhouse.app`이며 별도 검증 앱의 `.sowontrial`을 등록하지 않는다.
2. 서명 키를 만든 적이 있는지 확인한다. 기존 출시 키를 임의로 새 키로 바꾸지 않는다. 새 키가 필요하면 Android Studio의 서명 파일 생성 화면에서 소유자가 비밀번호와 저장 위치를 직접 관리한다. 키 파일·비밀번호·서명 인증정보를 채팅·GitHub에 올리지 않는다.
3. 출시 검사 통과 후 서명된 AAB를 만든다. 개발 APK, 샘플 기본 빌드, release-preview 또는 미확정 정책 빌드를 올리지 않는다.
4. 공개 출시 전 내부 테스트 트랙에 먼저 올려 실제 설치·분석·문의·신고·철회·삭제를 확인한다. Play가 추가 테스트나 검토를 요구하면 해당 계정의 화면에 따라 이행한다.

## 데이터 보안 항목을 작성할 때

| 실제 항목 | 입력 검토 방향 |
|---|---|
| 문제 글과 선택 사진 | 기기를 떠나 서버·OpenAI로 전송된다. 서버가 영구 저장하지 않아도 전송 사실을 누락하지 않는다. 임시 처리 해당 여부는 업체의 별도 보관 조건까지 대조한다. |
| 임시 사용자 ID와 세션 | 이름·이메일 입력 화면이 없어도 서버 인증 식별자가 있다. 사용자 ID 항목 및 삭제 대상에 반영한다. |
| 평가·의견·AI 신고 및 표시된 답변 일부 | 저장·보관·운영자 검토가 있다. 단순 화면 반응으로만 표시하지 않는다. |
| 사진 부가정보·접속/보안 로그 | 위치 부가정보나 IP 등 실제 전송·업체 처리 범위를 확인한다. 분석 서버·인증 제공사 로그를 앱 저장 정책과 혼동하지 않는다. |
| 앱의 로컬 닉네임 | 서버에 보내지 않는 로컬 저장과 서버 인증 ID를 구분한다. |
| 문의 메시지 | 직접 편집·복사하며 앱이 자동 발송하지 않는다. 클립보드 복사 기능을 메시지 자동 수집·전송 기능으로 설명하지 않는다. |

OpenAI·호스팅·저장 업체 사용이 Play 정의상 ‘공유’에 해당하는지는 서비스 제공자 예외와 계약 조건을 확인해 판단한다. 외부 업체 사용만으로 무조건 공유 예/아니오라고 정하지 않는다. 광고·판매·사용 추적은 구현하지 않았다. Play에 제출한 내용과 개인정보 처리방침·동의 화면이 일치해야 한다.

## 제출 URL과 운영

- 개인정보 처리방침 예정 경로: 기존 분석 서버의 `/privacy`
- 이용약관 예정 경로: `/terms`
- 외부 삭제 요청 예정 경로: `/data-deletion`
- 운영자 전용 신고·의견 검토: `/ops` — 스토어 일반 사용자용 URL이 아니다.

예정 경로는 실제 새 서버 배포, 최종 문서 승인, 일반 브라우저에서 정상 응답을 확인하기 전에는 스토어 제출 URL로 사용하지 않는다. 준비 중 503 페이지는 최종 공개 정책이 아니다.

서비스는 만 14세 이상으로 준비한다. Play의 대상 연령 선택 구간은 정책상 연령과 그대로 일치하지 않을 수 있으므로 해당 화면에서 확인한다. 아동용·가족용으로 임의 표시하지 않는다.

## 완료로 보고할 수 없는 경우

운영자 계정·권한 미연결, 미배포 서버 코드, 미확정 국외 처리 안내, 동의·삭제 실서버 검증 미완료, unsigned AAB, 내부 테스트 미실시를 ‘출시 준비 완료’로 표시하지 않는다.
