# 최소화 실행 결과와 외부 지원 문의 절차

2026-11-10, 출시 검토 브랜치 `codex/ai-release-privacy`. AI·사진 분석·Supabase Free·동의 증빙·삭제 기능 유지. main·운영 미적용. 최신 검증 범위와 배포 조건은 `AI_RELEASE_PRIVACY_HANDOFF.md`를 따른다.

## 세 조치의 완료 범위

| 조치 | 상태 | 남는 한계 |
| --- | --- | --- |

기존 외부 영상·링크도 사용자 명시 동작 전 자동 전송되지 않는지 최종 기기에서 재확인한다. 외부 기능을 제거하지 않는다. 분석 요청 전 사진 정리 실패 시 원본으로 대체하지 않는 기존 구현을 유지한다.

## 운영자가 Render·Supabase·OpenAI에 지원 문의할 때

1. 현상을 먼저 합성 글·합성 사진·새 테스트 계정으로 재현한다. 실제 이용자 입력·답변·신고를 복사하지 않는다.
2. 문의에는 제품/기능명, 앱·서버 버전, 재현 순서, 개인정보 없는 오류 코드, 필요한 대략의 시각을 우선 사용한다. 업체가 기록을 연결할 수 있는 식별자도 필요성을 검토하고 최소한만 제공한다.
3. 원본 문제 글·사진, 생성 답변 원문, 사용자 UUID/토큰, 삭제 코드/증빙 비밀값, DB 덤프, 전체 로그, 전체 환경변수, 이메일·상세 주소를 지원 티켓·업체 AI 도우미에 첨부하지 않는다.
4. 추가 자료 요청 시 합성 자료나 필드를 가린 재현 결과로 대체한다. 실자료가 반드시 필요하면 기존 미첨부 원칙의 예외로 취급하고 운영 책임자가 목적·항목·수령자·국가·보관·근거를 별도로 확인한 후 판단한다. 업체의 요청 자체를 사용자 동의로 보지 않는다.
5. 제출한 자료의 종류와 처리 경과만 남긴다. 지원 기록에 실사용자 자료를 추가 축적하지 않는다.

이 절차는 이번에 문서화한 운영 원칙이며 과거의 모든 지원 문의가 준수됐다는 감사 증거는 아니다. 이번 작업에서 외부 지원 문의는 전송하지 않았다.

## 출시 단계의 별도 완료 조건

- 최종 Android에서 카메라/갤러리 사진의 방향·색상·크기·업로드 제한·정리 실패·취소 확인.
- 분리된 실제 검증 환경에서 v6 동의·사진 분석·철회 후 428 차단·삭제 후 초기화 및 인증 거절을 확인했다. 삭제 응답 본문은 별도 폐기용 계정으로 보완했으며 세부 한계는 인계 문서를 따른다. 최종 배포 커밋과 서명 앱의 확인을 대체하지 않는다.
- 국외 고지의 남은 국가·보관 조건·재이전 충분성 판단. `AI_RELEASE_PRIVACY_HANDOFF.md`의 미확정 목록을 따른다. 최소화 조치만으로 이 판단을 완료했다고 표시하지 않는다. 기관·업체 문의는 이번 변경의 필수 선행 절차로 설정하지 않는다.
- 예슬이의 공개 Notion 본문과 앱·서버 버전·해시 일치 확인. 그 후 main 반영·배포·출시 빌드 및 스토어 절차 진행.

추가 유료 인프라가 필요한 조치는 도입하지 않았다. 실제 모델 호출에는 기존 API 사용료가 발생할 수 있다. 출시 승인 플래그는 false를 유지한다.
