## 빌드 모드

| 모드 | 용도 | 개발 도구 | 분석 |
|---|---|---|---|
| development | 로컬 개발 | 표시 | 기본 무료 샘플 |
| trial | 기존 팀 시험 | 표시 | 기본 실제 API |
| release-preview | 출시 화면 검증 | 렌더링하지 않음 | 기본 API, 미확정 고지이면 실제 동의·전송 차단 |
| release 또는 production | 실제 출시 후보 | 렌더링하지 않음 | 실제 API, 공개 HTTPS·정책 승인 설정 필수 |

기본 `npm run build`도 production 검사를 받는다. 공개 연결 설정 누락, 서버 비밀 값의 VITE_ 노출, 미확정 정책, 촬영용 우회 설정은 출시 빌드를 실패시킨다. 실패를 피하려고 문서 검사를 제거하거나 임의로 준비 완료 값을 넣지 않는다. `release-preview`는 스토어 제출용이 아니다.

## 코드와 서버 적용은 별도

1. 새 코드를 검토·게시하고, 실제 배포 브랜치와 실행 커밋을 대조한다. main 병합은 별도 승인 범위다.
2. DB 설정이 적용된 것을 먼저 확인한 뒤 Render의 `RELEASE_DATA_ENABLED=1`을 활성화한다. OpenAI 키·Supabase secret·암호화 키는 교체하거나 앱에 복사하지 않는다.
3. 운영자만 확인된 Auth `app_metadata.howhouse_reviewer=true` 권한을 갖도록 한다. 일반 앱 사용자와 user_metadata로는 운영자 권한을 얻을 수 없어야 한다. 운영자 비밀번호는 계정 소유자가 입력한다.
4. 신고 저장과 운영자 조회·처리 상태 변경을 테스트한다. 소원 담당자는 신고 내용을 확인하고 위험한 사례·생성 지침을 보완한다. 접수만으로 개선이 자동 완료되는 것은 아니다.
5. 동의 버전·연령 확인의 서버 기록과 거부 시 미전송, 철회 후 추가 분석 차단, 본인 삭제·실패 재시도·외부 삭제 페이지를 별도 테스트 계정으로 검증한다. 기존 이용자나 팀원의 데이터를 삭제하지 않는다.
6. 승인된 미국 고정을 위해 `OPENAI_PROCESSING_REGION=us`를 설정하고 운영자 화면의 고정 문장 점검으로 실제 지원을 확인한다. 실패해도 Global로 자동 우회하지 않는다. 월 10달러는 유지하며 지역 기능의 10% 할증이 적용될 수 있다. 공개 health/session의 지역 값은 설정 확인이고 실제 지원 확인은 성공한 점검 응답으로 구분한다.
7. 제공업체별 처리 국가·항목·보관·연락처를 확정하고 공개 문서에 반영한다. 그 후에만 서버 `PRIVACY_DOCUMENT_READY=1`, 앱 `VITE_RELEASE_PRIVACY_READY=1`을 활성화한다.

## 무료 서버의 실제 제약

Render 무료 서버는 유휴 상태에서 잠들 수 있어 최초 연결이 지연될 수 있다. Supabase Free 프로젝트도 장기 비활성 시 일시 정지될 수 있다. 자동 유료 전환·자동 유료 재시도는 하지 않는다. 무료 상태로 준비하며 항상 즉시 분석을 보장하지 않는다.

공식 근거: [Render Free](https://render.com/docs/free), [Supabase 운영 준비](https://supabase.com/docs/guides/deployment/going-into-prod), [Google Play 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311), [AI 콘텐츠 정책](https://support.google.com/googleplay/android-developer/answer/14094294).

## 개발·검증 실행 구분

- 로컬 무료 샘플: `npm run dev`. Android 샘플은 `npm run build -- --mode development` 후 기존 Capacitor 동기화를 수행한다.
- 기존 팀 API 시험: 공개 설정 3개를 준비하고 `npm run android:sync:trial`.
- 출시 화면 점검: `npm run build -- --mode release-preview`. 실제 출시용 승인·서명을 대신하지 않는다.
- 실제 출시: 최종 고지·실서버 검사 후 `npm run build -- --mode release`와 Capacitor 동기화를 수행하고 서명 AAB를 만든다.
- 웹 빌드는 `howhouse-build.json`에 모드·개발 도구·정책 승인·정책 해시를 기록한다. Android `preReleaseBuild`는 확인표가 없거나 승인된 최신 출시 빌드와 다르면 중단한다. 이전 trial 자산은 서명 대상으로 사용하지 않는다.
- DB의 캐시·호출 기록 정리 예약은 적용했으며, 90일 미사용 계정의 Auth 삭제 작업자는 새 서버의 개인정보 기능 활성화 후 동작한다.
- 상대 날짜가 있는 입력의 캐시 날짜와 하루 분석 한도는 한국 시간 기준이다.
