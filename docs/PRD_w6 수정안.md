## 1. 서비스 정의와 목표

**한 줄 정의:** 자취생 생활문제 해결 서비스.

자취방 생활문제를 처음 겪는 대학생이 비슷한 실제 해결 사례를 바탕으로 문제의 심각도와 다음 행동을 스스로 판단하도록 돕습니다. 스스로 해결하기 어려운 경우에는 집주인 연락 메시지 작성과 주변 수리업체 찾기로 다음 행동을 이어 줍니다.

원문 목표는 학기 안에 iOS 앱으로 출시 가능한 범위를 완성하는 것입니다. 출시 일정과 완료 기준은 팀이 확인합니다.

## 2. 문제 정의와 배경

자취 초보 대학생은 누수·악취·해충·보일러 고장 등을 발견해도 검색 결과의 원인 후보가 너무 많아 무엇부터 확인할지 모릅니다. 해결책 자체뿐 아니라 현재 상황이 얼마나 심각한지, 지금 무엇을 해야 하는지 알고 싶어 합니다.

원문은 책임 소재의 불확실성보다 불편의 심각도, 일정·방문 전 정리 부담, 낯선 사람을 집에 들이는 부담이 문제 해결을 미루는 주요 원인이라고 설명합니다.

### 원문에 기재된 조사 배경 — 근거 확인 필요

- 대학교 UX 수업 캡스톤 프로젝트로 자취 경력 3년 이내 대학생을 인터뷰·설문했습니다.
- 150개 인사이트를 어피니티 다이어그램으로 묶어 정보 탐색·타인 의존·미루기의 세 테마를 도출했습니다.
- 사용자 투표와 로파이 롤플레잉 검증을 거쳐 해결사례 도서관과 SOS 모드를 우선 범위로 정했습니다. 이후 사용성 테스트에서 SOS 모드를 쓴 참여자가 없어 범위에서 제외했습니다.
- **팀 확인:** 조사 자료 링크, 참여자 수, 진행 시점, 검증 결과를 연결해야 합니다. 이 문서에는 해당 근거가 첨부되어 있지 않습니다.

## 3. 대상 사용자

- 주 사용자: 자취 생활문제를 처음 겪는 대학생.
- 조사 대상 범위: 자취 경력 3년 이내 대학생(원문 기준).
- 사용 기기: iOS 앱.
- 카테고리: 라이프스타일 / 일상.

### 원문 페르소나: 김서윤

서울 동작구 상도동의 다세대주택 3층 원룸에 사는 22세 대학생으로, 자취 6개월 차입니다. 검색·지도·카카오톡에는 익숙하지만 수리와 시설 지식은 거의 없습니다. 평일 낮에는 수업으로 집을 비우고, 방문 일정 조율과 낯선 사람의 방문을 부담스러워합니다. 집주인에게 연락하기 전 문제의 범위를 판단하고 스스로 적절히 대응하고 싶어 합니다.

> 페르소나의 나이·거주지·주거 형태는 원문 사례이며 전체 사용자의 필수 조건이 아닙니다. 조사 기반인지 예시 설정인지 팀 확인이 필요합니다.

| 커뮤니티 | 다른 자취생이 올린 해결 후기·질문을 둘러보고 검색하며, 자신의 문제나 해결 경험을 글로 남깁니다. |
| 해결 단계 카드 | 단계마다 할 일을 한 문장으로 안내합니다. 낯선 부품·용어는 카드 안에서 쉬운 말로 풀어 씁니다. |

### 4.1 화면별 요구사항

**문제 입력과 문제 유형별 사례 보기**

- 홈과 사례 탭에서 사진으로 보여주기·말로 알려주기·직접 입력하기 중 하나로 문제를 입력합니다.
- 입력한 내용을 분석해 문제 유형(예: 수도·수질 › 싱크대 아래에서 물이 새요)으로 확인하고, 예상 긴급도와 원인 후보를 보여준 뒤 해당 문제의 해결 사례 페이지로 이동합니다.
- 사례 탭에서는 카테고리(화장실·보일러·수도·수질·세탁기·전기·조명·냉장고·해충·곰팡이·쓰레기)를 고른 뒤 세부 문제를 선택해 같은 해결 사례 페이지로 들어갈 수 있습니다.
- 해결 사례 페이지는 문제 요약(예상 시간·난이도·해결 방식), 순서형 해결 단계, '비슷한 상황의 이야기'(관련 커뮤니티 글), 다음 행동 버튼(집주인에게 알리기·근처 수리 업체 찾기)으로 구성합니다.
- 확인한 문제는 홈의 '최근 확인한 문제'와 마이의 '우리 집 문제 기록'에 남아, 나중에 같은 해결 사례 페이지로 다시 들어갈 수 있습니다.

**커뮤니티**

- 글 목록은 글 종류 칩(전체·자취팁·도움요청·해결후기·생활질문)과 정렬(인기순·최신순·도움이 많이 된 순·댓글 많은 순)로 걸러 봅니다.
- 상단 검색창에 겪고 있는 문제를 문장으로 입력하면, 비슷한 문제와 관련 글을 찾아 보여줍니다.
- 해결 사례 페이지의 '비슷한 상황의 이야기 › 더 보기'로 들어오면, 지금 보고 있는 문제와 관련된 글만 걸러진 목록을 보여줍니다.
- 글 상세에서는 본문·사진·태그를 보고 '도움돼요'와 댓글로 반응합니다.
- 글쓰기에서는 글 종류(필수)·제목·내용을 입력하고, 사진과 태그는 선택으로 추가합니다. 등록하면 '사례가 등록됐어요' 안내와 함께 목록으로 돌아갑니다.

**해결 단계 카드**

- 단계 문장에 낯선 부품·용어가 나오면 카드 안에서 바로 풀어 씁니다. 예: "연결부 너트(배수 호스와 배관을 잇는 둥근 조임 부품)를 손으로 조이거나, 패킹(연결 부위 사이에 끼우는 고무 링)을 교체해요."
- 아코디언으로 펼쳐 보는 라인드로잉 상세 이미지는 넣지 않습니다.

**연락 메시지 초안**

- 블록 목록과 메시지 미리보기를 하나로 합칩니다. 사용자는 메시지 카드에서 바로 편집합니다.
- 각 문장 옆의 ✕를 누르면 그 문장이 메시지에서 빠지고, 아래 '문장 추가하기' 칩(+)으로 내려갑니다. 칩을 누르면 다시 메시지에 들어갑니다.
- '블록'이라는 용어와 관련 설명 문구를 쓰지 않습니다. 꺼진 문장의 취소선 표시도 없앱니다. 추가할 수 있는 문장은 '+ 칩'으로 구분합니다.
- 제목을 한 줄로 줄이고 받는 사람 카드도 한 줄로 압축해, 첫 화면에 메시지 전체와 '메시지 앱에서 보내기' 버튼이 함께 보이게 합니다.
- 긴급 모드 삭제에 따라 '긴급 연락' 라벨과 긴급 전용 기본 문장("급한 상황이라 최대한 빨리 연락 부탁드려요.")을 일반 문장으로 바꿉니다.
- 메시지 앱으로 전송한 뒤에는 홈이 아니라 메시지 작성을 시작한 해결 사례 페이지로 돌아갑니다.

**주변 수리업체 찾기**

- 현재 위치를 기준으로 문제 유형에 맞는 검색어(예: 싱크대 누수 → '설비', '배관')로 카카오맵 로컬 API에서 업체를 검색합니다.
- 업체 카드에는 업체명·주소·전화번호를 표시합니다.
- '카카오맵에서 보기'를 누르면 카카오맵 장소 URL로 연결해 리뷰·영업시간 등 상세 정보를 확인하게 합니다.
- 앱 안의 전화 걸기 버튼은 제공하지 않습니다.
- API가 제공하지 않는 리뷰·평점·가격·영업 여부는 앱에 표시하지 않습니다. 다른 서비스의 화면을 수집(크롤링)해 보여주지 않습니다.

### 차별점

일반 검색이나 커뮤니티처럼 정보를 나열하는 데서 그치지 않고, 유사 사례를 통해 문제의 심각도를 가늠하고 다음 행동을 선택하게 돕습니다. 스스로 해결할 수 있는 문제는 단계별 해결 방법으로, 어려운 문제는 집주인 연락과 업체 찾기로 이어 줍니다.

### 범위에서 제외한 기능

- 긴급 모드(SOS)와 음성 호출(시리 등록 문구 포함). 사용성 테스트 결과에 따라 제외했습니다.
- 수리업체 직접 예약·중개와 앱 안의 전화 걸기.
- 업체 리뷰·평점·가격 표시. 카카오맵 API가 제공하지 않으며, 외부 화면 수집은 하지 않습니다.
- 비용 또는 법적 책임의 확정 판단.
- 위험한 상황을 과소 안내하는 진단·보장. 서비스 범위는 행동 안내와 기록 지원으로 제한합니다.

> 입력 방식별 구현 범위와 사례 확보 방식은 원문에 구체화되어 있지 않으므로 별도 합의가 필요합니다.

## 5. 사용자 시나리오

### 시나리오 1: 욕실 악취

1. 사용자가 욕실 악취를 발견하고 사례 모음에서 욕실과 냄새·배수구를 선택합니다.
2. 유사 사례를 살펴보며 배수구 이물질이나 트랩 문제가 원인 후보임을 확인합니다.
3. 자신의 배수구 사진을 촬영하여 상태를 다시 확인합니다.
4. 사례의 해결 단계를 따라 조치한 뒤 냄새가 줄었는지 확인합니다.
5. 문제가 해결되지 않으면 집주인 연락으로 이어집니다.

### 시나리오 2: 싱크대 아래 누수

1. 사용자가 싱크대 수납장 아래에서 물이 새는 것을 발견하고, 사진·음성·텍스트 중 하나로 문제를 입력합니다.
2. 서비스가 문제를 '싱크대 아래에서 물이 새요'로 확인하고 해결 단계를 보여줍니다.
3. 사용자가 해결 단계를 따라 새는 곳을 찾고, 카드 안의 용어 풀이를 보며 연결부 너트를 조이거나 패킹을 확인합니다.
4. 해결되지 않으면 집주인에게 보낼 메시지 초안을 다듬어 메시지 앱에서 직접 전송합니다.
5. 전송 후 해결 사례 페이지로 돌아와, 필요하면 주변 수리업체를 찾고 카카오맵에서 상세 정보를 확인합니다.

> 위 내용은 제품 사용 흐름의 예시입니다. 실제 안내 문구와 상황별 안내 순서는 검증 후 확정해야 합니다.

원문이 제시한 성공 방향은 학기 내 iOS 앱 출시 요건 충족, 문제 발생 시 유사 사례를 찾아 다음 행동을 선택하는 것입니다.

**원문에는 목표 수치·표본 수·측정 기한이 없습니다. 아래 측정 정의는 검토용 제안이며, 목표는 팀 합의 전까지 미정입니다.**

| 성공 기준 / 지표 | 측정 방법 제안 | 목표 / 기한 |
| --- | --- | --- |
| 문제 해결 과업 완료 | 유사 사례를 찾아 다음 행동을 선택한 참여자 수 / 과업 참여자 수 | 미정 |

| 해결 단계 확인 비율 | 해결 단계를 확인한 사용자 수 / 사례 모음에서 문제 탐색을 시작한 사용자 수 | 미정 |

테스트는 실제 위험 상황을 만들지 않는 모의 시나리오로 진행하는 것을 제안합니다. 열람·확인·완성의 판정 조건, 테스트 참여자 수, 과업별 통과 기준은 함께 정합니다. 행동 안내를 확인했다는 사실만으로 실제 문제가 해결됐다고 판단하지 않습니다.

## 7. 위험 요소와 대응 방향

- **사진 분석 오류:** 부정확한 분석이나 낮은 촬영 품질로 잘못된 행동을 권할 수 있습니다. 재촬영·직접 선택 경로가 필요합니다.
- **위험 상황 안내:** 긴급 모드를 제외했으므로, 누수·누전처럼 위험할 수 있는 문제의 해결 단계에는 '위험하다고 느껴지면 119 또는 관리실에 연락하세요' 같은 안전 문구를 일반 화면 안에 둡니다.
- **사례 신뢰성·개인정보:** 커뮤니티 사례에 잘못된 정보와 개인정보가 포함될 수 있습니다. 출처 검토 및 신고·숨김 기준이 필요합니다.
- **업체 정보 한계:** 카카오맵 로컬 API는 업체명·주소·전화번호·좌표·장소 링크만 제공합니다. 리뷰·가격·실시간 영업 정보는 앱에서 제공하지 않고 카카오맵 링크로 대신합니다. 출시 전 API 이용약관의 표시 의무와 상업적 이용 조건을 확인합니다.
- **안내 범위:** 비용·책임을 확정하거나 위험도를 과소평가하지 않도록 행동 안내·기록 지원의 범위를 정합니다.

## 8. 팀 논의 및 합의할 항목

- [ ] 문제 정의가 실제 조사 결과와 일치하는지 확인하고 근거 자료를 연결합니다.
- [ ] 주 대상 사용자와 페르소나 설정의 근거를 확인합니다.
- [ ] 해결사례 도서관·연락 메시지·업체 찾기의 학기 내 구현 범위를 확정합니다.
- [ ] 사진·음성·텍스트 입력의 필수 여부를 정합니다.
- [ ] 해결 단계의 용어 풀이 작성 기준(어떤 용어를 풀지, 문장 길이)을 정합니다.
- [ ] 문제 유형별 업체 검색어 목록을 정합니다.
- [ ] 커뮤니티 개선 여부를 정합니다. 1차 UT에서 관찰된 내용은 다음과 같습니다.
  - 하단 탭으로 들어가면 문제 필터가 풀려 관련 글을 찾기 어려웠습니다(P02).
  - 해결 단계 다음에 커뮤니티를 언제 쓰는지 몰랐습니다(P01).
  - 글쓰기의 필수 항목(글 종류)이 맨 위에 있어 '글 올리기'가 비활성인 이유를 몰랐습니다(P03).
- [ ] 카카오맵 API 이용약관(표시 의무, 상업적 이용)을 확인합니다.
- [ ] 사례 수집·검토 방법, 사진·음성·개인정보 보관 기준을 정합니다.
- [ ] 위험 상황 안전 문구를 넣을 문제 유형과 문구를 정합니다.
- [ ] 성공 지표의 목표 수치, 측정 조건, 테스트 참여자 수와 기한을 정합니다.
- [ ] iOS 출시 완료의 의미(테스트 배포 또는 스토어 출시 등)와 날짜를 확정합니다.
