최신 본문·Notion 인계는 [POLICY_SYNC_HANDOFF.md](POLICY_SYNC_HANDOFF.md)를 따른다. 본문 원본은 `src/app-screens/my/information-draft.json`, 버전·페이지 주소는 `src/analysis/policy-publication.json`이다.

기준 main: `d1939a29cf504272af64a24ecfc8379baacec196` (PR #55 포함). 작업 브랜치: `codex/consent-evidence-d01`.

main push·운영 SQL·서버 배포·유료 AI 호출·사용자 데이터 삭제는 수행하지 않았다. 예슬이의 B02 및 분석 확인 문구 변경은 기준 커밋 그대로 보존한다.

## 화면 변경과 충돌 지점

- `MyScreen.tsx`: 기존 외부 링크 4개를 유지하고 같은 메뉴 스타일의 `동의 철회·서버 데이터 삭제` 버튼 1개를 추가한다. 기존 `onMenu('data')`를 통해 기존 관리 화면으로 들어간다. App 라우터·스타일·PrivacyActions 동작은 바꾸지 않는다.
- `ConsentDocument.tsx`: 본문과 제목을 `src/analysis/consent-document.ts`로 이동하고 다시 export한다. 탄성 스크롤·시트·닫기 등 UI 코드는 유지한다. **이후 약관 본문은 information-draft.json에서 수정하고 공유 모듈은 이를 참조한다.** 이전 TSX 파일에 별도 본문을 다시 만들지 않는다.
- `TermsScreen.tsx`: 체크 문구는 공유 원본에서 읽는다. 기존 저장 콜백에 `documentSurface:'onboarding'`만 추가해 E03의 실제 체크 문구로 증빙을 만든다.
- `AnalysisConsentSheet.tsx`: 체크 문구를 공유 원본에서 읽는다. 기존 A02 저장→분석·중복 방지·취소 동작은 유지한다. 기본 증빙 화면은 `analysis`다.
- 공유 원본은 현재 초안을 유지하며 증빙 항목·보관 설명만 추가했다. 미확정 업체 조건을 확정하거나 출시 준비 플래그를 켜지 않았다. 최종 공개 정책 JSON/Notion 동기화는 별도로 남는다.

예슬이 후속 커밋은 위 4개 화면 파일의 변경부터 비교한다. 특히 본문 수정은 공유 파일에 반영하고, 외부 링크 변경과 내부 관리 버튼을 함께 보존한다. ProblemPreview·App·B02·스타일 파일은 이번 보완에서 수정하지 않았다. 최신 main에 통합 시 실제 고지 원본을 하나로 유지하는지 확인한다.

## 증빙 저장 계약

- 버전 `2026-11-10-v4`. 이전 v2 기록을 자동 동의로 바꾸지 않으며 재동의가 필요하다. 최종 문구를 수정하면 버전도 다시 올린다.
- 앱·서버는 동일 공유 원본에서 화면별 수집·이용/국외 이전 본문, 제목·체크 문구·연령 확인 맥락을 직렬화하고 SHA-256을 계산한다. E03와 A02의 체크 문구 차이를 구분한다.
- 앱은 `version`, `documentSurface`, `documentHash`와 실제 동의 선택을 보낸다. 서버는 자체 본문·해시와 비교하며 앱이 보내는 임의 본문을 보관하지 않는다.
- 새 RPC는 기존 main의 항목별 상태 갱신과 이력 추가를 같은 트랜잭션으로 실행한다. 본문 저장 실패나 동일 버전/화면의 다른 본문 충돌 시 둘 다 롤백한다.
- 응답은 동의 여부, 본문 해시, 이벤트 ID, DB 기록 시각을 포함한다. 클라이언트는 완전한 영수증을 확인해야 동의 완료를 저장한다. 철회도 별도 이력으로 저장한다.
- 분석 권한은 현재 항목별 동의 상태와 가장 최근 증빙이 현재 버전·현재 화면별 해시에 일치해야 인정한다. E03 또는 A02의 정상 증빙 모두 인정한다.
- 증빙에 원본 질문·사진·IP·토큰·삭제 코드를 추가하지 않는다. 익명 ID 기준 요청 기록이며 실명 본인 인증을 의미하지 않는다.

## 추가 SQL

기존 main의 `release-data.sql` 적용 후 `server/analysis/consent-evidence.sql`을 추가한다. 기존 SQL·데이터를 덮어쓰는 방식이 아니다.

- `howhouse_legacy_consent_states`: 적용 직전 마지막 상태를 기존 기록으로 복사한다. 새 증빙으로 인정하지 않으며, 재적용 시 이미 보존한 값을 덮어쓰지 않는다. 삭제 코드 해시는 복사하지 않는다. 과거에 이미 덮어쓰인 이력은 복원할 수 없다.
- `howhouse_consent_documents`: 화면·버전별 정확한 고지 원문 사본. 같은 화면·버전의 본문 교체를 금지한다. 사용자 식별 정보가 없는 공통 문서다.
- `howhouse_consent_events`: 사용자·화면·문서 버전/해시·항목별 선택·연령 확인·서버 시각·동의/철회 이벤트. 과거 이벤트를 덮어쓰지 않는다.
- 일반 앱 역할은 조회/쓰기/RPC 실행 불가. service_role은 표를 직접 수정할 수 없고 기록 RPC로 추가한다. DB 관리자 권한까지 변조 불가능하다고 주장하지 않는다.
- 사용자 관련 이력/기존 기록 사본은 Auth 계정 삭제 시 cascade로 정리한다. 기존 삭제 실패·재시도 흐름을 유지한다. 공통 고지 본문은 버전 자료로 남는다. 별도 삭제 후 증빙 보관 기간을 새로 만들지 않았다.

운영 적용 전 시험 DB에서 검증하고 DB→서버→호환 앱 순서를 맞춘다. SQL 없이 새 서버를 실행하면 스키마 검사에서 실패한다. 이전 앱은 새 해시/영수증 계약과 호환되지 않으므로 기존 운영을 유지한 채 업데이트 일정을 정해야 한다. 이번에는 실제 적용하지 않았다.
